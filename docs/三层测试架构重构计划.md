# 三层测试架构：当前状态与长期运行规范

## 1. 文档目的

本文档记录三层测试架构当前已经落地的能力、尚未完成的现场验收，以及后续长期运行规则。历史实施过程详见：

- `docs/阶段1完成记录.md`
- `docs/阶段7完成记录.md`

三层测试架构如下：

```text
第一层：离线单元测试
第二层：模拟设备集成测试
第三层：真实设备 smoke 测试
```

当前状态不是“全部阶段完成”：第一层、第二层和测试入口建设已经完成；第三层的脚本、配置模板和门禁已经实现，但尚未在真实设备上执行验收。

## 2. 当前已实现能力

### 2.1 测试入口

项目命令必须使用 `.env` 中 `AUTO_TEST_PYTHON` 指定的解释器。运行前由脚本检查解释器是否存在，不得改用 Anaconda `base` 环境、裸 `python` 或其他解释器。

| 层级 | 推荐入口 | 设备访问 |
| --- | --- | --- |
| 默认离线测试 | `./run_tests.ps1` | 禁止真实设备访问 |
| 离线单元测试 | `./run_tests.ps1 -Layer Unit` | 禁止真实设备访问 |
| 模拟设备测试 | `./run_tests.ps1 -Layer Simulation` | 只访问模拟对象 |
| 应用依赖检查 | `./start_gui.bat --check` | 不连接真实设备 |
| 配置校验 | `./start_gui.bat --validate-config` | 不连接真实设备 |
| 真实设备 smoke | `./run_hardware_smoke.ps1` | 仅允许指定真实设备 |

真实设备测试不属于默认 `tests` 发现范围，只能通过 `run_hardware_smoke.ps1` 进入。`run_tests.ps1` 仍兼容原有 `unittest discover` 位置参数形式。

### 2.2 第一层和第二层

当前已经具备以下离线能力：

- `MockScpiTransport` 和 VISA transport 的通信、超时、异常及关闭行为测试；
- 信号源、频谱仪和电源 driver 的命令格式、参数校验、查询解析和错误处理测试；
- 配置、测量计算、结果模型、快照、取消、状态转换和资源清理测试；
- `instrument/simulation.py` 提供模拟设备、测量读数、故障注入、命令记录和安全清理；
- 模拟设备覆盖正常流程、连接失败、准备失败、测量失败、停止、紧急停止和重复清理；
- 测量服务通过 `measurement_port` 和 `PortMeasurementAdapter` 接入新协议，同时保留旧 `InstrumentControl` 回滚路径；
- action/flow 不需要自行创建 VISA 连接或依赖真实地址。

## 3. 第三层真实设备 smoke

### 3.1 已实现的安全边界

真实设备入口 `run_hardware_smoke.ps1` 已实现以下门禁：

- 使用 `.env` 中配置的 Python 解释器，并检查文件存在；
- 配置文件必须由调用方明确传入，且必须位于 `hardware/`；
- 示例、模板和占位地址配置会被拒绝；
- 配置必须声明 `environment: hardware_smoke`；
- 必须声明设备空载和操作者确认；
- 必须设置 `HARDWARE_SMOKE_ENABLED=1`；
- CI 环境中拒绝执行；
- 必须传入 `-ConfirmHardwareSmoke`；
- 硬件测试位于 `tests/hardware`，不参与普通测试发现。

硬件目录目前包含：

- `smoke_config.example.json`：安全准备模式模板，动作数为 0；
- `smoke_config.minimal_action.example.json`：单次受限动作模板；
- `read_only_smoke.py`：只读身份和状态检查；
- `safe_prepare_smoke.py`：配置准备但保持输出关闭；
- `minimal_action_smoke.py`：受限动作、测量和清理；
- `tests/hardware/`：三类真实 smoke 入口测试；硬件 smoke 合同测试位于 `tests/test_hardware_smoke_contract.py`。

### 3.2 尚未完成的事项

以下事项仍需要具备现场条件后执行，不能由离线测试替代：

1. 根据实际仪器手册填写未纳入版本控制的 `hardware/smoke_config.local.json`；
2. 核对设备型号、VISA 地址、SCPI 查询、输出状态返回值和保护参数；
3. 执行只读 smoke，确认身份、错误状态、地址和通信环境；
4. 执行安全准备 smoke，确认配置命令有效且 RF/电源输出保持关闭；
5. 在设备空载、现场授权和操作者确认均满足时，执行一次最小动作 smoke；
6. 保存每次报告、配置快照、软件版本、设备身份和现场问题记录；
7. 将第三层结果补记到本文件或对应的阶段验收记录。

本机当前没有 `hardware/smoke_config.local.json`，因此真实设备 smoke 尚未执行，也不能宣称第三层通过。

推荐命令如下，只有在现场条件满足时执行：

```powershell
$env:HARDWARE_SMOKE_ENABLED = "1"
./run_hardware_smoke.ps1 -ConfigPath "hardware/smoke_config.local.json" -ConfirmHardwareSmoke
```

禁止直接执行示例配置；禁止把真实地址、凭据或本地硬件配置提交到版本库。

## 5. 长期运行规则

- 每次提交运行 `./run_tests.ps1`；
- 修改 transport、driver、action、flow、设备配置或清理逻辑后，至少单独运行相关 Unit/Simulation 测试；
- 修改真实设备控制、SCPI、时序或硬件配置后，安排相应的真实 smoke；
- 重构前后使用同一套真实 smoke 步骤和安全限制；
- 定期执行只读 smoke，检查地址、固件和通信环境漂移；
- 每次硬件 smoke 保存日志、配置快照、软件版本和设备身份；
- 硬件 smoke 失败时先保留日志和现场状态，再区分软件、网络、设备和配置问题；
- 真实设备 smoke 不加入普通 CI；
- 离线和模拟测试不得访问真实局域网、VISA 资源或真实地址；
- 普通设置动作不得隐式打开 RF 或电源；
- 所有清理路径必须覆盖异常、取消、程序退出和重复调用；
- 旧入口在新实现完成现场验证前继续保留。
