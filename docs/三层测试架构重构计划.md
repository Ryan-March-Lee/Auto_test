# 三层测试架构重构计划

## 1. 文档目的

本文档规定在开始大范围功能重构前，如何为项目建立三层测试架构，并将其作为后续重构的验证基础。

三层测试架构包括：

```text
第一层：离线单元测试
第二层：模拟设备集成测试
第三层：真实设备 smoke 测试
```

本计划的目标不是一次性重写全部测试，而是先建立一条可以重复执行的验证闭环：

```text
命令和逻辑验证
    ↓
模拟设备流程验证
    ↓
真实设备连接和最小动作验证
```

只有这条闭环稳定后，才开始迁移线损测量、驱动功率映射和主功放测试等其他功能。

## 2. 当前基线

当前项目已经具备一部分三层测试基础：

- `tests/` 中已有离线测试；
- `instrument/ports.py` 定义了信号源、频谱仪、电源和仪器会话协议；
- `instrument/simulation.py` 提供模拟信号源、模拟频谱仪、模拟电源和安全会话；
- 已有命令记录、故障注入、取消、清理和上下电顺序测试；
- `instrument_control.py` 支持注入 ResourceManager，便于隔离真实 VISA；
- `run_tests.ps1` 使用项目规定的 Python 解释器运行编译检查和测试；
- `start_gui.bat --check` 和 `start_gui.bat --validate-config` 已提供应用检查入口。

重构开始前必须记录以下信息：

```text
Git 提交号：
测试日期：
Python 解释器：.env 中 AUTO_TEST_PYTHON
Python 版本：
离线测试数量：
离线测试结果：
启动依赖检查结果：
配置校验结果：
真实设备 smoke 结果：
已知问题：
```

当前基线检查命令为：

```powershell
./run_tests.ps1
./start_gui.bat --check
./start_gui.bat --validate-config
```

项目命令必须使用 `.env` 中 `AUTO_TEST_PYTHON` 指定的解释器。执行命令前应确认该解释器存在；如果不存在，应停止并报告环境问题，不得改用 `base` 环境或裸 `python` 安装依赖。

## 3. 总体架构和依赖方向

生产代码的依赖方向保持单向：

```text
GUI / CLI
    ↓
测试服务或 flow
    ↓
action
    ↓
仪器 driver
    ↓
SCPI transport
    ↓
真实 VISA 或模拟 transport
```

测试代码对应三层：

```text
离线单元测试
    ↓
Mock transport、Fake driver、纯 Python 对象

模拟设备集成测试
    ↓
SimulatedSignalGenerator
SimulatedSpectrumAnalyzer
SimulatedPowerSupply
SafetyInstrumentSession

真实设备 smoke 测试
    ↓
Visa transport、真实 driver、设备局域网和真实仪器
```

各层职责如下：

| 层级 | 设备访问 | 主要目标 | 推荐运行频率 |
| --- | --- | --- | --- |
| 离线单元测试 | 禁止访问真实设备 | 验证逻辑、状态、命令和异常 | 每次修改、CI |
| 模拟设备集成测试 | 只访问模拟对象 | 验证跨设备流程和安全清理 | 每次流程修改、CI |
| 真实设备 smoke | 允许访问指定设备 | 验证真实通信、时序和最小动作 | 重构前、硬件相关改动后、定期 |

## 5. 阶段总览

| 阶段 | 名称 | 主要结果 |
| --- | --- | --- |
| 0 | 冻结并记录基线 | 确认重构前所有已知结果 |
| 1 | 划分测试边界 | 建立三层测试入口和硬件隔离规则 |
| 2 | 完善离线单元测试 | 覆盖 transport、driver、状态和安全逻辑 |
| 3 | 完善模拟设备集成测试 | 覆盖完整流程、异常和清理 |
| 4 | 建立真实设备只读 smoke | 验证连接、身份和安全初始状态 |
| 5 | 建立真实设备安全准备 smoke | 验证配置设备但不执行动作 |
| 6 | 建立最小空载动作 smoke | 验证真实动作、测量、停止和清理闭环 |
| 7 | 将三层测试接入重构流程 | 每个功能迁移均有三层验证 |
| 8 | 验收并冻结测试架构 | 形成长期运行规范和回滚边界 |

每个阶段都必须满足本阶段验收标准后才能进入下一阶段。

## 6. 阶段 0：冻结并记录当前基线

### 目标

建立重构前的可追踪基线，区分既有问题和重构引入的问题。

### 步骤

1. 检查 Git 工作区状态，记录当前提交号和未提交改动。
2. 从 `.env` 读取 `AUTO_TEST_PYTHON`。
3. 确认解释器文件存在。
4. 执行完整离线测试。
5. 执行应用依赖检查。
6. 执行配置校验。
7. 记录测试数量、失败项、警告和运行环境。
8. 记录当前真实设备 smoke 是否已经执行，以及执行时使用的设备配置和现场状态。

### 命令

```powershell
./run_tests.ps1
./start_gui.bat --check
./start_gui.bat --validate-config
```

### 验收标准

- 测试基线有日期、提交号和解释器信息；
- 已知失败和警告已经单独记录；
- 启动检查和配置校验结果明确；
- 没有把真实设备访问混入离线测试；
- 基线文档可以被后续阶段引用。

## 7. 阶段 1：划分测试边界和运行入口

### 目标

建立三层测试的明确入口，确保离线测试和 CI 永远不会访问真实设备。

### 步骤

1. 保留 `run_tests.ps1` 作为默认离线测试入口。
2. 增加单元测试和模拟测试的独立发现路径，或通过参数筛选测试集合。
3. 新增 `run_hardware_smoke.ps1`，作为真实设备测试的唯一推荐入口。
4. 为真实设备测试增加独立配置路径参数。
5. 将硬件 smoke 测试从默认 `unittest discover -s tests` 范围中隔离。
6. 在 CI 中只运行离线单元测试和模拟设备集成测试。
7. 增加测试层级命名约定，例如 `unit`、`simulation`、`hardware`。

### 硬件测试入口要求

真实设备脚本至少应检查：

- `.env` 中的 Python 解释器存在；
- 硬件配置文件明确传入；
- 配置文件不是示例文件；
- 当前环境显式启用硬件 smoke；
- 操作者显式确认测试条件；
- 当前运行不是 CI；
- 目标设备地址来自硬件 smoke 配置，而不是隐式回退到 `config.json`。

### 验收标准

- 执行 `./run_tests.ps1` 不会打开真实 VISA 资源；
- CI 不会发现或执行硬件 smoke；
- 未满足硬件门禁时，硬件脚本拒绝执行；
- 三层测试可以被单独运行并得到明确结果。

## 8. 阶段 2：完善第一层离线单元测试

### 目标

在不需要任何设备的情况下，验证底层命令、参数、状态、数据和错误处理。

### 步骤一：建立 transport 测试替身

实现或整理以下接口：

```python
class ScpiTransport:
    def write(self, command: str) -> None: ...
    def query(self, command: str) -> str: ...
    def close(self) -> None: ...
```

实现：

- `VisaScpiTransport`：包装真实 VISA resource；
- `MockScpiTransport`：记录命令并返回预设响应；
- 统一通信异常类型；
- 可配置超时行为；
- 幂等的 `close()`。

测试内容：

- 写入命令按顺序记录；
- 查询命令返回预设值；
- 未配置响应时明确失败；
- 通信异常被保留或转换为明确异常；
- 关闭操作可重复调用；
- Mock transport 不创建 `pyvisa.ResourceManager()`。

### 步骤二：建立仪器 driver 测试

信号源 driver 至少覆盖：

```text
set_frequency_hz()
set_power_dbm()
set_rf_enabled()
```

频谱仪 driver 至少覆盖：

```text
set_center_frequency_hz()
set_span_hz() 或 configure_bandwidth_hz()
measure_peak_power_dbm()
```

电源 driver 至少覆盖：

```text
set_voltage_v()
set_current_limit_a()
set_output_enabled()
read_voltage_v()
read_current_a()
```

每个 driver 都必须测试：

- 正常命令格式；
- 输入单位；
- 参数范围；
- 非法参数在发送前被拒绝；
- 查询返回值解析；
- 非数字返回；
- 查询失败和超时；
- RF 或电源输出的状态约束。

### 步骤三：保留并扩展现有纯逻辑测试

继续覆盖：

- 配置模型和配置校验；
- 增益、效率、线损和压缩点计算；
- 结果模型序列化和兼容读取；
- 取消和状态转换；
- 资源清理错误汇总；
- GUI 导入不触发硬件连接。

### 验收标准

- 所有单元测试不需要局域网、仪器或 VISA 驱动；
- driver 测试能够检查实际发送的 SCPI；
- 非法参数不会产生硬件命令；
- 单元测试可以稳定重复运行；
- CI 可以运行全部第一层测试。

## 9. 阶段 3：完善第二层模拟设备集成测试

### 目标

验证多设备组合、测量流程、故障处理和安全清理，而不接触真实设备。

### 步骤一：统一模拟设备行为

基于现有 `instrument/simulation.py`，确保模拟设备支持：

- 命令和动作记录；
- 连接和断开状态；
- RF 状态；
- 电源通道状态；
- 模拟测量读数；
- 根据输入功率生成读数；
- 单步故障注入；
- 查询失败和清理失败注入。

### 步骤二：实现正常流程测试

至少覆盖：

```text
validate
connect
prepare
power_on
start_measurement
set_rf_enabled(True)
measure
set_rf_enabled(False)
power_off
close
```

验证：

- 状态转换合法；
- RF 开启前已完成准备；
- 电源输出顺序正确；
- 测量结果完整；
- 最终 RF 和电源输出均关闭；
- 连接资源均已释放。

### 步骤三：实现异常和取消测试

至少覆盖：

- 信号源连接失败；
- 频谱仪连接失败；
- 电源连接失败；
- 准备阶段失败；
- RF 开启失败；
- 测量查询失败；
- RF 关闭失败；
- Drain 关闭失败；
- Gate 关闭失败；
- 连接关闭失败；
- 普通停止；
- 紧急停止；
- 中途异常后的清理；
- 重复调用 `close()`。

### 步骤四：实现流程级命令序列断言

至少验证以下安全顺序：

```text
正常结束：RF off → Drain off → Gate off → connection close
上电：Gate on → Drain on
掉电：Drain off → Gate off
```

### 验收标准

- 模拟设备可以运行一条完整基础流程；
- 每一种预期故障都进入清理路径；
- 清理失败时仍尽力执行后续安全动作；
- 普通停止和紧急停止语义不同且可验证；
- 流程测试不需要真实 VISA 地址；
- 模拟层结果和命令记录可用于后续回归比较。

## 10. 阶段 4：建立第三层真实设备只读 smoke

### 目标

先验证设备局域网、VISA 地址、设备身份和只读状态，不执行会改变设备输出的动作。

### 步骤

1. 新建 `hardware/smoke_config.example.json`。
2. 在本机创建未纳入版本控制的 `smoke_config.local.json`。
3. 为每台设备配置地址、型号、用途和超时。
4. 通过 VISA 打开资源。
5. 执行身份查询，例如 `*IDN?`，具体命令以设备协议为准。
6. 检查返回型号是否与配置匹配。
7. 查询设备错误状态。
8. 读取 RF 和电源输出状态。
9. 关闭 VISA 资源。
10. 记录每台设备的身份、响应时间、错误状态和最终连接状态。

### 只读 smoke 禁止事项

- 不打开 RF；
- 不打开电源输出；
- 不执行完整测量；
- 不修改校准、保护和生产参数；
- 不默认读取业务 `config.json`；
- 不在测试失败后跳过清理。

### 验收标准

- 所有目标设备可以连接并返回正确身份；
- 设备错误状态符合现场预期；
- 测试结束后没有遗留连接；
- 测试结果包含可追踪日志；
- 没有发送 RF 开启或电源开启命令。

## 11. 阶段 5：建立真实设备安全准备 smoke

### 目标

验证真实设备可以完成准备和配置，但 RF 和电源输出仍保持关闭。

### 步骤

1. 通过硬件 smoke 门禁。
2. 连接信号源、频谱仪和电源。
3. 验证设备身份。
4. 将信号源功率设置为经批准的最低测试值。
5. 设置测试频率。
6. 设置频谱仪中心频率、带宽或 Span。
7. 设置电源电压、电流和保护参数，但保持输出关闭。
8. 读取设备状态。
9. 验证 RF 关闭。
10. 验证全部电源输出关闭。
11. 执行统一清理。

### 验收标准

- 配置命令在真实设备上得到预期响应；
- RF 始终保持关闭；
- 电源输出始终保持关闭；
- 任意中途异常都能触发清理；
- 清理后设备仍处于可确认的安全待机状态。

## 12. 阶段 6：建立真实设备最小空载动作 smoke

### 目标

验证真实环境中的“连接、准备、最小动作、读数、停止和清理”闭环。

该阶段只在只读 smoke 和安全准备 smoke 稳定后执行。

### 硬件配置要求

真实 smoke 配置必须独立于业务配置，例如：

```json
{
  "environment": "hardware_smoke",
  "require_empty_setup": true,
  "require_user_confirmation": true,
  "max_action_count": 1,
  "max_duration_s": 30,
  "devices": {
    "signal_generator": {
      "address": "TCPIP0::example::inst0::INSTR",
      "model": "现场型号"
    },
    "spectrum_analyzer": {
      "address": "TCPIP0::example::inst0::INSTR",
      "model": "现场型号"
    },
    "power_supply": {
      "address": "TCPIP0::example::inst0::INSTR",
      "model": "现场型号"
    }
  }
}
```

本地真实配置不得提交到版本库。示例配置不得被测试脚本当作可执行配置。

### 执行步骤

1. 检查当前网络接口和设备地址。
2. 检查所有设备身份。
3. 要求操作者确认设备空载。
4. 要求操作者确认允许执行一次最小动作。
5. 设置最低风险的测试参数。
6. 按安全顺序准备设备。
7. 执行一个受限动作。
8. 读取一个预期测量值或状态值。
9. 立即关闭 RF。
10. 按 `Drain off → Gate off` 顺序关闭电源。
11. 关闭连接。
12. 再次读取或确认 RF 和电源输出状态。
13. 保存测试日志和结果摘要。

### 强制限制

- 动作次数限制为配置允许的最大值；
- 设置总超时、单动作超时和连接超时；
- 限制信号源功率、频率范围和持续时间；
- 遇到超时、断连、报警、状态不一致时立即停止后续动作；
- 正常结束、异常、取消和程序退出都必须进入清理路径；
- 测试完成后必须确认 RF 和电源输出关闭；
- 不能把“程序没有抛出异常”作为唯一通过标准。

### 通过标准

- 设备身份正确；
- 动作数量符合配置上限；
- 获得预期响应或读数；
- 没有报警或未处理超时；
- RF 已关闭；
- 电源输出已关闭；
- 连接已释放；
- 日志包含开始、身份、动作、读数、清理和结束信息。

## 13. 阶段 7：将三层测试接入功能重构

### 目标

确保每个功能迁移都经过三层验证，并且旧入口在迁移期间仍可回滚。

### 推荐迁移顺序

1. transport；
2. 信号源 driver；
3. 频谱仪 driver；
4. 电源 driver；
5. action；
6. 上电和掉电 flow；
7. 线损测量服务；
8. 驱动功率映射服务；
9. 主功放测量服务；
10. GUI worker 和应用入口。

### 每个功能迁移的固定步骤

1. 记录旧实现的输入、输出、命令顺序和清理行为。
2. 为纯逻辑和接口行为补充第一层测试。
3. 使用模拟设备补充完整流程和故障测试。
4. 实现新层或新 flow，并保留旧入口适配。
5. 运行相关离线测试。
6. 运行完整模拟流程测试。
7. 仅在功能涉及设备控制时运行真实设备 smoke。
8. 对比重构前后的结果、命令顺序和日志。
9. 确认旧入口仍可回滚。
10. 记录阶段结果后再迁移下一个功能。

### 每个功能的最低验收要求

- 第一层覆盖参数、结果和异常；
- 第二层覆盖正常流程和清理；
- 涉及真实设备控制时，第三层通过相应 smoke；
- 没有新增未解释的回归；
- 新实现没有把 SCPI 发送逻辑泄漏到 GUI 或业务服务；
- 旧实现仍有明确回滚方式。

## 14. 阶段 8：最终验收和长期运行规范

### 最终验收命令

```powershell
./run_tests.ps1
./start_gui.bat --check
./start_gui.bat --validate-config
./run_hardware_smoke.ps1 -ConfigPath "hardware/smoke_config.local.json"
```

真实设备命令只在设备已连接、设备空载、现场允许执行时运行。

### 长期运行规则

- 每次提交运行离线单元测试和模拟设备测试；
- 修改 transport、driver、action、flow、设备配置或清理逻辑后，安排真实 smoke；
- 重构前和重构完成后使用同一套真实 smoke 步骤；
- 定期执行只读 smoke，确认地址、固件和通信环境没有漂移；
- 每次硬件 smoke 保存日志、配置快照、软件版本和设备身份；
- 真实设备测试失败时，先保留日志和现场状态，再判断是软件、网络、设备还是配置问题；
- 不把真实设备 smoke 放入普通 CI；
- 不将真实地址、现场凭据和本地硬件配置提交到版本库。

## 15. 设计约束

整个重构期间保持以下约束：

1. 离线测试不得访问真实局域网和 VISA 资源。
2. 模拟设备测试不得依赖真实地址。
3. 真实设备测试不得默认使用业务 `config.json`。
4. hardware smoke 不得默认包含在普通测试发现范围内。
5. transport 只负责通信，不实现仪器业务语义。
6. driver 不读取全局业务配置，不组合完整测试流程。
7. action 和 flow 不直接创建 VISA 连接。
8. action 和 flow 不直接拼接 SCPI。
9. 普通设置动作不得隐式打开 RF 或电源。
10. 电源通道角色不得依赖固定的 `CH1`、`CH2` 约定。
11. 所有内部接口明确参数单位。
12. 所有清理路径都必须考虑异常、取消和重复调用。
13. 旧入口在迁移期间保留，直到新实现完成三层验证。
14. 每个阶段必须记录测试结果、已知问题和回滚方式。

## 18. 后续维护项

以下问题不影响当前测试结果，但应在后续有合适机会时整理：

1. `tests/test_instrument_simulation.py` 中的连接失败参数化用例通过手动调用 `self.setUp()` 重置 fixture。应改为提取设备/session 构造辅助方法，或拆分为独立测试，避免绕过 unittest 的常规生命周期，降低未来增加清理回调或资源管理时的维护风险。
2. `tests/test_instrument_simulation.py` 中 Drain/Gate 关闭失败用例使用回调交替翻转状态来选择失败动作。应改为使用调用计数或支持按动作和值匹配的故障注入方式，直接表达指定通道失败，提升测试可读性和稳定性。
