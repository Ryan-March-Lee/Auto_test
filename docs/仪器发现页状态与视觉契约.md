# 仪器发现页状态与视觉契约

本文记录当前 `InstrumentDiscoveryPanel` 的实际行为，作为仪器卡片动效重构的基线。代码用 `instrument_discovery_panel.DiscoveryPhase` 显式表达流程（`IDLE` / `SCANNING` / `RESULT_PENDING` / `DEALING` / `INTERACTIVE` / `CLOSED`），`results_box.boxState` 只由当前状态推导外观；扫描线程、等待牌堆与发牌动画各自是独立组件。

本文覆盖本次重构涉及的关键异步事件：扫描启动与进度、扫描结果、等待动画周期结束、发牌完成、返回、页面关闭。它不穷举所有信号顺序，也不把“某一轮动画是否已经播完”以外的时序当作契约。

## 状态定义

| 流程状态 | 当前实现中的依据 | 扫描设置与按钮 | 用户可见内容 |
| --- | --- | --- | --- |
| `IDLE` | `phase == IDLE`（`boxState == idle`），没有待处理结果；扫描 worker 已释放或只剩收尾 | 网段、扫描方式、“查找设备”可用；“返回”隐藏 | 结果区上方显示“查找设备”卡片，没有结果卡片。空结果、失败、取消呈现后也回到这个布局，状态行保留各自说明（空结果不是完整的初始画面，见下文）。 |
| `SCANNING` | `phase == SCANNING`（`boxState == busy`），扫描 worker 正在执行 | 扫描设置在 `request_scan` 时禁用；“查找设备”隐藏、原位换成等待牌堆；“返回”隐藏 | 状态行显示“正在查找设备 … x/y”；结果卡片不显示。 |
| `RESULT_PENDING` | `phase == RESULT_PENDING`：扫描信号已把 `(completed/failed/cancelled, payload)` 写入 `_pending_outcome`，等待 `cycle_finished`（显式策略 `WAIT_FOR_FULL_CYCLE`） | worker 结束时由 `worker.finished` 重新启用网段与扫描方式，这个信号可能早于或晚于本轮等待动画结束；“查找设备”仍隐藏（`boxState == busy`），界面正常路径无法再次启动；直接调用 `request_scan` / `request_back` 仍被 pending 守卫拒绝并提示“扫描正在进行，请等待完成” | 保持 `SCANNING` 画面，等待动画完整收拢一轮后才消费结果；扫描线程可能已结束。 |
| `DEALING` | `phase == DEALING`（`boxState == results`），`CardDealAnimation` 正在运行，真实卡片不可点 | 结果卡片区禁用；扫描设置见下注；“返回”可见且可点——点击会取消发牌并回到 `IDLE`（`request_back` → `clear_results` → `_clear_cards`） | 卡片按最终布局占位但被透明度效果隐藏；牌从等待牌堆位置飞至卡片槽位，先背面朝上，全部落位后由左至右翻开；结果提示暂不显示。 |
| `INTERACTIVE` | `phase == INTERACTIVE`（`boxState == results`）：发牌层已完成 | 结果卡片区启用；扫描设置见下注；“返回”可见 | 卡片可见且可交互；只有存在失败、提示或需要核对的信息时状态行才出现（不再写数量统计），结果保持在页面，不存在收起/展开结果抽屉。 |
| `ERROR` | 当前不是持久独立状态：失败结果被消费后 `phase` 回到 `IDLE`（`outcome=failed`），调用 `_show_failure` | `boxState` 回到 `idle`；扫描设置见下注；“查找设备”可见；“返回”隐藏 | 显示“扫描失败: …”，用户可修改扫描设置后重试。失败同样先等等待动画完成一整轮。 |
| `CANCELLED` | 当前不是持久独立状态：取消结果被消费后 `phase` 回到 `IDLE`（`outcome=cancelled`），调用 `_show_cancelled` | `boxState` 回到 `idle`；扫描设置见下注；“查找设备”可见；“返回”隐藏 | 显示“扫描已取消，结果未更新”。取消结果也先等等待动画完成一整轮。 |
| `CLOSED` | `phase == CLOSED`，`_closed == True` | 终态：之后不再接受任何流程转移，页面也不再改控件 | 关闭时丢弃待处理结果、作废当前扫描、取消发牌（不恢复被隐藏的卡片），请求停止扫描并最多等待 `timeout_ms`；扫描线程不被强杀，超时则保留引用交由调用方处理，不再处理后续 UI 信号。 |

`ERROR` 与 `CANCELLED` 是 `RESULT_PENDING` 消费后的结果分支，不是额外的 `boxState` 值；它们直接复用 `idle` 布局。

允许的转移由 `_PHASE_TRANSITIONS` 表定义，`_set_phase` 在改写状态之前校验；表里没有的跳转直接 `ValueError`，不会停在两个状态之间：

```text
IDLE            → SCANNING, CLOSED
SCANNING        → RESULT_PENDING, IDLE, CLOSED
RESULT_PENDING  → DEALING, IDLE, CLOSED
DEALING         → INTERACTIVE, IDLE, CLOSED
INTERACTIVE     → IDLE, SCANNING, CLOSED
CLOSED          → （终态）
```

因此 `IDLE` / `INTERACTIVE` 可以开始新查找；`SCANNING` / `RESULT_PENDING` / `DEALING` 下程序调用 `request_scan` 也不会进入扫描（前两者提示“扫描正在进行，请等待完成”，`DEALING` 直接忽略——卡片与覆盖层都还指着这一次结果）；清空结果、空结果、失败与取消都能回到 `IDLE`；`CLOSED` 之后一切转移被拒绝。

扫描设置（网段、扫描方式）的可用性由扫描 worker 的生命周期单独决定：`request_scan` 时禁用，`worker.finished` 时恢复，与流程状态没有直接关系。状态表默认该信号已处理；若结果消费早于 worker 收尾，`IDLE` / `DEALING` / `INTERACTIVE` 下网段与扫描方式会短暂仍禁用。“查找设备”按钮只在 `IDLE` 可见，“返回”按钮只在 `DEALING` / `INTERACTIVE` 可见。

逻辑主路径：

```text
IDLE → SCANNING → RESULT_PENDING → DEALING → INTERACTIVE
                        │
                        ├─ completed 且设备数为 0 → 回到 IDLE 布局（保留一句空结果说明）
                        ├─ failed                 → 显示失败说明（IDLE 布局）
                        └─ cancelled              → 显示取消说明（IDLE 布局）
```

实际的结果分支：

- 成功且设备数大于零：消费 pending outcome → 建卡并排定结果区 → `DEALING` → 动画完成 → `INTERACTIVE`。
- 成功但设备数为零：跳过发牌，`boxState` 设回 `idle` 并立即显示空结果说明（“未发现设备，可调整网段或扫描方式后重新查找”）及扫描器提示；“查找设备”卡片重新可用，不显示返回按钮。这是 `IDLE` 布局加空结果状态行，不等同于“还没查找过”的完整初始画面。
- 失败/取消：不创建结果卡片，回到 `IDLE` 布局并显示原因/取消提示。
- “返回”仅在结果态可见；点击后清空本次结果、勾选和状态，回到初始查找画面，同时作废本次进入页面时登记的配置预选基线：随后重新查找从“什么都没选”开始，不能马上又按旧绑定把卡片勾回去（配置本身不改，重新进入本页时仍按身份预选）。扫描或 pending 期间即使从代码路径调用也会被拒绝，提示“扫描正在进行，请等待完成”。
- 页面关闭走 `CLOSED` 清理路径，不等待等待牌堆周期完成。

## 状态转移与触发条件

| 当前状态 | 事件 | 后续状态/行为 |
| --- | --- | --- |
| `IDLE` | `request_scan` | 清空旧卡片与 pending outcome，禁用扫描设置，切换 busy 画面并启动 worker → `SCANNING`。 |
| `SCANNING` | worker progress | 状态行更新进度；流程状态不变。 |
| `SCANNING` | `completed` / `failed` / `cancelled` 信号 | 保存 pending outcome → `RESULT_PENDING`；不立即收走等待牌堆。 |
| `SCANNING` | `request_scan` 时线程启动失败（`QThread.start()` 抛 `RuntimeError` / `OSError`） | 释放 worker 引用、恢复扫描设置并写“扫描失败: 无法启动扫描线程，请重试”，回 `IDLE`；异常原样向外传播，不静默降级。 |
| 任意未关闭状态 | `clear_results`（进入页面、切换配置、按“返回”） | 清空设备、卡片、pending outcome；作废当前查找（见下）→ `IDLE`。 |
| `SCANNING` / `RESULT_PENDING` | `worker.finished` | 仅当这是当前那次查找的线程时释放引用并重新启用扫描设置；不改变 `boxState`，不消费 pending outcome，也不推进结果动画。旧线程的收尾不动当前扫描。 |
| `RESULT_PENDING` | `ScanWaitStack.cycle_finished` 且有 pending outcome | 消费一次 pending outcome；成功结果按有设备/空结果分流（有设备进入 `DEALING`，空结果直接回 `IDLE`），失败/取消呈现各自提示。无 pending 时不改变状态，等待动画继续循环。 |
| `DEALING` | `CardDealAnimation.finished` | 清理残留透明度效果并进入 `INTERACTIVE`，恢复卡片区交互并显示状态行。 |
| `DEALING` | `CardDealAnimation.start()` 抛错 | 撤销透明度效果、恢复卡片区可点，进入 `INTERACTIVE` 让结果立即可用；写一条日志说明发牌未启动，异常继续向外传播。 |
| `DEALING` / `INTERACTIVE` | 清理卡片/返回 | 先取消发牌层（不恢复显示），再删除卡片并进入 `IDLE`。 |
| 任意未关闭状态 | 页面 shutdown | 作废当前扫描，进入 `CLOSED` 清理，不再响应 UI 结果。 |

等待周期与扫描 worker 是两条异步链路。产品要求“结果到达时不打断未完成的一轮”，代码用显式策略 `WAIT_FOR_FULL_CYCLE` 表达：为真时结果先进入 `RESULT_PENDING`，等 `cycle_finished`（牌堆复原）再消费；为假时扫描结论一到就直接进入 `DEALING` / 空结果，不再等牌堆。因为 `worker.finished` 与 `cycle_finished` 的先后没有保证，`RESULT_PENDING` 期间控件可用性与“能否开始新扫描”必须分开看：前者由 worker 生命周期决定，后者由 pending 守卫和当前 `phase` 共同决定。

### 结果作废与终态

- 每次 `request_scan` 递增一个扫描代次并把代次交给 `DiscoveryWorker`；`clear_results` 与 `shutdown` 会再次递增（`_invalidate_scan`）。信号到达时代次对不上就只当作“旧线程收尾”，不更新状态行、不写 pending、不进入 `RESULT_PENDING`。
- 作废时同时请求协作取消（`cancel_event` / `requestInterruption()` / `scanner.request_cancel()`），但不等待线程；线程结束后的 `worker.finished` 照常释放引用并恢复扫描设置，所以“清空结果”不会留下禁用的扫描行。
- `CLOSED` 是终态：关闭后脚本化的结果信号（`completed` / `failed` / `cancelled`）、等待周期结束与动画回调都不改变流程状态，也不重新显示结果。

## 当前视觉契约

### 常驻布局与按钮

- 扫描网段/扫描方式行位于标题下方并居中；扫描期间也不因焦点切换而主动滚动页面。
- 结果区没有边框和底色，直接落在页面背景上。结果卡片位于上部；“查找设备”/等待牌堆位于其下，中间保留引导间距，二者不重叠。
- “查找设备”是与仪器卡片同尺寸的自绘深色卡片，不是标准按钮；点击后在原位置切换成等待动画。等待舞台可以比卡片大，但占位和点击范围不因此变宽。
- 结果区动作行里，“全选”和“下一步”作为一个整体严格居中，面板自己的“返回”贴在最右端；居中是按左右两端等宽占位实现的（左端先留出与返回按钮等宽的占位）。
- “全选”只在本次结果进入 `INTERACTIVE` 且存在可应用设备后出现，与“下一步”同时出现：初始是白底黑框黑字的可点胶囊，点击后一次选中所有可应用卡片，按钮随即变成白底灰框灰字、不可点；用户取消任意一张已选卡片后立刻恢复初始态。未登记、无角色或无法识别地址的卡片本来就不可选，不参与“是否全部选中”的判断。它没有蓝色填充与展开动画，形状、高度、圆角与字重和“下一步”共用同一份胶囊几何。鼠标点击“全选”后按钮转为灰态，焦点交给“下一步”但不画键盘焦点框，避免它看起来像也被选中；用 Tab/空格激活“全选”时，焦点框仍随焦点交给“下一步”。
- “下一步”只在本次结果进入 `INTERACTIVE` 且存在可应用设备后出现：一台都没勾时是灰色不可点的静止态；勾上任何一台后变为可点的蓝色按钮，并在那次状态切换里播放一次自绘动效（圆形色块从中心展开、外圈光晕变宽、文字转白）。可用状态下鼠标移入再轻微上浮 2px，按下缩放 0.95；写入校验仍以页面的 `request_next` 为准，按钮状态只是外观与第一道入口。
- 等待动画为 7 张卡：扇形展开、轻微捻动、收拢复位并停顿后循环。扫描结果到达时不打断未完成的一轮。

### 结果与发牌

- 每台发现设备对应一张卡，扫描结果到达后先创建卡片并确定布局，再执行发牌；结果区高度由页面可用高度决定，窗口较矮时压缩到一行，卡片过多时在结果区内滚动。
- 发牌起点为等待牌堆当时的屏幕位置，目标为卡片最终槽位。发牌层挂在页面根容器的覆盖层上（`presentation/qt/animation_overlay.py`，步骤 6），不在 `results_box` 或 `QScrollArea` 内部；起点、每张卡的落点与卡片区裁剪矩形在动画开始时一次性换算到覆盖层坐标（跨分支经屏幕坐标中转，见 `widget_rect_in()`），动画期间不再逐帧追踪卡片控件。页面根容器尺寸变化或页面滚动时取消这一次发牌并恢复卡片（记录 `cancel_reason=surface-changed`），不在动画中途追踪布局；页面被藏起来（切页、标签页切走）或所在窗口最小化时按 `page-hidden` 同样收尾（覆盖层同时看宿主 `Hide` 与顶层窗口 `WindowStateChange`，同一次“看不见”只通知一次），关闭页面则按 `page-shutdown` 收尾且不恢复即将销毁的控件（步骤 12 的 `OverlayLifecycle`）。卡片区自己的视口尺寸/滚动变化先比较当前落点与冻结落点，卡片挪了才取消，只是可见区域变化就只刷新裁剪遮罩。裁剪只约束**已经落定**的牌：牌堆继承“查找设备”按钮的位置、按设计就在卡片视口之外，牌堆与飞行段因此整段可见，落点本身在视口外的牌不画（不让轨迹压到状态行/动作行上），牌不会在卡片区边界上被平切。动画正面由 `card_assets.render_card_asset()` 按卡片内容渲染（`CardAsset.front`），背面用 `CardAsset.back`（绿色光子卡面，与等待动画最上面那张牌同一张位图；牌背朝上时再按 `CardAsset.back_particles` 叠一层外飘的绿色粒子），都不截取卡片控件；真实卡片以透明度效果隐藏，动画期间不可点。动画只接收 `CardDealItem(asset, target_rect, index)`，每张读自己的内容快照（不按设备标题回查，标题重名不会串画面）；`index` 必须是 `0..N-1` 的连续编号（面板直接把它当卡片列表下标），翻开哪张就通过 `card_revealed(index)` 交回面板恢复哪张。旧的 `card.grab()` 截图只在面板的排障开关打开时使用。空结果走 `skip` 并直接回 `IDLE`，若上一次发牌还在播会先按完成路径交回每张卡片并发 `finished`；面板在 `start()` 抛错时统一撤销透明度效果、恢复卡片区可点并把流程推进到 `INTERACTIVE`，因此任何收尾路径都不会留下透明、不可点或停在 `DEALING` 的卡片。
- 牌先背面朝上飞行；全部落位后停顿，再从左至右逐张翻开。最后一张翻完才恢复卡片交互。
- 结果回来后不再显示“发现 N 台设备：已登记…／可应用…／未登记…”这类数量统计：每张卡片已经写明自己的登记与可用状态（未登记、未分配角色、无法识别），这行灰字只是重复。状态行只在扫描进度、失败原因、空结果说明、扫描器提示与“角色以设备表为准”这类需要用户核对的信息出现；没有话要说时整行隐藏。
- 有设备时结果留在页面；“返回”清除本次结果与勾选，回到初始查找卡片（全选与下一步随结果隐藏）。空结果、失败、取消均不进入发牌，不显示结果返回按钮。

### 卡片内容与交互

- 卡片第一行显示设备缩写码（无登记缩写时退回完整设备码）；型号下一行显示“型号·角色”；底部以灰色小字显示本次扫描 IP。完整身份和连接细节在悬浮提示中。
- 未登记设备及无法识别地址仍显示卡片，但不可应用为测试角色；无角色的已登记设备也不能应用。角色不由用户在卡片上选择。
- 可应用卡片可选择；电源卡片按设备身份分别选择，多台电源互不覆盖。重新查找时选中状态清空。

## 重构边界提示

以上记录的是现状。步骤 8 起 `DiscoveryPhase` 是唯一的流程状态，`boxState` 只是由它推导的外观值（`idle` / `busy` / `results`）；`_set_phase` 是唯一转移入口（按 `_PHASE_TRANSITIONS` 校验），`_render_phase` 是唯一渲染入口，失败与取消回 `IDLE` 并保留状态行说明。扫描结果按代次归属：清空、重扫与关闭之后，旧线程的迟到信号只释放资源，不会把结果画回页面。发牌正面自步骤 5 起改用卡片资产；步骤 6 起覆盖层挂在页面根容器上，落点在动画开始时冻结，页面尺寸或滚动变化用取消代替中途追踪，卡片区仅裁剪遮罩随可见区域刷新。步骤 12 起“何时收尾”不再由页面各自接事件：`animation_lifecycle.OverlayLifecycle` 统一处理宿主缩放、滚动、隐藏（含所在窗口最小化）与关闭，页面只登记一个收尾入口，定时器由动画自己的 `cancel()` 停；面板单独使用时由自己的隐藏事件走同一个入口。页面宿主与面板的隐藏事件没有先后约定，收尾入口在未运行时返回 `False`，因此两条入口重复触发是幂等的。每次转移都写 `animation event=discovery_phase ...` 日志，成功、空结果、失败与取消可以按固定字段复现。后续步骤应在保留上述可见行为的前提下继续清理命名与公共过渡。

对应实现：`presentation/qt/instrument_discovery_panel.py`、`presentation/qt/scan_card.py`、`presentation/qt/photon_card.py`、`presentation/qt/device_cards.py`、`presentation/qt/animation_overlay.py`（步骤 6 新增），以及卡片资产 `presentation/qt/card_assets.py`（步骤 4 新增，步骤 5 已接入发牌）。卡片资产与真实卡片共用同一份内容、行位置（`device_cards.card_row_plan()`）与字体（`theme.card_*_font()`），因此两者在边框以内逐像素一致；发牌不再需要重新定义卡片的视觉规则。

步骤 9 起，上文“牌先背面朝上飞行；全部落位后停顿，再从左至右逐张翻开”有固定帧测试：`tests/ui/test_card_deal_frames.py` 钉住起飞、双牌飞行、全部落位、半翻、全部翻开与取消六个时刻，并与 `tests/ui/visual_baselines/card_deal_frames/` 下的关键帧做低精度比对（整帧按粗采样控制整体回归，卡片落点区域再按更密的采样单独比对）；另有一条用例让真实计时器 tick 一次，确认 `elapsed_ms` 推进时空覆盖层仍是空的。`tests/integration/device_discovery/test_discovery_frames.py` 在真实面板上覆盖无设备、单设备、多设备、窄窗口与取消恢复。画面断言以“是否真的画出牌面 / 正反面与位置是否正确”为主，不要求每帧逐像素相等。
