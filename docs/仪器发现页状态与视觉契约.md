# 仪器发现页状态与视觉契约

本文记录当前 `DeviceDiscoveryPanel` 的实际行为，作为仪器卡片动效重构前的基线。这里的流程状态是描述/设计契约，不代表当前代码已经实现了一个显式状态机；代码目前以 `results_box.boxState`、`_pending_outcome`、扫描线程和动效对象的状态共同表达流程。

本文覆盖本次重构涉及的关键异步事件：扫描启动与进度、扫描结果、等待动画周期结束、发牌完成、返回、页面关闭。它不穷举所有信号顺序，也不把“某一轮动画是否已经播完”以外的时序当作契约。

## 状态定义

| 流程状态 | 当前实现中的依据 | 扫描设置与按钮 | 用户可见内容 |
| --- | --- | --- | --- |
| `IDLE` | `boxState == idle`，没有待处理结果；扫描 worker 已释放或只剩收尾 | 网段、扫描方式、“查找设备”可用；“返回”隐藏 | 结果区上方显示“查找设备”卡片，没有结果卡片。空结果、失败、取消呈现后也回到这个布局，状态行保留各自说明（空结果不是完整的初始画面，见下文）。 |
| `SCANNING` | `boxState == busy`，扫描 worker 正在执行 | 扫描设置在 `request_scan` 时禁用；“查找设备”隐藏、原位换成等待牌堆；“返回”隐藏 | 状态行显示“正在查找设备 … x/y”；结果卡片不显示。 |
| `RESULT_PENDING` | 扫描信号已把 `(completed/failed/cancelled, payload)` 写入 `_pending_outcome`，等待 `cycle_finished` | worker 结束时由 `worker.finished` 重新启用网段与扫描方式，这个信号可能早于或晚于本轮等待动画结束；“查找设备”仍隐藏（`boxState == busy`），界面正常路径无法再次启动；直接调用 `request_scan` / `request_back` 仍被 pending 守卫拒绝并提示“扫描正在进行，请等待完成” | 保持 `SCANNING` 画面，等待动画完整收拢一轮后才消费结果；扫描线程可能已结束。 |
| `DEALING` | 有设备结果已填卡，`boxState == results`，`DealRevealLayer` 正在运行 | 结果卡片区禁用；扫描设置见下注；“返回”可见且可点——点击会取消发牌并回到 `IDLE`（`request_back` → `clear_results` → `_clear_cards`） | 卡片按最终布局占位但被透明度效果隐藏；牌从等待牌堆位置飞至卡片槽位，先背面朝上，全部落位后由左至右翻开；结果统计暂不显示。 |
| `INTERACTIVE` | 发牌层完成；`boxState == results` | 结果卡片区启用；扫描设置见下注；“返回”可见 | 卡片可见且可交互，状态行出现；结果保持在页面，不存在收起/展开结果抽屉。 |
| `ERROR` | 当前不是持久独立状态：失败结果被消费后调用 `_show_failure` | `boxState` 回到 `idle`；扫描设置见下注；“查找设备”可见；“返回”隐藏 | 显示“扫描失败: …”，用户可修改扫描设置后重试。失败同样先等等待动画完成一整轮。 |
| `CANCELLED` | 当前不是持久独立状态：取消结果被消费后调用 `_show_cancelled` | `boxState` 回到 `idle`；扫描设置见下注；“查找设备”可见；“返回”隐藏 | 显示“扫描已取消，结果未更新”。取消结果也先等等待动画完成一整轮。 |
| `CLOSED` | `_closed == True` | 页面正在关闭，不再保证控件可用性 | 关闭时丢弃待处理结果，取消发牌（不恢复被隐藏的卡片），请求停止扫描并最多等待 `timeout_ms`；扫描线程不被强杀，超时则保留引用交由调用方处理，不再处理后续 UI 信号。 |

`ERROR` 与 `CANCELLED` 是 `RESULT_PENDING` 消费后的结果分支，不是额外的 `boxState` 值；它们直接复用 `idle` 布局。

扫描设置（网段、扫描方式）的可用性由扫描 worker 的生命周期单独决定：`request_scan` 时禁用，`worker.finished` 时恢复，与 `boxState` 没有直接关系。状态表默认该信号已处理；若结果消费早于 worker 收尾，`IDLE` / `DEALING` / `INTERACTIVE` / `ERROR` / `CANCELLED` 下网段与扫描方式会短暂仍禁用。“查找设备”按钮只在 `idle` 可见，“返回”按钮只在 `results` 可见。

逻辑主路径：

```text
IDLE → SCANNING → RESULT_PENDING → DEALING → INTERACTIVE
                        │
                        ├─ completed 且设备数为 0 → 回到 IDLE 布局（保留“发现 0 台设备”统计）
                        ├─ failed                 → 显示失败说明（IDLE 布局）
                        └─ cancelled              → 显示取消说明（IDLE 布局）
```

实际的结果分支：

- 成功且设备数大于零：消费 pending outcome → 建卡并排定结果区 → `DEALING` → 动画完成 → `INTERACTIVE`。
- 成功但设备数为零：跳过发牌，`boxState` 设回 `idle` 并立即显示“发现 0 台设备 …”及结果提示；“查找设备”卡片重新可用，不显示返回按钮。这是 `IDLE` 布局加空结果状态行，不等同于“还没查找过”的完整初始画面。
- 失败/取消：不创建结果卡片，回到 `IDLE` 布局并显示原因/取消提示。
- “返回”仅在结果态可见；点击后清空本次结果、勾选和状态，回到初始查找画面。扫描或 pending 期间即使从代码路径调用也会被拒绝，提示“扫描正在进行，请等待完成”。
- 页面关闭走 `CLOSED` 清理路径，不等待等待牌堆周期完成。

## 状态转移与触发条件

| 当前状态 | 事件 | 后续状态/行为 |
| --- | --- | --- |
| `IDLE` | `request_scan` | 清空旧卡片与 pending outcome，禁用扫描设置，切换 busy 画面并启动 worker → `SCANNING`。 |
| `SCANNING` | worker progress | 状态行更新进度；流程状态不变。 |
| `SCANNING` | `completed` / `failed` / `cancelled` 信号 | 保存 pending outcome → `RESULT_PENDING`；不立即收走等待牌堆。 |
| `SCANNING` / `RESULT_PENDING` | `worker.finished` | 释放 worker 引用并重新启用扫描设置；不改变 `boxState`，不消费 pending outcome，也不推进结果动画。 |
| `RESULT_PENDING` | `ScanWaitStack.cycle_finished` 且有 pending outcome | 消费一次 pending outcome；成功结果按有设备/空结果分流，失败/取消呈现各自提示。无 pending 时不改变状态，等待动画继续循环。 |
| `DEALING` | `DealRevealLayer.finished` | 恢复卡片区交互，`boxState == results` 时显示状态行 → `INTERACTIVE`。 |
| `DEALING` / `INTERACTIVE` | 清理卡片/返回 | 先取消发牌层（不恢复显示），再删除卡片并回到 `IDLE`。 |
| 任意未关闭状态 | 页面 shutdown | 进入 `CLOSED` 清理，不再响应 UI 结果。 |

等待周期与扫描 worker 是两条异步链路，结果要同时满足“扫描信号已到达”和“等待牌堆完整一轮已结束”才进入结果呈现。因为 `worker.finished` 与 `cycle_finished` 的先后没有保证，`RESULT_PENDING` 期间控件可用性与“能否开始新扫描”必须分开看：前者由 worker 生命周期决定，后者由 pending 守卫和当前 `boxState` 共同决定。

## 当前视觉契约

### 常驻布局与按钮

- 扫描网段/扫描方式行位于标题下方并居中；扫描期间也不因焦点切换而主动滚动页面。
- 结果区没有边框和底色，直接落在页面背景上。结果卡片位于上部；“查找设备”/等待牌堆位于其下，中间保留引导间距，二者不重叠。
- “查找设备”是与仪器卡片同尺寸的自绘深色卡片，不是标准按钮；点击后在原位置切换成等待动画。等待舞台可以比卡片大，但占位和点击范围不因此变宽。
- 等待动画为 7 张卡：扇形展开、轻微捻动、收拢复位并停顿后循环。扫描结果到达时不打断未完成的一轮。

### 结果与发牌

- 每台发现设备对应一张卡，扫描结果到达后先创建卡片并确定布局，再执行发牌；结果区高度由页面可用高度决定，窗口较矮时压缩到一行，卡片过多时在结果区内滚动。
- 发牌起点为等待牌堆当时的屏幕位置，目标为卡片最终槽位。发牌层目前挂在 `results_box` 内部；真实卡片通过 `card.grab()` 获取动画正面图，再以透明度效果隐藏，动画期间不可点。
- 牌先背面朝上飞行；全部落位后停顿，再从左至右逐张翻开。最后一张翻完才恢复卡片交互并显示结果统计/提示。
- 有设备时结果留在页面；“返回”清除本次结果与勾选，回到初始查找卡片。空结果、失败、取消均不进入发牌，不显示结果返回按钮。

### 卡片内容与交互

- 卡片第一行显示设备缩写码（无登记缩写时退回完整设备码）；型号下一行显示“型号·角色”；底部以灰色小字显示本次扫描 IP。完整身份和连接细节在悬浮提示中。
- 未登记设备及无法识别地址仍显示卡片，但不可应用为测试角色；无角色的已登记设备也不能应用。角色不由用户在卡片上选择。
- 可应用卡片可选择；电源卡片按设备身份分别选择，多台电源互不覆盖。重新查找时选中状态清空。

## 重构边界提示

以上记录的是现状，不是目标架构承诺。当前 `boxState` 只有 `idle`、`busy`、`results` 三值；`RESULT_PENDING`、`DEALING`、`INTERACTIVE`、`ERROR`、`CANCELLED` 是用于描述异步流程和用户体验的概念状态，尚未由单一枚举/渲染入口统一管理。当前动画依赖卡片截图，且覆盖层处于结果区内部；后续步骤应在保留上述可见行为的前提下逐步替换这些实现细节。

对应实现：`presentation/qt/device_discovery_panel.py`、`presentation/qt/scan_card.py`、`presentation/qt/device_cards.py`，以及步骤 4 新增的卡片资产 `presentation/qt/card_assets.py`（面板尚未接入，当前发牌仍用卡片截图）。卡片资产与真实卡片共用同一份内容、行位置（`device_cards.card_row_plan()`）与字体（`theme.card_*_font()`），因此两者在边框以内逐像素一致；发牌切到资产时不需要再重新定义卡片的视觉规则。
