# 仪器发现页真实窗口验收

本文是仪器发现页的真实窗口验收说明：在真实 Windows 窗口里验收仪器发现页的等待、发牌与翻牌，确认用户实际看到的三个阶段连续、稳定，且不出现空白覆盖层、卡片闪现、卡片重复、残留定时器或不可点击状态。

离屏测试（`tests/ui`、`tests/integration`）继续负责逻辑、坐标与绘制回归；本验收补的是离屏环境覆盖不到的部分：真实窗口合成、真实计时器、系统 DPI/缩放、实际窗口缩放与真实按钮点击。验收采用“证据不足即不通过”：窗口被裁切、截图不是桌面合成画面、结果没有等满一轮等待动画、阶段序列与预期不符，都会记为未通过检查，而不是降级成诊断信息后继续算通过。

## 运行方式

必须在有桌面会话的 Windows 上运行。脚本在创建窗口后检查 `sys.platform` 与 Qt 平台名，只接受 Windows 上的 `windows` 平台；`offscreen`、`minimal`、`minimalegl` 以及其他系统一律以退出码 `3` 拒绝，不会写出报告目录，避免把非目标环境的结果当成验收证据。扫描使用模拟数据，不打开任何真实端口。

```powershell
# 常规 DPI：本机系统缩放 125%，乘 0.8 得到 DPR 1.0
& "D:\Anaconda\envs\Auto_test\python.exe" tools/manual_acceptance.py `
    --scale 0.8 --label normal-dpi

# 高 DPI：使用系统默认缩放（本机 DPR 1.25）
& "D:\Anaconda\envs\Auto_test\python.exe" tools/manual_acceptance.py `
    --label high-dpi
```

`--scale` 是乘在系统缩放上的 Qt 缩放倍数；报告中的 `device_pixel_ratio` 是实际生效的 DPR。窗口固定为 1366×768 逻辑像素。其他可选参数：

| 参数 | 含义 |
| --- | --- |
| `--label` | 写进输出目录名与报告的标签 |
| `--only deal failure empty back resize` | 只跑指定场景 |
| `--output <目录>` | 指定报告目录 |

报告、截图与 JSON 默认写到 `test_results/manual_acceptance/<时间>-<标签>/`。该目录已被 `.gitignore` 忽略，验收证据只保留在本机。退出码：`0` 全部通过，`1` 有检查未通过，`2` 参数错误，`3` 运行环境不符合真实验收条件（非 Windows，或非 Windows 桌面平台）。

## 场景矩阵

| 场景 | 操作 | 期望 |
| --- | --- | --- |
| `deal` | 扫描约 0.5 s 返回 6 台设备 | 等待牌堆完整走完一轮（约 2.1 s）后才发牌；牌从牌堆飞向各自槽位，全部落位后逐张翻开；最后一张翻完才恢复卡片交互与统计行 |
| `failure` | 扫描器报错 | 同样等完一轮等待动画；显示失败说明，回到“查找设备”，不进入发牌 |
| `empty` | 模拟网络没有设备 | 同样等完一轮；显示“发现 0 台设备”，跳过发牌，覆盖层没有一帧牌 |
| `back` | 发牌进行中点结果区“返回” | 覆盖层清空，结果卡片随结果一起清空，回到初始查找画面 |
| `resize` | 发牌进行中把窗口缩到 1180×700 | 按 `surface-changed` 取消本次发牌；真实卡片恢复可见可点，统计行重新出现 |

每个场景各开一个真实窗口，场景之间不共享面板状态。等待牌堆一轮的时长由 `WAIT_CYCLE_MS`（2140 ms）决定，与扫描速度无关。

## 判定方式

脚本逐项记录下列检查，全部写入 `report.md` / `report.json`：

- **环境门槛**：只接受 Windows 上的 `windows` 平台；`offscreen` / `minimal` / 非 Windows 直接拒绝运行并返回退出码 `3`。
- **窗口证据**：每个场景都检查窗口完整落在桌面可用区内（`window_visible_ratio` 不低于 `0.999`）。窗口被屏幕边缘裁切时，截图不再代表用户看到的完整窗口，记为未通过。
- **截图证据**：每张截图都检查来源必须是桌面合成（`source=screen`）、尺寸有效、文件非空。控件自身渲染（`source=widget`）只用于排查画面内容，不能替代桌面截图；保存失败或被同名旧文件顶替都会判为未通过。
- **阶段序列**：每个场景声明完整序列并逐项比对，要求不多、不少、不重复、顺序正确，例如正常路径为 `scanning → result-pending → dealing → interactive → closed`。失败与空结果额外禁止出现 `dealing`，证明结果没有被提前消费。
- **等待周期与计时**：以点击“查找设备”的时刻为基准，读取生产代码的 `WAIT_CYCLE_MS`。结果必须在首轮等待结束前返回（否则“等满一轮”是自然发生的，不能证明策略）；从扫描开始到发牌/失败/空结果又必须至少跨过一整轮（允许 120 ms 调度误差）。正常、失败、空结果三种结局都按这条判据检查。
- **等待阶段**：等待牌堆可见、有实际绘制，“查找设备”已收起，扫描设置在扫描期间禁用。
- **发牌阶段**：动画挂在页面级 `AnimationOverlay` 上；动画项数等于卡片数；真实卡片全部带透明度效果且卡片区不可点；覆盖层可见；`front_source=asset`；`first_drawn_cards > 0`；覆盖层采样到非空画面。
- **翻牌阶段**：`phase_at() == "flipping"` 时覆盖层仍非空。
- **收尾**：`event=finish`、`revealed_count=6`、`paint_frames > 0`；卡片可见、不再有透明度效果、卡片区可点、统计行出现。
- **取消/失败/空结果**：`cancel_reason` / `restore_result` 与可见状态一致；空结果的诊断是 `skip` 且 `paint_frames=0`。
- **无残留**：发牌计时器停止、等待牌堆帧计时器停止、扫描线程已释放。
- **人工确认**：逐张打开截图检查画面内容；脚本无法判断“看起来是否自然”，截图与 DPR 信息保留给验收人复查。

上述判定中的环境门槛、等待周期、阶段序列、窗口可见性与截图有效性都是纯函数，由 `tests/test_manual_acceptance_contract.py` 离线覆盖；真实窗口、窗口合成与 DPI 仍只在桌面会话中验证。

### 观察项（不属于本次动效判定）

六列卡片布局下，未登记设备的完整设备码（例如 `DP8B174400885`）在第一行右侧被裁切；已登记设备显示缩写设备码，不受影响。这与发牌/翻牌无关，是卡片内容在窄列宽下的既有表现，留待单独评估，不在本次步骤 10 中修改。

## 结论

步骤 10 的完成标准已满足：真实窗口中等待、发牌、翻牌三个阶段连续可见；两次 DPI 运行都没有空白覆盖层、卡片闪现、卡片重复、残留定时器或不可点击状态。判定不再依赖“阶段出现过”或固定的 800 ms 经验值，而是完整阶段序列、生产等待周期、窗口可见性与桌面截图证据共同成立。后续交付前按本文重跑这两个命令即可；任一证据无效时脚本以非零退出码结束，不会给出通过报告。

本验收只覆盖界面动效与页面交互，不替代真实设备扫描和硬件测量现场验收；硬件路径仍按 Hardware smoke 与现场验收流程执行。
