# 依赖与运行时契约

本文是[技术债分阶段重构计划](技术债分阶段重构计划.md)步骤 14 的执行产物，固定
**解释器、依赖锁定、命令口径和 DPD 隔离**四条契约。启动器、测试入口、编译检查、
锁定清单核对、发布清单和文档都引用同一份定义：

- 代码侧唯一来源：`infrastructure/runtime/runtime_contract.py`
  （`REQUIRED_PYTHON_SERIES`、`DEPENDENCY_LOCK_FILE`、`python_version_supported()`、
  `interpreter_command()`、`verification_commands()`）与
  `infrastructure/runtime/dependency_lock.py`（锁文件严格解析与整份环境核对）。
- 可执行门禁：`tests/test_runtime_dependency_contract.py`。

## 1. 解释器

| 项目 | 契约 |
| --- | --- |
| Python | **3.11.x**（3.11 之外的系列一律拒绝） |
| Conda 环境 | `Auto_test` |
| 已用解释器 | `D:\Anaconda\envs\Auto_test\python.exe` |
| 配置来源 | 项目根目录 `.env` 的 `AUTO_TEST_PYTHON` |

规则：

- 启动器不再使用 `>=3.7` 之类过宽判断；`launcher.py --check` 与 GUI 启动都要求 3.11.x。
- 只读命令（`--validate-config`、`--run-id`、`--list-runs` 等）同样先校验项目解释器与
  3.11 系列，避免用其他版本的结论冒充项目结论；它们仍然不检查依赖包、不初始化日志、
  不连接仪器。
- `tools/runtime_environment.ps1` 在 `run_tests.ps1` 与 `run_hardware_smoke.ps1` 装载时校验
  同一版本系列，PowerShell 入口与 Python 入口不会出现两套标准。
- 解释器必须等于 `.env` 中的 `AUTO_TEST_PYTHON`；不一致时启动器返回退出码 `4`。

`AUTO_TEST_PYTHON` 未配置时，发布清单会回退到生成清单时的解释器绝对路径并记录在
`interpreter` 字段，不会退回裸 `python`。

## 2. 依赖锁定

| 文件 | 作用 |
| --- | --- |
| `requirements.txt` | 主系统**直接依赖**，全部 `==` 精确版本 |
| `requirements.lock.txt` | 主系统**完整锁定**，含传递依赖；新环境复现的唯一依据 |
| `requirements-dpd.txt` | `DPD_auto_test` 专用可选依赖，与主系统隔离 |

锁定清单只由导出工具生成，**不支持手工编辑**：直接 `pip freeze > requirements.lock.txt`
会把 `pip` / `setuptools` / `wheel` 写进清单，违反本文件自己的约定。

### 2.1 新建环境（顺序不可颠倒）

```powershell
# 1. 创建并激活 3.11 环境
conda create -n Auto_test python=3.11
conda activate Auto_test

# 2. 确认新环境自己的解释器（只在这里使用裸 python 做引导，之后一律用 AUTO_TEST_PYTHON）
python -c "import sys; print(sys.version_info[:2]); print(sys.executable)"

# 3. 把第 2 步打印的 python.exe 绝对路径写入项目根目录 .env（先复制 .env.example）
#    AUTO_TEST_PYTHON=D:\Anaconda\envs\Auto_test\python.exe

# 4. 用同一个解释器安装锁定清单
& $env:AUTO_TEST_PYTHON -m pip install -r requirements.lock.txt

# 5. 核对锁文件、直接依赖与已安装环境是否一致
& $env:AUTO_TEST_PYTHON tools/export_dependency_lock.py --check
& $env:AUTO_TEST_PYTHON launcher.py --check
```

`.env` 的 `AUTO_TEST_PYTHON` 是唯一解释器来源。第 3 步之前任何
`& $env:AUTO_TEST_PYTHON ...` 都会失败或落到旧环境；写错环境时第 5 步会立刻报出
锁文件要求与实际安装版本之间的差异，而不是静默装进别的环境。

### 2.2 重新生成锁定清单

```powershell
# 依赖变更并验证通过后，在 Auto_test 环境重新导出
& $env:AUTO_TEST_PYTHON tools/export_dependency_lock.py
& $env:AUTO_TEST_PYTHON tools/export_dependency_lock.py --check
```

导出工具按当前解释器已安装的发行版生成清单：排除打包工具、按名称排序、固定使用
CRLF 与 UTF-8（无 BOM），因此同一环境重复导出得到完全相同的字节。

### 2.3 约束与核对范围

- 锁文件每行必须是 `包名==版本`；出现 `>=`、范围、通配符、直接 URL、重复条目或空文件
  时，解析直接失败（`DependencyLockError`），不会退化成“半份有效清单”。
- `requirements.txt` 的每个直接依赖版本必须与锁文件完全一致。
- 打包工具 `pip` / `setuptools` / `wheel` 由安装环境自带，不写入锁文件。
- **整份核对**：`launcher.py --check` 与 `tools/export_dependency_lock.py --check` 都以
  锁文件为基准逐项核对全部已安装发行版（含传递依赖），而不是只比对启动器导入的
  8 个模块。
- **不在运行时自动安装依赖**：启动器只检查并提示，不执行 `pip`。

| 差异 | `launcher.py --check` | 导出工具 `--check` | GUI 启动 |
| --- | --- | --- | --- |
| 锁内依赖缺失 | 退出码 `5` | 退出码 `1` | 缺失必需模块时退出码 `5`，否则只告警 |
| 锁内版本不符 | 退出码 `5` | 退出码 `1` | 只告警 |
| 锁文件缺失或格式错误 | 退出码 `5` | 退出码 `1` | 只告警 |
| 锁外多余包 | 提示，退出码 `0` | 提示，退出码 `0` | 提示 |

GUI 启动保持“必需模块可用即可启动”的历史语义，把全量锁定结论留给显式的
`--check` 和发布前核对；`--check` 是环境是否合格唯一对外承诺的判据。

## 3. 统一命令

`verification_commands()` 是测试、编译、锁定核对、启动检查、配置校验和发布清单的唯一
命令来源，首段永远是显式解释器路径：

| 用途 | 命令 |
| --- | --- |
| 全量离线测试 | `<AUTO_TEST_PYTHON> -m unittest discover -s tests -v` |
| 编译检查 | `<AUTO_TEST_PYTHON> tools/compile_check.py .` |
| 锁定清单核对 | `<AUTO_TEST_PYTHON> tools/export_dependency_lock.py --check` |
| 启动检查 | `<AUTO_TEST_PYTHON> launcher.py --check` |
| 配置校验 | `<AUTO_TEST_PYTHON> launcher.py --validate-config` |
| 发布清单 | `<AUTO_TEST_PYTHON> release_manifest.py` |

- 编译检查使用 `tools/compile_check.py`（内存编译，不写 `__pycache__`），不使用
  `python -m compileall`。
- `release_manifest.py` 的 `verification` 段直接写入上述命令，并额外记录
  `python_requirement`、`interpreter` 与 `dependencies.lock_sha256`，使发布验证绑定
  **同一解释器、同一份依赖锁定结果和同一套核对命令**。
- `launcher.py --help`、`README.md` 与本文使用同一批命令，不允许各自维护裸 `python` 命令。
- `--validate-config` 的边界是“用项目解释器只读校验配置内容”：它校验解释器路径和 3.11
  系列，但不检查依赖包、不校验 Conda 环境名，因此不能替代 `--check`。

## 4. DPD 隔离

- 主系统启动与三类测量不导入 `DPD_auto_test` 代码。
- `TensorFlow`、`Jupyter`、`SciPy`、`nptdms` 等 DPD 依赖只在 `requirements-dpd.txt`，
  不进入 `requirements.txt` 与 `requirements.lock.txt`。
- DPD 环境使用自己的锁文件 `requirements-dpd.lock.txt`（在该环境中 `pip freeze` 生成），
  不得与本项目的锁文件合并。

## 5. 验收核对

1. 新机器按本文 2.1 的顺序完成安装后，`tools/export_dependency_lock.py --check` 与
   `launcher.py --check` 均返回 `0`，且后者输出“依赖版本与 requirements.lock.txt 一致
   （含传递依赖）”。
2. 全量 `unittest`、`tools/compile_check.py`、`--check`、`--validate-config` 全部通过。
3. 生成一次 `release_manifest.json`，确认 `verification` 中没有裸 `python`、
   包含 `dependency_lock` 命令，`dependencies.lock_sha256` 与仓库内锁文件一致。
4. 主系统环境未安装 TensorFlow / Jupyter 仍可启动并完成离线仿真测量。
