# 兼容层弃用与删除发布说明

本文是 [测试运行目录与配置结果解耦重构指南](测试运行目录与配置结果解耦重构指南.md) **步骤 E**
的产出：把步骤 A 至 D 的调用方清单固化为可执行的删除条件，并记录不兼容变更、迁移方式、
目标版本和回滚/查看方案。

## 1. 结论速览

| 项目 | 结论 |
| --- | --- |
| 拟定目标版本 | 弃用接口删除目标 **v1.1**；旧结果写入类接口目标 **v1.2**（原因见 3.3）。这两个版本是迁移计划目标，不代表当前已发布版本。 |
| 当前状态 | 删除条件已确定并固化为门禁测试；**兼容层尚未删除** |
| 证据形式 | 仓库内生产调用方清单由 `tests/test_compatibility_deletion_conditions.py` 逐接口断言；清单区分正式流程调用和旧兼容调用 |
| 适用范围 | 结论限定为仓库内生产代码。外部脚本依赖无法由静态搜索证明，按全局条件 2 单独确认 |

全局删除前置条件（四类接口都适用，缺一不可）：

1. **仓库内调用方清单已清空或只剩已批准的兼容调用**：
   `tests/test_compatibility_deletion_conditions.py` 固定各接口当前生产调用文件集合，新增
   调用方立即失败；删除前必须迁移正式运行调用，并明确处理清单中剩余的兼容调用。当前
   `save_compatibility_copy()` 仍由正式测量用例调用，因此清单测试通过不代表已达到删除条件。
2. **外部调用方迁移确认**：由发布负责人建立并归档调用方清单，逐个取得脚本所有者的
   迁移确认，或确认该调用方已退役。`DeprecationWarning` 默认可能被 Python 过滤，不能
   用“一个周期没有看到告警”代替确认；当前尚无外部调用方登记。
3. **步骤 F 现场验收归档**：按
   [重构收尾与真实HardwareSmoke验收.md](重构收尾与真实HardwareSmoke验收.md) 完成真实
   Hardware Smoke。删除前必须保证现场有一份可回滚的已验证版本。
4. **回滚/查看方案已验证**：历史结果仍可只读查看与导出（见各接口“回滚与查看”）。

未同时满足以上条件的接口**继续保留**，并在第 4 节记录保留原因。当前调用方清单不是
“零生产调用方”证明，而是删除决策基线；删除时必须重新验证清单为空或残余调用已迁出。

| 旧兼容测量根入口（`cable_loss_measurement.py`、`driver_power_mapping.py`、`app/legacy_amplifier_measurement.py` 等） | 外部脚本旧入口 | `app.gui_runtime.create_*_measurement()` | v1.2 批次评估（本次保留，见 3.5） |

## 3. 各接口删除条件

### 3.1 `latest_path()` / `latest_compatibility_path()`

拟定删除目标版本：**v1.1**（以实际发布计划批准为准）。

- 端口声明：`application/ports/result_repository.py:39`
- 实现：`infrastructure/persistence/result_repository.py:106`（`latest_path`，带
  `DeprecationWarning`）、`:115`（`latest_compatibility_path`，仅服务该弃用链）
- 生产调用方证据：**仅兼容层调用** `application/inputs/legacy_result_input_reader.py:44`。
  间接链路只有 `LegacyResultInputReader.latest_legacy_driver_mapping_path() ->
  repository.latest_path("driver_power_mapping")`，即兼容读取器自身。
- 删除条件：
  1. 3.2 的无路径映射读取先删除（`latest_path()` 的唯一调用方就在其中）。
  2. 删除端口声明、实现和 `latest_compatibility_path()`；同步把
     `tests/test_result_repository.py` 中的
     `test_legacy_paths_and_latest_path_are_resolved_by_repository`、
     `test_latest_path_reports_missing_timestamped_result`、
     `test_latest_compatibility_path_only_serves_legacy_compatibility_calls`、
     `test_result_input_port_marks_latest_path_as_compatibility_only` 改为只读历史端口断言。
  3. 满足全局条件 2 至 4。
- 迁移方式：正式阶段输入使用
  `RunStageRecorder(run_repository, run_id).verified_result_path(STAGE_*)`；
  历史浏览使用
  `FileResultHistoryRepository.latest_result_id(result_type)` 或
  `ResultQueryAdapter.latest_legacy_result(result_type)`。
- 回滚与查看：历史 JSON 文件不做任何删除或改写，只读历史端口和 GUI 历史页面仍可
  查看/导出；回滚到删除前的发布版本即可恢复旧接口。

### 3.2 无路径驱动映射读取（`LegacyResultInputReader`）

拟定删除目标版本：**v1.1**（以实际发布计划批准为准）。

- 端口：`application/ports/legacy_result_input_reader.py:17,20`
- 实现：`application/inputs/legacy_result_input_reader.py:27-49`
  （`read_legacy_cable_loss()`、`latest_legacy_driver_mapping_path()`、
  `read_latest_legacy_driver_mapping()`，全部发出 `DeprecationWarning`）
- 生产调用方证据（均为旧兼容分支，不是正式运行调用方）：
  - `application/measurements/driver_mapping.py:130-140`（`stage_recorder is None` 的旧兼容分支）
  - `application/measurements/amplifier_test.py:168`、`:206-227`（旧兼容分支）
  - `app/gui_runtime.py:354-362` 的 `_input_reader_for()`：只有旧兼容快照才注入该读取器
- 删除条件：
  1. 删除 `_input_reader_for()` 的旧兼容分支（依赖 3.4 的兼容快照删除）。
  2. 删除 `DriverPowerMappingUseCase` 与 `AmplifierMeasurementUseCase` 中
     `stage_recorder is None` 的旧兼容输入分支及其 `isinstance(..., LegacyResultInputReader)`
     保护。
  3. 删除端口、实现和 `application/inputs/__init__.py`、`application/ports/__init__.py`
     再导出；同步迁移 `tests/test_result_input_reader.py::LegacyResultInputReaderTests`
     与 `tests/test_result_reading_compatibility.py` 的期望。
  4. 满足全局条件 2 至 4。
- 迁移方式：调用方必须显式提供 `loss_data_path` / `driver_mapping_path`
  （`ResultInputReader.read_cable_loss(path)` / `read_driver_mapping(path)`），
  或在运行契约下由当前运行 manifest 提供路径。
- 回滚与查看：兼容副本文件仍存在，可通过 GUI 历史浏览/导出或在历史目录中只读检查；
  新运行输入无法回退到“最新结果”。CLI 的运行列表/manifest 检查不是历史结果浏览器。

### 3.3 旧结果写入（全局兼容副本与旧运行快照）

拟定删除目标版本：**v1.2**（依赖历史浏览迁移，且以实际发布计划批准为准）。

- `save_compatibility_copy()`：端口 `application/ports/result_repository.py:56`，
  实现 `infrastructure/persistence/result_repository.py:67`
- `write_legacy_run_snapshot()`：`infrastructure/persistence/json_result_repository.py:181`，
  兼容再导出 `result_storage.py:62`
- `create_legacy_run_snapshot()`：端口 `application/ports/result_repository.py:31`，
  实现 `infrastructure/persistence/result_repository.py:85`
- 生产调用方证据（区分权威运行结果和兼容副本）：
  - `save_compatibility_copy()`：`application/measurements/cable_loss.py:247`、
    `driver_mapping.py:230`、`amplifier_test.py:335`（权威结果先写入运行目录并登记 manifest，
    但正式流程仍写兼容副本，因此不是零生产调用方）
  - 仓储 `save()` 的兼容副本写入：`application/measurements/cable_loss.py:217`、
    `driver_mapping.py:200`、`amplifier_test.py:304`（三个用例的旧兼容分支），以及
    `cable_loss_measurement.py:166`、`driver_power_mapping.py:150`、
    `app/legacy_amplifier_measurement.py:145`（三个旧入口的仓储分支，另一分支
    `cable_loss_measurement.py:157` 直接调用 `save_measurement_result()`）。这些调用最终进入
    `json_result_repository.save_measurement_result()`，同时写运行归档和全局旧路径。
  - `write_legacy_run_snapshot()`：`cable_loss_measurement.py:43`、
    `driver_power_mapping.py:42`、`app/legacy_amplifier_measurement.py:63`
  - `create_legacy_run_snapshot()`：**零生产调用方**
- 删除条件（比其他接口更严格）：
  1. **历史浏览必须先脱离全局副本目录**。当前 `FileResultHistoryRepository` 只读
     `test_results` 下由 `HISTORY_RESULT_TYPES` 定义的固定文件和时间戳历史 JSON；一旦停止写入兼容副本，新运行结果将不再出现在
     历史列表里。删除前必须提供基于 `runs/<run_id>/manifest` 的只读历史视图，并完成
     旧数据迁移说明。该迁移任务尚未立项，因此本组接口**目标版本为 v1.2**。
  2. 迁移三个正式用例中的 `_write_compatibility_copy()` 并删除对
     `save_compatibility_copy()` 的调用；同时删除三个旧用例的 `result_repository.save()`
     全局副本路径，或把它改为明确独立的历史导入/导出操作，不能继续作为测量隐式副作用。
  3. 旧兼容测量根入口删除或改为显式路径（见 3.5）。
  4. 同步删除 `tests/test_result_repository.py::test_save_compatibility_copy_writes_only_the_global_copy`、
     `tests/test_history_result_isolation.py` 中依赖兼容副本的用例，并保留“运行目录结果
     不依赖兼容副本”的断言。
  5. 满足全局条件 2 至 4。
- 迁移方式：权威结果只写当前运行 manifest 登记的阶段结果（线损/驱动映射使用
  `inputs/<stage>.json`，主功放结果位于运行目录 `results/`）；全局旧文件仅作为历史只读
  数据保留，不再产生新的兼容副本。
- 回滚与查看：删除后历史数据保持不变（只读），通过历史端口或运行目录 manifest 视图
  查看/导出；回滚到 v1.1 发布版本可恢复兼容副本写入。
- 当前决定：**保留**。原因：条件 1、条件 2 均未满足——正式测量用例仍主动写兼容副本，
  历史浏览仍只依赖全局兼容副本；`release_manifest.py` 也把相关根入口登记为回滚/兼容文件。

### 3.4 旧 GUI 测量入口（兼容快照与查询别名）

拟定删除目标版本：**v1.1**（以实际发布计划批准为准）。

- `prepare_configuration(..., run_contract=False)` 兼容快照分支：
  `app/gui_runtime.py:111`（默认值）、`:148-189`（旧分支）
- GUI worker 的 `prepare_factory` 后备分支：`presentation/qt/workers.py:183-188`、
  `:264-273`、`:319-325`
- GUI 历史查询别名：`infrastructure/gui_data_service.py:94-102`（`latest()`）与
  `application/ports/gui_data_service.py:46-54`（`LegacyResultQueryPort`）
- 生产调用方证据：
  - 生产代码只有 `presentation/qt/main_window.py:1051` 调用 `prepare_configuration`，
    且显式传入 `run_contract=True`；仓库内**没有任何**显式 `run_contract=False`。
  - `prepare_factory` 在生产代码中从未被注入，只有 `presentation/qt/workers.py`
    自身持有该属性；仅测试通过它构造迁移/停止时序用例。
  - `ResultQueryAdapter.latest()` 与 `LegacyResultQueryPort` 无生产调用：GUI 历史页面
    使用 `latest_legacy_result()`（`presentation/qt/main_window.py:334`、`:1265`）。
- 删除条件：
  1. `prepare_configuration()` 取消 `run_contract=False` 分支，改为只接受运行契约
     （保留 `create_prepared_run` 与 `load_prepared_run` 两个入口）。
  2. 删除三个 worker 的 `prepare_factory` 参数与后备分支，缺失 `PreparedRun` 时只保留
     “先创建或按 `run_id` 重新加载运行”的失败路径。
  3. 删除 `ResultQueryAdapter.latest()` 与 `LegacyResultQueryPort`，并把
     `tests/test_visualization_export.py::test_latest_legacy_result_is_a_non_deprecated_browsing_api`
     更新为只断言历史端口。
  4. 满足全局条件 2 至 4（尤其要确认没有外部脚本直接调用旧 GUI 组装函数）。
- 迁移方式：配置阶段用 `prepare_configuration(..., run_contract=True)`（GUI 已如此），
  或离线调用 `create_prepared_run()` / `load_prepared_run(run_id)`；测量阶段把
  `PreparedRun` 传给 `create_*_measurement(prepared_run=...)`；历史浏览统一使用
  `latest_legacy_result()` 或只读历史端口。
- 回滚与查看：v1.0 兼容流程保存在 `release_manifest.py` 的 `rollback_files` 中，
  必要时回滚发布版本；历史结果只读查看不受影响。

### 3.5 旧兼容测量根入口（本次保留）

涉及模块：`cable_loss_measurement.py`、`driver_power_mapping.py`、
`app/legacy_amplifier_measurement.py`、`amplifier_measurement.py`（转发）、
`result_storage.py`、`measurement_services.py`、`measurement_lifecycle.py`，
以及 `config_io.py` / `config_models.py` / `config_validation.py` 等配置再导出。

保留原因：

1. `release_manifest.py` 将 `cable_loss_measurement.py`、`driver_power_mapping.py`、
   `amplifier_measurement.py` 登记为 `ROLLBACK_FILES`，并将 `result_storage.py`、
   `measurement_services.py`、`measurement_lifecycle.py` 及配置再导出模块登记为
   `COMPATIBILITY_FILES`。`app/legacy_amplifier_measurement.py` 未单独列入清单，仍需在
   外部迁移台账中单独确认。
2. 外部脚本对这些模块的依赖无法由静态仓库搜索确认（步骤 A 已记录该限制）。
3. 步骤 F 的真实现场验收（含重新连接与回滚判定）尚未完成归档。

解除条件：兼容调用清单清空、全局条件 2 至 4 全部满足后，在 v1.2 批次统一评估删除，并同步更新
`release_manifest.py` 的文件清单与本说明第 2 节。

## 5. 证据与验证

```powershell
./run_tests.ps1
& $env:AUTO_TEST_PYTHON -m unittest tests.test_compatibility_deletion_conditions -v
& $env:AUTO_TEST_PYTHON launcher.py --check
& $env:AUTO_TEST_PYTHON launcher.py --validate-config
```

2026-10-23 审查复验结果：`Ran 1016 tests ... OK (skipped=8)`；门禁文件 12 个用例全绿；
`--check` 依赖检查通过；`--validate-config` 配置校验通过。

机器化证据（`tests/test_compatibility_deletion_conditions.py`，共 12 个用例）：

1. 逐接口断言生产代码中的调用文件集合等于本文记录；新增调用方立即失败。
2. 断言仓储 `save()` 的兼容副本写入只出现在三个用例旧分支和三个旧入口这六个文件内。
3. 断言生产代码中不存在显式 `run_contract=False`，且唯一的
   `prepare_configuration` 调用点传入 `run_contract=True`。
4. 断言 `prepare_factory` 只作为 worker 自身属性出现，生产代码不注入。
5. 断言 `ResultQueryAdapter.latest()` 无生产调用、`LegacyResultQueryPort` 无生产导入。
6. 断言本文 3.1 至 3.4 每一节都写了删除条件、迁移方式、回滚与查看和目标版本，且指南
   记录了步骤 E 并链接本文。
