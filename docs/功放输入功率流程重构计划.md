# 功放输入功率流程重构计划

## 目标与范围

把测试方案中的功率扫描范围从“信号源输出功率”改为“主功放输入功率”。无驱动时根据线损直接反算信号源设定；有驱动时先测量驱放映射，再按目标主功放输入功率反查信号源设定。每个步骤控制在一个局部契约或一段流程内，完成后都可以独立验证。

本计划覆盖配置模型、驱动映射阶段、主功放测量阶段、结果契约、UI 展示和测试。硬件真实设备冒烟不属于常规验证，除非用户另行授权。

## 已确认的技术决定

1. 配置页的起始/结束功率统一表示主功放输入功率；功率步长表示目标输入功率网格间隔。
2. DUT 最大输入限制与扫描结束功率共同限制映射上限，取较小值。限制点若不在步进网格上，则作为额外的最后目标点加入；不得超过限制。
3. 驱动功放预估增益是测试配置中的单一全局值，不按频率分别配置。
4. 驱动映射的初始信号源输出功率为“最低目标输入功率 - 预估增益 - 10 dB 安全余量”。安全余量是相对功率差，单位为 dB。
5. 映射上推采用自适应策略：根据测量输出与目标的误差更新源功率，接近目标时缩小步长，必要时在已测区间内二分逼近；每个目标点要求独立实测输出落在 ±0.2 dB 内，不复用同一读数满足多个目标。
6. 源功率有效范围沿用配置控件范围 -50～20 dBm。源功率超界或无法覆盖最大目标时，映射失败，不生成可供正式测试使用的完整映射。
7. 驱动映射结果同时保留原始实测点和目标网格插值结果。原始点用于追溯；插值曲线用于正式测量，不把容差内实测输出直接冒充目标功率。
8. 插值关系基于实测的“信号源输出功率 -> 驱放补偿后输出功率”曲线反解。增益压缩导致斜率变小可以接受；输出随源功率增加而下降的非单调区段不能用于反查，应报错。
9. 无驱动时采用 `信号源输出功率 = 目标主功放输入功率 + cable1损耗`，与现有 DUT 输入计算公式互为反算。
10. 正式功放测试按目标输入功率网格执行。驱动模式下，`input_power_dut` 使用驱放映射阶段实测曲线插值所得的驱放输出功率；该阶段已测得驱放增益/输出，不在主功放测试时重复测量驱放。信号源设定功率由反查映射得到。
11. 现有结果中的 `sg_power` 和 `input_power_dut` 继续保留其测量含义；驱动映射结果另存目标输入、插值源功率及原始测量，供审计和追溯。

## 分阶段步骤

### 阶段一：冻结新功率语义

#### 步骤 1：建立目标功率网格计算

- **范围**：仅在应用/领域计算边界新增一个纯计算入口，生成正式测试目标输入功率序列。
- **执行策略**：输入起始功率、结束功率、步长和 DUT 最大输入限制；按步长生成不越界的目标点，取扫描结束与 DUT 限制的较小值作为上限，若上限不在网格上则补入该上限。
- **技术决定**：起始功率大于有效上限时明确拒绝配置；浮点端点采用现有 `PowerSweep.points()` 的容差策略，避免重复点或因浮点误差越过限制。
- **验证**：新增纯计算测试，覆盖整步/非整步上限、最大限制低于结束功率、限制点补入、起始点越限和浮点边界。

#### 步骤 2：把配置 DTO 字段语义改为主功放输入功率

- **范围**：正式输入 DTO、配置草稿、配置读取/写出及领域校验，不改仪器动作。
- **执行策略**：保留现有配置字段结构，先通过文档和 UI 标签明确其语义变化，再将正式输入对象中的扫描字段命名/说明调整为 DUT 输入功率；增加全局驱动增益预估字段，并贯通解析、校验、冻结方案及回填。
- **技术决定**：增益以 dB 表达，非有限数值拒绝；起止功率仍为 dBm、步长为 dB。对旧配置不根据历史数值猜测或自动换算，避免无法判定旧功率范围是源功率还是 DUT 输入功率；加载时提供可识别的兼容/迁移提示，并在新配置保存后写入新语义。
- **验证**：配置草稿、正式方案构造、校验、作者写入/投影回填测试；检查旧配置读取行为和错误提示。

#### 步骤 3：更新配置 UI 的功率字段

- **范围**：Qt 配置页、表单适配器、配置投影/状态层及相应 UI 测试。
- **执行策略**：将起止功率文案改为“主功放输入功率”，新增“驱动功放预估增益 (dB)”字段；仅在启用驱动模式时显示或启用预估增益控件。功率范围继续为 -50～20 dBm，步长范围沿用现有设置。
- **技术决定**：UI 不承担功率反算或增益业务计算；增益字段由配置 DTO 校验。隐藏/禁用时保留已填写的值，但驱动关闭时不将其作为运行必填项。
- **验证**：按仓库规则运行纯 UI 层测试 `tools/run_tests.py --layer ui`，涵盖控件创建、配置回填、读取写出、驱动启停联动。

### 阶段二：重构驱动映射

#### 步骤 4：定义双层驱动映射结果契约

- **范围**：驱动映射结果 DTO、序列化/反序列化和输入读取校验。
- **执行策略**：为原始映射点和目标网格映射分别定义清晰字段；原始点至少记录源功率、补偿后的驱放输出功率及增益，目标表记录目标 DUT 输入功率、插值源功率和插值输出功率。为新结构增加明确的 schema 版本。
- **技术决定**：正式测试只消费目标网格映射及其可验证的插值数据；原始数据是映射审计依据。禁止把旧 `输入 -> 输出` 字典静默解释为新 `目标输入 -> 源输出` 数据。
- **验证**：DTO 合法/非法结构、字段缺失、非有限数值、未知版本和旧格式拒绝/兼容提示测试。

#### 步骤 5：实现驱放曲线校验和反向插值

- **范围**：领域测量值对象/计算模块的驱放曲线处理，不含仪器扫描。
- **执行策略**：将原始点按源功率排序；验证源功率唯一、输出随源功率严格递增或在定义的数值容差内递增；利用分段线性插值，将每个目标 DUT 输入功率反解为源功率，并同时计算该插值点的驱放输出功率。
- **技术决定**：增益压缩只改变输出曲线斜率，不要求恒定增益；目标输入位于原始映射覆盖范围之外时禁止外推。重复输出或非单调点不允许通过排序掩盖，必须给出具体频率/区间错误。
- **验证**：恒定增益、斜率下降的压缩曲线、目标恰好命中实测点、两点间插值、范围外目标、重复/下降输出和浮点近似单调测试。

#### 步骤 6：重写驱动映射扫描的起点与上推算法

- **范围**：`DriverPowerMappingService` 的频点扫描算法及其服务单元测试。
- **执行策略**：每个频点从“最小目标输入 - 预估增益 - 10 dB”起步，测量驱放补偿输出；按当前误差自适应调整源功率，接近目标时收缩步长，对目标两侧已形成的区间做二分逼近。为每个目标点独立找一个 ±0.2 dB 内的命中读数，命中后继续处理下一目标。
- **技术决定**：源功率不得超出 -50～20 dBm；命中读数不重复分配给另一个目标；每个目标有明确的迭代/测量上限，防止测量无法收敛时无限循环。达到上限、无有效进展或源功率到界仍未覆盖目标时失败，不产出完整映射。
- **验证**：使用可控假仪器模拟线性增益、压缩曲线、目标已命中、容差边界、目标间隔小于容差、源功率越界、不可达目标及取消/清理。

#### 步骤 7：在映射完成时生成并保存目标网格表

- **范围**：映射服务的完成路径、事件/结果 DTO 转换和运行目录正式输入写入。
- **执行策略**：完成所有目标实测锚点后，先验证完整覆盖与单调性，再对每个正式测试目标生成插值源功率和对应驱放输出功率；保存原始实测点及规整后的目标表。部分取消结果只保存已经完整完成的频点，不作为正式测试输入。
- **技术决定**：目标表的主键是目标主功放输入功率；实际容差偏差只存在于锚点记录，不改写目标键或插值结果。目标表必须覆盖步骤 1 生成的全部目标点。
- **验证**：更新 `DriverPowerMappingUseCase`、运行阶段输入持久化、取消部分结果和结果 DTO 测试；检查新输入能被正式输入读取器验证。

### 阶段三：改造主功放正式测试

#### 步骤 8：实现无驱动信号源功率反算

- **范围**：无驱动模式下的纯计算路径和主功放服务单元测试。
- **执行策略**：对每个目标输入点查频率对应的 cable1 损耗，计算信号源输出设定，并在硬件动作前验证源功率处于 -50～20 dBm。
- **技术决定**：正式扫描循环的横向目标始终是 DUT 输入目标值；无驱动模式不创建或读取驱放映射。保护限制已由目标网格生成器应用，测得输出和效率等计算流程不变。
- **验证**：按频率验证不同 cable1、源功率上下界、超界前置失败及目标点数量/顺序。

#### 步骤 9：实现有驱动映射反查和输入功率记录

- **范围**：主功放测量服务的驱动模式扫描路径。
- **执行策略**：对每个目标输入点，在目标映射表中查源功率和插值驱放输出；以该源功率设置仪器，以插值驱放输出作为 `input_power_dut`，再计算主功放增益、效率和压缩指标。
- **技术决定**：不在主功放阶段再次测量驱放；`sg_power` 保存实际设置的信号源输出，`input_power_dut` 保存映射曲线插值得到的驱放输出。驱动表缺点、目标表不完整或源功率越界时，在连接/硬件动作前失败。
- **验证**：验证多频点独立查询、压缩曲线反查、每点一一对应、保护限制、输入功率和信号源功率结果列，以及缺失/过期映射的前置拒绝。

#### 步骤 10：同步主功放实时展示和历史结果语义

- **范围**：主功放事件数据、实时曲线、历史页/报告中与输入功率相关的标签及适配。
- **执行策略**：确保横轴使用实际采用的 `input_power_dut`；显示或保留 `sg_power` 作为信号源设定列。历史记录查看不能把 `sg_power` 当成测试目标输入。
- **技术决定**：既有结果文件继续按原字段读取；新结果仍使用相同字段名，但明确 `input_power_dut` 是实际测试采用的 DUT 输入功率（无驱动按线损计算，有驱动按映射插值）。驱动映射的新 schema 版本单独区分，不混淆旧映射。
- **验证**：实时数据、结果 DTO、历史图表和报告测试，确认输入功率与信号源功率不会互换。

### 阶段四：集成验证与收尾

#### 步骤 11：更新运行配置和校准输入前置校验

- **范围**：配置验证、运行准备、主功放输入预检和当前运行目录驱动映射读取。
- **执行策略**：把增益预估必填条件限制在驱动模式；校验目标扫描范围、DUT 限制、源功率范围和映射目标网格完整性。保证任何不完整/旧格式映射都在执行硬件动作之前被拒绝。
- **技术决定**：本次运行仍只使用当前运行目录登记的线损和驱动映射；不回退读取全局“最新结果”。无驱动运行跳过映射阶段，且不要求驱动增益预估。
- **验证**：运行配置校验、预检和阶段契约测试；断言所有错误在仪器测量/输出动作发生前触发。

#### 步骤 12：做端到端离线回归与迁移说明

- **范围**：测试文档、默认配置/模板、集成测试和用户可见提示。
- **执行策略**：更新示例配置和人工验收步骤；使用假仪器覆盖无驱动与有驱动完整流程，检查配置保存、线损消费、映射输入写入、主功放扫描、结果归档和历史展示。
- **技术决定**：不自动把旧信号源功率范围换算成新 DUT 输入范围；旧映射文件不能用于新正式流程。提示用户按新语义确认并保存配置、重新执行本次运行的驱动映射。
- **验证**：按变更面运行仓库测试 runner。跨 DTO/应用服务/基础设施改动时运行全量离线测试：`& "D:\Anaconda\envs\Auto_test\python.exe" tools/run_tests.py`；同时执行 `launcher.py --check` 与 `launcher.py --validate-config`。不运行硬件层测试，除非操作者明确授权并满足硬件门禁。

## 执行顺序与阶段门

按步骤 1 至 12 顺序推进。阶段一完成后，配置和目标网格语义固定；阶段二完成后，映射结果可以独立生成并验证；阶段三完成后，主功放两种模式都按目标输入功率运行；阶段四通过后，重构才可交付。每一步只合并其标明的局部职责，若步骤中的契约测试未通过，不开始依赖它的后续步骤。
