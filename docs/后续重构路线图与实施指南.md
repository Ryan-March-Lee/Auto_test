### 任务 2：迁移一个历史测量入口

依次处理 `amplifier_measurement.py`、`cable_loss_measurement.py`、`driver_power_mapping.py`，一次只处理一个。

1. 对照对应的 `application/measurements/` 用例，列出旧入口仍独有的行为。
2. 将仓库内一个调用方迁移到正式用例或装配 API，并更新其测试与 patch 路径。
3. 确认该调用方行为测试和资源清理测试通过，再迁移下一个调用方。
4. 所有内部调用迁出后，按兼容条件决定保留薄转发还是删除旧入口。

完成条件：正式实现只有一份；旧入口没有业务实现；需要保留的公开 API 有兼容测试；完整离线验收通过。

### 任务 3：收口历史测量服务与生命周期模块

1. 盘点 `measurement_services.py` 与 `measurement_lifecycle.py` 的公开符号，分别归属到 application 用例/lifecycle 或 `instrument/flow`。
2. 一次迁移一个职责，保持普通停止、取消、紧急停止及清理失败的差异明确。
3. 为迁移后的正式 API 增加测试；兼容测试只验证旧 API 转发，不再验证第二套实现。

完成条件：生产代码不依赖旧实现；资源所有权和清理路径有回归测试；若保留根入口，其内容仅为明确的兼容转发。

### 任务 4：收口 `instrument_control.py`

1. 将旧模块公开符号逐项映射到 `instrument/session.py`、`instrument/safety.py`、`instrument/power_control.py`、`instrument/flow/`、driver 或 transport。
2. 先迁移不触发设备动作的导入与仿真调用，再逐项迁移设备控制调用。
3. 验证 RF 关闭、电源 `Drain -> Gate` 关闭、VISA 资源释放和外部注入资源所有权。
4. 所有内部调用迁出并确认外部兼容要求后，才将根模块改为薄转发或删除。

完成条件：离线安全/仿真测试和架构门禁通过。真实设备验证仅按独立现场验收文档执行，不以离线结果替代。

### 任务 5：迁移可视化与连接图

分别处理 `data_visualization.py` 和 `connection_diagrams.py`，不要合并成一次大迁移。

1. 对可视化模块，分清纯分析、结果读取和 Qt 展示职责；纯分析放 `analysis/`，结果读取走 application input，界面留在 `presentation/qt/`。
2. 对连接图模块，确认生成逻辑的归属并增加图内容/输出回归测试。
3. 每个模块迁移后检查页面没有直接读写结果文件，且正式调用不再依赖旧根模块。

完成条件：模块职责唯一、行为测试覆盖、旧入口符合兼容层规则、完整离线验收通过。

### 任务 6：清理其他兼容入口与阶段性测试

1. 根据任务 1 的盘点结果，逐个处理配置转换、GUI、助手根入口；每次只改一个入口。
2. 对名称含 `phase`、`refactor`、`acceptance` 的测试，先判断是否有长期行为价值。
3. 只有在等价行为或架构门禁已覆盖时才删除重复测试；保留唯一的安全、兼容和业务回归覆盖。
4. 每次删除兼容入口前，满足下方“兼容入口删除条件”。

完成条件：文档、脚本、发布清单与代码入口一致；保留的兼容入口有明确迁移目标；完整离线验收通过。

### 任务 7：真实 Hardware smoke 现场验收

此项需要现场负责人提供授权、设备信息和安全窗口。按《重构收尾与真实HardwareSmoke验收》依次执行基础连接与清理 smoke、线损、驱动功率映射、主功放测量，并归档脱敏报告、配置快照、设备身份、动作顺序、清理证据和回滚决定。

**没有现场授权不得执行真实 RF 或电源动作。**只有三类完整测量及安全清理证据齐全后，才能把现场验收标记为完成；该现场记录在完成并归档前不得删除。

## 兼容入口删除条件

删除单个旧模块前，必须全部满足：

- 生产调用方已迁移，测试不再把旧路径当正式 API 使用。
- 外部脚本已有替代入口，或相关负责人明确接受破坏性变更。
- 正式实现的行为和失败路径有测试覆盖。
- 文档、启动入口及发布清单已更新。
- 删除后完整离线验收通过。

若仍需兼容，根模块只保留显式符号转发，不得包含业务实现、文件读写、全局设备状态或隐式初始化。

## 已完成部分

以下内容已有代码、测试和实施记录。它们不是当前待办；除非后续发现回归，不要重复重做。

- **GUI 与运行时拆分：**页面、controller、worker factory 和 `MainWindow` 已按职责拆分；生命周期状态、停止/取消/紧急停止语义及资源所有权已有统一协议和回归测试。
- **配置、结果与路径边界：**配置领域模型、校验、仓储、旧格式转换，结果模型/读写/持久化和路径服务已迁入正式包；根目录对应模块按现状作为兼容入口处理。
- **GUI 数据访问：**配置、结果查询、导出和报告通过 application ports 与 DTO 访问，文件操作由 infrastructure 实现。
- **运行与交付契约：**启动器、测试脚本和 Hardware smoke 使用 `.env` 中的 `AUTO_TEST_PYTHON`；只读检查不初始化真实设备，Hardware smoke 有独立门禁。
- **设备安全基础：**已有 session、driver、transport、仿真及安全 flow；离线覆盖安全关闭与资源所有权。该记录不代表现场真实 Hardware smoke 已通过。

## 统一依赖规则与验收

- `presentation` 依赖 application API，不直接访问 VISA、SCPI、driver 或持久化实现。
- `application` 不依赖 Qt；`domain` 不依赖 infrastructure、Qt 或设备模块。
- `infrastructure` 实现 ports；`instrument` 承担设备会话、driver、transport、仿真和安全动作。
- 新生产代码使用正式包路径，不新增对根目录兼容模块的依赖。
- 每个迁移任务先跑对应测试；每个小批次完成后跑完整离线测试、应用检查、配置校验、编译检查和架构门禁。
- 项目命令使用 `.env` 指定且存在的 `AUTO_TEST_PYTHON`；禁止改用其他解释器代跑。
- 真实 Hardware smoke 始终是独立现场安全门禁，不属于普通离线验收。
