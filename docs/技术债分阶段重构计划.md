# 技术债分阶段重构计划

## 1. 当前结论

代码重构步骤 1–16 均已完成，分别有各步骤执行记录、自动化测试和配套文档作为证据。当前不能删除本计划：项目的真实 Hardware Smoke 与三类硬件测量尚未完成现场验收；验收记录仍为空模板，且明确要求先取得现场授权、设备信息和安全窗口。

本计划现只跟踪剩余现场验收和最终收尾。已完成的代码工作压缩为基线，不重复维护逐文件变更日志。详细历史与约束见[兼容层弃用与删除发布说明](兼容层弃用与删除发布说明.md)、[测试运行目录与配置结果解耦重构指南](测试运行目录与配置结果解耦重构指南.md)及[真实 Hardware Smoke 验收记录](重构收尾与真实HardwareSmoke验收.md)。现场操作以指南步骤 F 为唯一操作与判定口径。

## 2. 已完成基线

- 步骤 1–6：正式 API、运行目录结果、配置及结果 DTO 收敛；旧测量入口、配置转换和兼容结果读取/写入退役。
- 步骤 7–9：测量会话与安全清理端口、显式设备能力和仪器路由落地。
- 步骤 10–12：Qt 协调器、历史/导出/配置展示边界和迁移残留清理完成。
- 步骤 13–16：测量值对象、Python 3.11 与依赖锁、异常分类与静态质量门禁、剩余兼容转发清理完成。
- 最近记录的离线检查均通过；最终收尾时仍须按步骤 G 实际重跑并记录结果。项目解释器必须为 `D:\Anaconda\envs\Auto_test\python.exe`，真实硬件操作不得由离线检查替代。

## 3. 未完成执行步骤

每项独立记录证据；未满足前置条件时停止，不执行真实 RF 或电源动作。所有现场操作须由获授权人员按指南步骤 F 完成。

### 步骤 A：确认现场验收前置条件

**工作量：小；现场准备。**

- 取得现场授权、设备信息和安全时间窗口，确认正式拓扑、通道、上下电顺序、DUT 保护限值及停止/急停方案。
- 确认线损/驱动映射输入、配置版本、动作预算和本地证据存放位置；敏感现场资料不提交版本库。
- 依指南 F1 逐项核对 Hardware Smoke 门禁和正式运行契约。任一项未满足则记录阻塞项并暂停后续步骤。
- **完成证据：**验收记录填写前置条件与授权信息；不得在此步骤执行设备动作。

### 步骤 B：执行基础连接与清理 Smoke（F2）

**工作量：小；需现场授权。**

- 按指南 F2 验证设备身份、初始 RF/电源安全状态、最小安全动作、异常清理及 VISA 资源释放。
- 确认失败场景能安全停止；无合格空载电源或受检输出未关闭时按指南判失败，不继续测量。
- **完成证据：**记录脱敏设备身份、执行结果、清理状态和证据位置。

### 步骤 C：执行线损测量现场验收（F3）

**工作量：小；需现场授权。**

- 使用正式应用路径和新建 `run_id`，确认输入由当前运行 manifest 登记；执行正常完成并核对单位、结果范围、manifest 与归档。
- 分别验证普通停止、紧急停止、测量异常后的安全清理及重新连接；每类场景独立记录结果。
- **完成证据：**线损运行 ID、脱敏结果/配置证据、各终态清理与重连记录。

### 步骤 D：执行驱动功率映射现场验收（F4）

**工作量：小；需现场授权。**

- 使用正式应用路径和新建 `run_id`，核对驱动/DUT 通道、扫描顺序、外部供电条件及 manifest 输入；执行正常测量并核对结果归档。
- 分别验证普通停止、紧急停止、测量异常后的安全清理及重新连接；每类场景独立记录结果。
- **完成证据：**驱动映射运行 ID、脱敏结果/配置证据、各终态清理与重连记录。

### 步骤 E：执行主功放测量现场验收（F5）

**工作量：小；需现场授权。**

- 使用正式应用路径和新建 `run_id`，核对校准输入、单位、功率限制和 manifest 输入；执行正常测量并核对结果归档。
- 分别验证普通停止、紧急停止、测量异常后的安全清理及重新连接；每类场景独立记录结果。
- **完成证据：**主功放运行 ID、脱敏结果/配置证据、各终态清理与重连记录。

### 步骤 F：现场证据复核并归档

**工作量：小；现场负责人复核。**

- 按指南 F6 检查 F2–F5 证据齐全、无未解释失败，确认 RF 关闭、电源按 `Drain -> Gate` 关闭、VISA 资源释放及回滚决定。
- 将脱敏证据位置、失败处置、签字和日期填写到[验收记录](重构收尾与真实HardwareSmoke验收.md)。原始敏感资料仅本地保存。
- 条件未全部满足时不得标记归档；记录未完成项并回到相应步骤。

### 步骤 G：复跑离线门禁并更新结项文档

**工作量：小；归档后执行。**

- 先确认指定解释器存在，再按项目运行时契约执行全量测试、`launcher.py --check`、`launcher.py --validate-config`、编译检查、依赖锁核对及静态质量门禁；命令以 `docs/依赖与运行时契约.md` 和 `verification_commands()` 为准。
- 记录实际命令、日期和结果；任何失败先修复并重跑，不以历史测试数量代替本次结果。
- 同步验收记录、重构指南及发布说明的当前状态，确保结论一致。
- **完成证据：**现场 F 归档、全部离线检查通过、配套文档一致。满足后本计划可以删除。

## 4. 结束条件

只有步骤 A–G 均有证据、现场验收按指南正式归档，且代码、测试、发布清单和文档状态一致后，才删除本计划。离线测试或仿真通过不能替代现场验收；未获现场授权不得执行真实 RF 或电源动作。
