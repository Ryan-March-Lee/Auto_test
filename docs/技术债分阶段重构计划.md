# 技术债分阶段重构计划

## 1. 文档目的

本文将项目技术债审查结果转化为一组可独立执行、独立验证、工作量较小的重构步骤。

本计划采用**不考虑向后兼容**的技术决策：

- 不保留旧 Python 导入入口。
- 不保留旧配置格式的自动转换。
- 不保留全局结果兼容副本。
- 不保留旧测量类、旧快照和旧结果字段。
- 不为外部旧脚本增加迁移适配层；调用方必须直接迁移到正式 API。

每个步骤应形成独立提交。一个步骤只改变一个主要责任边界，完成后先执行本步骤验收，再进入下一步。

## 2. 当前基线

审查时的验证结果：

- 全量离线测试：`1109 tests, OK (skipped=3)`。
- `launcher.py --check`：通过。
- `launcher.py --validate-config`：通过。
- 编译检查：通过，命令为：

  ```powershell
  & "D:\Anaconda\envs\Auto_test\python.exe" tools\compile_check.py .
  ```

- 最大生产文件：`presentation/qt/main_window.py`，约 1740 行。
- 兼容层和旧入口由 `release_manifest.py`、`tests/test_compatibility_deletion_conditions.py` 持续维护。
- 正式测量仍会写全局兼容结果副本，旧测量根入口仍存在。

本计划不把“全量测试通过”视为架构已经收敛。每次删除兼容分支后，测试应同步删除旧行为断言，新增的测试只验证正式行为。

## 3. 目标架构

```text
Qt 页面 / CLI
    ↓ 只传递 DTO 和运行 ID
Application use case
    ↓ 依赖 application ports
Domain models / calculations
    ↑
Infrastructure repositories     Instrument session / safety ports
```

目标约束：

1. 所有测量必须绑定一个有效 `run_id`。
2. 配置只有一个正式 schema，结果只有一个正式 schema。
3. 正式结果只写入 `runs/<run_id>/`，由 manifest 登记和校验。
4. application 层不导入具体硬件 flow、VISA、Qt 或文件系统实现。
5. 硬件动作必须经由统一 session 和安全清理流程。
6. 展示层只能消费 DTO、事件和只读历史端口。

## 4. 执行规则

### 4.1 每步提交边界

- 每一步只处理一个主要主题。
- 每一步完成后运行该步骤列出的定向测试。
- 每个阶段结束后运行一次全量离线测试。
- 删除代码时同步删除只服务于该代码的测试、文档和发布清单条目。
- 不在重构提交中混入测量公式变更、UI 视觉改版或真实硬件操作。

### 4.2 统一验证命令

所有命令使用项目规定的解释器：

```powershell
& "D:\Anaconda\envs\Auto_test\python.exe" -m unittest discover -s tests -v
& "D:\Anaconda\envs\Auto_test\python.exe" launcher.py --check
& "D:\Anaconda\envs\Auto_test\python.exe" launcher.py --validate-config
```

真实设备验收仍必须遵守 `docs/重构收尾与真实HardwareSmoke验收.md`，离线测试不能代替现场验收。

## 阶段一：冻结正式边界

目标：先把唯一正式 API 和唯一结果路径固定下来，再删除兼容实现。此阶段不改变测量算法。

### 步骤 1：建立正式 API 目录清单

**工作量：小。**

**范围：**

- `application/`
- `domain/`
- `infrastructure/`
- `instrument/`
- `presentation/qt/`
- `app/`（装配层，一并纳入导入门禁）
- `launcher.py`

**执行策略：**

1. 列出正式允许的导入路径、入口函数和 DTO。
2. 在架构测试中把正式路径清单固化为断言。
3. 先不删除旧文件，只禁止新代码继续导入旧路径。

**技术决定：**

- 正式配置入口为 `domain.configuration` 和 `infrastructure.config`。
- 正式结果仓储入口为 `application.ports.result_repository` 和其基础设施实现。
- 正式测量入口为 `application.measurements` / `application.run_service`。
- 旧根目录模块不再视为公共 API。

**验收：**

- 静态架构测试能发现新增的旧模块导入。
- 正式 production code 不新增根目录兼容模块引用。

**执行状态：已完成（2026-10-26）。**

- 清单文档：`docs/正式API目录清单.md`，区分正式公共 API（48 个模块路径、160 个公开名称）、
  正式内部模块（32 个路径）和旧模块（28 个条目）。
- 静态门禁：`tests/test_public_api_inventory.py`，冻结顶层包、包内模块路径、公开名称、旧模块
  状态和存量引用基线；覆盖静态导入、`from 包 import 模块`、星号导入、常量动态导入和动态导入

3. 仓储 `save()` 只返回运行目录中的权威结果路径。
4. 将结果文件路径登记到当前运行 manifest。

**技术决定：**

- 不再同时写 `test_results/<固定文件名>` 或时间戳兼容文件。
- 兼容副本写入失败不再被视为可忽略问题，因为该功能直接删除。
- 历史浏览只读取运行目录 manifest。

**验收：**

- 三类正式测量每次只产生一个权威结果文件。
- 结果文件不再出现在全局兼容目录。
- manifest 中的结果路径、哈希和运行 ID 一致。

**执行状态：已完成（2026-10-26）。**

- 三个正式用例删除 `_write_compatibility_copy()` 调用与失败告警分支；仓储 `save()` 只返回
  运行目录内的权威路径，`SavedMeasurementResult` 不再暴露 `legacy_copy_path`。

  继续与运行目录一致。
- 旧入口边界：三个旧测量根入口属步骤 4 范围，本步骤不改变其兼容行为；它们改为**显式**
  调用 `save_compatibility_copy()` / `write_compatibility_copy()`，不再依赖仓储 `save()` 的
  隐式副作用；旧运行快照写入仍留待后续步骤。

  仍读取该历史字段，留待步骤 6 删除；门禁只允许它出现在该文件。（步骤 6 已删除该读取，
  见下文步骤 6 执行状态。）

  正式流程零调用；兼容调用被门禁冻结在三个旧入口与仓储适配器内，接口在步骤 3 已删除。

- 仓储只提供 `save/load/register/verify` 等正式运行目录能力。

**验收：**

- 生产代码中不存在 `legacy_path`、`save_compatibility_copy`、`create_legacy_run_snapshot`。

  `RuntimeError`，不读取配置、不连接仪器、不创建运行目录或写结果；文件本体仍留待
  步骤 4 退役。
