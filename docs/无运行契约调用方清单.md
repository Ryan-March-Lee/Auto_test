# 无运行契约调用方清单

本文是[《技术债分阶段重构计划》](技术债分阶段重构计划.md)步骤 4（盘点无运行契约调用方）的产出：
把生产调用点、仅测试调用点，以及底层为“无运行契约对象”保留的分支逐项固定下来，作为步骤 5
（测量装配入口收敛为 `PreparedRun`）与步骤 6（删除无运行契约的前置校验分支）的输入。

> 说明：本文的“步骤 4”指技术债分阶段重构计划的步骤 4。`docs/正式API目录清单.md` 中出现的
> “步骤 4”属于更早一次兼容层退役计划（退役三类旧测量根入口），两者不是同一步骤。

本文只做盘点，**不改变现有行为**：清单里的无契约分支在本步骤保持原样，全部按归属步骤迁移或删除。
可执行形式是 [`tests/test_run_contract_inventory.py`](../tests/test_run_contract_inventory.py)，它冻结
下文第 2.2、3.1、4 节的条目：条目被删除必须同步改本文与该基线（只减不增，且不允许静默新增）。

## 1. 唯一生产契约与判定口径

生产契约只有一条：**每次测量都必须绑定同一个 `runs/<run_id>/` 运行目录**（`config.json` +
`manifest.json` + `inputs/hardware_config.json` 冻结快照），由它提供运行标识、领域配置和硬件装配
配置。判定口径固定如下：

| 判据 | 含义 |
| --- | --- |
| `PreparedRun.run_repository` 非 `None` | 该对象具备运行契约（`PreparedRun.has_run_contract` 的唯一依据） |
| `PreparedRun.hardware_connection_path()` | 硬件连接与测量的配置权威：运行目录内冻结的 `inputs/hardware_config.json`，并先校验 manifest SHA-256/大小 |
| `create_prepared_run()` / `load_prepared_run()` | 唯一的“创建运行”与“按 `run_id` 重新打开”入口，两者都产出带契约的 `PreparedRun` |
| `prepared_run is None` 或 `has_run_contract` 为假 | 无运行契约对象；任何以它为输入的硬件装配都是待移除路径 |

生产侧不得再新增无契约对象进入装配；测试需要“无契约”时只能使用明确登记在第 3 节的调用点，
并随步骤 5/6 迁移为契约替身。

## 6. 迁移顺序（供步骤 5、6 使用）

1. **步骤 5（装配入口收敛）**：先让 `connect_instruments`/`create_measurement_port` 接受 `PreparedRun`
   并只从 `hardware_connection_path()` 取配置（B11、B12），再迁移 `InstrumentWorker` 与协调器连接路径
   （B13–B15、X2–X6），使“没有运行就不连硬件”成为唯一路径；三个测量工厂的 `prepared_run` 参数变为必填
   （X7、B20）。此时 `prepare_run`/映射探测等分支虽然还在，但已无生产调用方。
2. **步骤 6（删除无契约前置校验分支）**：删除 B1–B10、B19 与 X1，随后按 B16–B18 清理应用层旧输入回退，
   并删除第 3 节 T1–T8 的相应用例或改为契约替身。
3. 每一步完成后同步更新本文的对应行（删除条目即删行）与 `tests/test_run_contract_inventory.py` 的基线；
   不要留下“清单已删、代码还在”或反向的偏差。
