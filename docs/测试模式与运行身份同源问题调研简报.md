# 测试模式与运行身份同源问题调研简报

- 日期：2026-11-13
- 状态：已完成（方案已落地，见[重构计划](测试模式与运行身份同源问题重构计划.md)）
- 基线：`main` / `f4fadbe`（步骤 6 收尾提交）
- 范围：`presentation/qt` 的测试模式来源、测量入口与工作台身份
- 结论：这是一个真实的同源问题，不只是页面显示不一致；旧运行在新会话里仍然可能被启动测量。只改驱动模式 provider 会造成“界面 B、测量 A”的错配，必须同时收紧测量入口。

## 1. 结论摘要

当前有两套“驱动模式”语义，但多数 UI 消费者只拿到一套查询：

- **会话模式**：欢迎页选择的、当前这次配置会话要使用的模式；`None` 表示尚未选择。
- **运行模式**：已冻结/已提交运行里的 `test_plan.driver_enabled`。

`ApplicationCoordinator.amplifier_driver_mode()` 按设计优先返回运行模式，这适合加载运行、提交运行和测量进行中的场景；但 `PageContext.driver_mode_provider` 与仪器排布页也直接使用了它，它们服务的是下一次配置会话的 UI。返回欢迎页后 `prepared_run` 与旧端口仍然保留，于是旧运行的模式会覆盖新会话的选择，而且旧运行仍可被 `resolve_measurement_run()` 解析。

推荐修复分两部分：

1. 页面与排布页改用“当前会话模式”查询：非测量态跟会话模式，测量进行中跟冻结运行模式。
2. 测量入口要求流程状态为 `CONNECTED`；旧运行在新会话里只保留给明确的重连/历史动作。

## 2. 复现现象

在离屏真实窗口上复现（基线 `f4fadbe`）：

1. 完成一个有驱放运行 A 并连接。
2. 返回欢迎页，选择“无驱放测试”B。
3. 进入工作区配置页并激活功放页。

结果：

- 徽标显示“无驱放测试”。
- `amplifier_page._driver_mode_provider()` 仍返回 `True`。
- 功放页“加载驱动映射结果”入口仍可见，并提示必须加载驱动映射。
- 仪器排布页 `board._driver_enabled` 仍为 `True`，链路里仍会画 Driver。
- `coordinator.state` 已是 `DEVICE_SELECTION`，但 `prepared_run` 仍是 A，`instrument_ctrl` 仍是旧连接。
- `coordinator.resolve_measurement_run()` 仍返回运行 A。

这说明问题不只是显示：如果只把页面 provider 改成会话模式 B，页面会显示 B，但启动时仍可能拿到运行 A，形成更危险的错配。

## 3. 根因链

1. `ApplicationCoordinator.amplifier_driver_mode()` 优先使用 `prepared_run` 的 `test_plan.driver_enabled`，没有运行才回退到配置页。
   - 位置：`presentation/qt/application_coordinator.py:1110-1121`
   - 该语义有测试锁定：`tests/ui/test_application_coordinator.py:1294`
2. 返回欢迎页只复位工作台身份与模式，不释放旧端口，也不解除 `prepared_run`。
   - 位置：`presentation/qt/main_window.py:306-309`
3. `PageContext.driver_mode_provider` 与仪器排布页直接使用上述“运行优先”的查询。
   - 页面：`presentation/qt/main_window.py:332`
   - 排布页：`presentation/qt/main_window.py:259`
4. 工作区配置页上阶段条可见，用户可以在新运行提交前进入功放页；`AmplifierPage.on_activated()` 会按 provider 刷新驱动映射入口。
   - 位置：`presentation/qt/amplifier_page.py:247-250`、`379-391`
5. `resolve_measurement_run()` 只检查未决清理、`prepared_run`、端口和快照，不检查流程状态，所以 `DEVICE_SELECTION` 下的旧运行仍可被测量页消费。
   - 位置：`presentation/qt/application_coordinator.py:621-644`

## 4. 影响面

- 徽标/页头与功放页、仪器排布页的驱动模式不一致。
- 有驱放切换到无驱放时，功放页仍要求驱动映射输入；反向切换时入口被错误隐藏。
- 仪器排布页可能画出旧运行才需要的 Driver 链路。
- 用户可能在新会话里启动旧运行 A；如果只修 UI provider，输入判断按 B、实际运行按 A，风险更高。
- 不影响应用层/领域层/基础设施的存储格式；问题集中在表现层状态与测量入口边界。

## 5. 方案对比

| 方案 | 做法 | 评价 |
| --- | --- | --- |
| A（推荐） | 窗口提供会话模式查询；测量入口增加 `CONNECTED` 守卫 | 改动小，同时修 UI 与旧运行误测；不复制状态 |
| B | 协调器新增会话模式字段，`amplifier_driver_mode()` 内部按状态选择 | 查询集中，但与 `WorkspaceBinding` 已有会话模式重复，需要多点同步，容易再漂移 |
| C | 返回欢迎页时释放端口并解除旧运行 | 模型最干净，但改变“重新连接”语义，端口清理失败需要新的 UX，属于产品决策 |
| D | 只把 `PageContext.driver_mode_provider` 改成会话模式 | 最小，但页面显示 B、启动仍可能拿 A，不安全 |

最终决定：采用方案 C 的会话生命周期（返回欢迎页即放弃当前会话），并保留方案 A 的查询拆分与测量入口守卫。方案 B 会与 `WorkspaceBinding` 已有的会话模式重复，不采用；方案 D 不安全，不采用。落地顺序与验收见重构计划。

## 6. 采用的查询与入口守卫（原推荐方案 A）

### 6.1 增加会话模式查询

在 `MainWindow` 增加短方法：

```python
def _current_driver_mode(self) -> bool:
    """当前配置会话的驱动模式；测量进行中始终使用冻结运行的模式。"""
    binding = getattr(self, "workspace_binding", None)
    mode = binding.driver_mode() if binding is not None else None
    if mode is None or self.measurement_controller.state.is_active:
        return self.coordinator.amplifier_driver_mode()
    return mode
```

语义：

- 正常配置阶段：使用 `WorkspaceBinding` 里已维护的会话模式（欢迎页选择、成功加载或提交后的运行模式）。
- 测量进行中：使用冻结运行模式，避免运行中切换模式改变页面输入。
- 绑定层尚未装配（页面构造期）：回退到协调器；此时通常没有 `prepared_run`，协调器会回退到配置页模式。

### 6.2 接线

- `PageContext(driver_mode_provider=self._current_driver_mode, ...)`
- `_open_rack_overview_page()` 使用 `driver_enabled=self._current_driver_mode()`
- `_on_run_loaded()` 与 `on_instrument_connected()` 继续使用 `coordinator.amplifier_driver_mode()`，因为这两个时刻必须以刚加载/刚提交的运行为准。
- `WorkspaceBinding` 的会话模式与运行身份逻辑保持不变。

### 6.3 测量入口守卫

在 `resolve_measurement_run()` 的“未决清理 / 无运行 / 无端口”检查之后增加：

```python
if self._state is not RunFlowState.CONNECTED:
    self._error("当前不在已连接的测量会话中；请先完成配置并连接仪器后再开始测量")
    return None
```

放在“无运行/无端口”之后，可以保留现有更具体的提示：

- 没有运行：仍是“尚未创建运行”；
- 没有端口：仍是“请先重新连接仪器”；
- 有旧运行 + 旧端口但已回到欢迎页/新配置会话：落到新提示，而不是静默测量旧运行。

## 9. 已确认的产品语义

- **返回欢迎页代表放弃当前运行**：采用方案 C。成功返回前释放当前仪器端口、清除内存中的当前运行/后台运行关联与工作台身份；不删除运行目录、配置文件或历史数据。端口清理失败时留在当前流程并报告失败，不丢端口引用。
- **方案 A 的查询拆分与入口守卫仍保留**：配置 UI 只读会话模式（重构计划步骤 1），测量入口要求 `CONNECTED`（步骤 2）；即使在完成会话清理之前，旧运行也不能被当次会话的测量入口消费。
- **是否允许在未连接时进入功放页浏览**：仍允许。功放页按当前会话模式呈现，不改变工作台导航与阶段可见性。
