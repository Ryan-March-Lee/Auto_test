# 测试结果归档：失败重试与幂等（步骤 9）

本文对应 [测试结果自动归档与导出流程重构计划](测试结果自动归档与导出流程重构计划.md) 的
**步骤 9：补齐失败重试和幂等测试**。它建立在
[归档契约](测试结果归档契约.md)（步骤 2）、[归档服务](测试结果归档服务.md)（步骤 3）、
[CSV 自动生成](测试结果归档CSV自动生成.md)（步骤 4）、
[报告自动生成](测试结果归档报告自动生成.md)（步骤 5）与
[历史运行/结果管理页](测试结果归档历史管理页.md)（步骤 7）之上，不重新定义归档状态。

本步骤的目标只有一个：**证明自动流程在失败、重复触发、部分完成和取消时不会破坏已有
结果**。因此范围以测试为主；过程中发现两处行为与契约不符，按“只修复发现的问题、不扩大
功能范围”一并修掉（见第 2 节）。

---

## 1. 冻结的重试与幂等规则

| 触发场景 | 正式结果 | 交付产物 | 归档结果 |
| --- | --- | --- | --- |
| 同一运行同一阶段重复归档，产物为 `completed` | 完全不改写 | 复用前经 `verify_artifact()` 复核；不重写记录、不重新生成 | 与首次一致 |
| 已完成阶段再次 `RunStageRecorder.complete()` | 拒绝（“不允许重新写入结果”），文件与登记不变 | 不产生 | — |
| 结果文件存在但 manifest 未登记 | 拒绝（`ArchivalRequestError`），不采纳该文件 | 不产生 | — |
| CSV 生成失败 | 保留 | CSV `failed` + 失败原因；报告照常生成 | `partial` |
| 报告生成失败 | 保留 | 报告 `failed` + 失败原因；CSV 照常生成 | `partial` |
| `retry_failed=True` 且产物为 `failed`、端口声明支持该类型 | 保留 | 仅该产物 `failed → pending → completed`，另一产物不重写 | 重试后的状态 |
| `retry_failed=True` 但连续失败 | 保留 | 同一条记录只更新失败原因，不累积、不重复登记 | 仍是 `partial` |
| `retry_failed=True` 且产物为 `completed` | 保留 | 不重新生成（`completed` 是终态） | 与首次一致 |
| `retry_failed=True` 但端口未声明该类型（含未装配端口） | 保留 | 保持 `failed` 与原失败原因，**不退化成 `pending`** | 仍是 `partial` |
| 运行/阶段已取消 | 不产生 | 不写 manifest、不生成产物；重复归档幂等 | `not_applicable` |
| 端口返回空路径、非 `GeneratedArtifact`、非请求的受控路径 | 保留 | 该产物 `failed`，不登记任何路径 | `partial` |
| 端口抛出未预期异常（实现缺陷） | 保留 | 异常上抛，产物停在 `pending` 待复查 | 不返回结果 |

幂等键仍是 `(source_result, kind)`：同一运行内同一份正式结果的同类产物只有一条记录。
重试只接受已登记的 `run_id` 与阶段（历史页走 `RunHistoryService`，阶段由 manifest
产物记录反查），不接受任何用户输入路径。

## 2. 本步骤修复的两处行为问题

### 2.1 重试把“端口不支持”的失败产物退化成 `pending`

| | 行为 |
| --- | --- |
| 原行为 | `retry_failed=True` 对**所有** `failed` 产物执行 `failed → pending`，之后才检查端口是否声明该类型；端口不支持的产物停在 `pending`，失败原因被清空 |
| 后果 | “没有实现”被显示成“正在生成”，历史页面的产物状态从此不再显示失败原因，`can_regenerate` 也随之失效（只看 `failed`） |
| 现行为 | 重试只复位端口**当前能生成**的产物类型；其余保持 `failed` 与原失败原因，并写一条应用日志说明跳过原因 |

对应测试：`test_retry_keeps_a_failure_the_port_cannot_generate`、
`test_retry_without_a_generator_keeps_the_failure`。

改动位置：`application/archival_service.py::ResultArchivalService._prepare_artifacts`。

### 2.2 历史页把已删除的 `completed` 产物说成“已生成”

| | 行为 |
| --- | --- |
| 原行为 | 运行摘要只读 manifest，`completed` 产物一律显示“已生成”；文件被删除后页面仍说已生成，且因为没有 `failed` 产物，重新生成按钮是禁用的，用户看不到任何异常 |
| 后果 | 只有 `RunRepository.verify_artifact_files()` 能发现文件缺失，历史页给出误导性状态（步骤 4 验收要求“文件缺失能被发现”） |
| 现行为 | `FileRunHistoryRepository.list_run_summaries()` 对 `completed` 产物做一次**存在性**诊断，文件不在时填 `RunArtifactSummary.missing=True`，页面显示 `CSV 已生成（文件缺失）` 并在说明列提示“请用导出副本重新获取”；manifest 记录与 `completed` 终态都不被改写 |

只做存在性判断（不重算 SHA-256）：历史刷新会遍历所有运行的产物，逐条计算摘要代价过高；
完整性校验仍由 `verify_artifact()` 在归档复用与显式校验时完成。结构不完整的运行同样按
文件事实诊断，不会因为缺配置快照就谎报产物缺失。

对应测试：`test_missing_completed_artifact_is_reported_without_rewriting_the_manifest`、
`test_incomplete_run_with_intact_artifacts_is_not_marked_missing`、
`test_missing_artifact_is_described_as_a_missing_file`、
`test_missing_completed_artifact_is_flagged_and_the_result_stays_exportable`。

## 3. 覆盖位置

`tests/test_archival_retry_idempotency.py`（16 项，本步骤新增）：

- 正式结果已存在：重复归档只有一份正式结果与每类一条产物记录、manifest 输入/输出与阶段
  状态不变；已完成阶段不能再写结果；未登记的结果文件不会被采纳；
- 产物失败与重试：CSV 失败、报告失败各自只影响该产物，显式重试只重生成失败项；连续重试
  不累积记录、保留最近失败原因；重试不会重写 `completed` 产物；端口不支持的失败产物保持
  `failed`；
- 运行取消：取消运行的归档幂等，不写 manifest、不生成产物，取消后重试也不会产出报告；
- 端口返回值边界：空路径、非 `GeneratedArtifact`、不受控/越界路径都登记为 `failed` 且不写
  路径；端口实现缺陷上抛且产物停在 `pending`；生成请求本身拒绝 `artifacts/` 之外的目标。

`tests/test_run_history_page.py`（本步骤新增 9 项）：

- DTO：`missing` 只能出现在 `completed` 产物上，且不影响 `can_regenerate`；
- 视图模型：`CSV 已生成（文件缺失）` 与说明列文案；
- 运行摘要：已完成产物文件缺失被标记、manifest 不被改写；结构不完整但文件齐全时不误报；
- 页面：无效运行不能重新生成（同批次有效运行仍可重试）、部分运行显示“进行中/无交付
  产物”、没有产物记录的运行显示“无交付产物”、产物文件缺失时提示且正式结果仍可导出副本。

既有覆盖不重复实现：产物生成适配器的输入/输出边界见
`tests/test_csv_artifact_generator.py`、`tests/test_report_artifact_generator.py`；
服务侧的已完成产物复核、并发归档与 manifest 写回失败见
`tests/test_result_archival_service.py`；成功完成路径与三类测量接线见
`tests/test_archival_success_path.py`。

## 4. 明确不属于本步骤

- 不提供“原地重新生成**已成功**产物”的强制入口：`completed` 仍是终态，文件缺失通过
  “导出副本”重新取得交付数据，历史页只做只读诊断。若将来要支持原地重建，应新增独立的
  `force` 入口并同时改契约、manifest 状态迁移与页面动作，而不是让重试顺手覆盖成功产物。
- 不改变 manifest schema、运行目录结构、阶段提交顺序或三类测量的归档时机。
- 不把部分运行、取消运行描述成完整成功；也不把产物失败混进测量状态。
