# 测试结果归档：报告自动生成（步骤 5）

本文对应 [测试结果自动归档与导出流程重构计划](测试结果自动归档与导出流程重构计划.md) 的
**步骤 5：将测试报告生成接入完整成功路径**。它建立在
[测试结果归档契约](测试结果归档契约.md)（步骤 2）、[测试结果归档服务](测试结果归档服务.md)
（步骤 3）与 [测试结果归档：CSV 自动生成](测试结果归档CSV自动生成.md)（步骤 4）冻结的
路径、状态与幂等规则之上，不再重新定义契约。

本步骤完成三件事：

1. 基础设施新增报告产物生成适配器，把**已登记的正式结果**渲染成运行目录 `artifacts/`
   下的 HTML 测试报告；
2. 组合根把 CSV 与报告合成**一个**生成端口，主功放完整成功后报告自动生成、报告与 CSV
   都登记进 manifest；
3. 报告失败只登记该产物为 `failed` 并保留正式结果，显式 `retry_failed=True` 是唯一的
   重新生成入口。

---

## 1. 入口与模块

| 模块 | 名称 | 职责 |
| --- | --- | --- |
| `infrastructure.persistence.artifact_generator` | `ReportArtifactGenerator` | 报告产物生成端口实现：只读 manifest 已登记并校验过的正式结果，写 `artifacts/<stage>_report.html`，返回实际路径 + SHA-256 + 大小 |
| `infrastructure.persistence.artifact_generator` | `ArchiveArtifactGenerator` | 组合端口：按 `supported_kinds` 把 `generate()` 派发给 CSV / 报告实现，是归档服务持有的唯一生成端口 |
| `infrastructure.persistence.artifact_generator` | `CsvArtifactGenerator` | 步骤 4 的 CSV 实现，本步骤只把它与报告实现共享的输入/目标边界收敛到 `_RegisteredResultGenerator` |
| `analysis.reporting` | `render_html_report()` | 报告 HTML 写入（步骤 5 扩充为：运行标识、状态、指标表、配置快照、计算摘要，以及同目录 CSV 链接与图表清单；`data_file` 按“单一文件名”严格校验） |
| `app.gui_runtime` | `_request_kwargs()` | 组合根：运行契约运行装配 `ResultArchivalService(generator=ArchiveArtifactGenerator(...))`；旧兼容快照不装配 |

调用形状：

```python
service = ResultArchivalService(
    runs=run_repository,
    generator=ArchiveArtifactGenerator(run_repository),
)
outcome = service.archive(ArchivalRequest(run_id, STAGE_AMPLIFIER))
outcome.csv.status, outcome.report.status, outcome.archive_status
```

## 2. 报告生成契约

| 维度 | 规则 |
| --- | --- |
| 目标路径 | 只允许 `artifacts/` 下的受控相对路径；默认值由 `domain.run.models.default_artifact_path(stage, report)` 给出（`artifacts/amplifier_report.html`），适配器不自己拼文件名 |
| 目标边界 | 与 CSV 共用同一套真实路径校验：`artifacts/` 的真实位置必须在运行目录内，目标文件的真实位置必须在 `artifacts/` 内；POSIX 符号链接与 Windows junction 都被挡住 |
| 目标阶段 | 只有 `amplifier` 有报告交付产物；线损/驱动映射请求会被明确拒绝（它们应登记 `not_applicable`） |
| 生成时机 | 由归档服务判定：只有 `stage=amplifier` 且 `test_status=completed`（阶段完成 + 运行整体完成 + 正式结果已登记且校验值齐全）才调用端口 |
| 输入来源 | `RunRepositoryPort.read_run_json(run_id, source_result)`：缺登记、缺文件、SHA-256/大小不一致一律拒绝；解析只走 `measurement_result_from_document()`，且必须解析为 `amplifier` 结果 |
| 运行标识一致性 | 解析出的 DTO `run_id` 必须等于归档请求的 `run_id`：文件在目录里、登记也齐全，但内容自称属于另一个运行时（被复制/替换过的结果），按显式失败拒绝，不生成任何交付产物 |
| 空数据 | 结果没有可生成报告的数据行时抛 `ArtifactGenerationError`（显式失败），不写空报告 |
| 报告内容 | 只来自正式结果 DTO：`run_id`、`measurement_type`、`status`、点数、测量时间、来源文件名、`saturation_points()` 指标表、配置快照与计算摘要；不读取页面状态，不使用“最新文件” |
| 同目录引用 | 报告只引用**真实存在**的兄弟文件名：只有该 CSV 对同一正式结果已登记为 `completed` 且 `verify_artifact()` 确认文件与登记值一致时，才写 `<a href="amplifier.csv">`；否则省略数据链接（不写死链，也不让报告失败）。`render_html_report()` 对 `data_file` 做文件名校验（拒绝目录分隔符、盘符、`..`），图表路径只取其文件名 |
| 渲染依赖 | **不使用 matplotlib 渲染图表**：自动归档发生在测量成功之后，必须在任何环境下都不拖垮测量进程；图表渲染留给用户在可视化/历史页显式触发 |
| 渲染依赖 | **不使用 matplotlib 渲染图表**：自动归档发生在测量成功之后，必须在任何环境下都不拖垮测量进程；图表渲染留给用户在可视化/历史页显式触发 |
| 写入方式 | 与 CSV 共用 `_publish()`：先写同目录临时文件（文件名带随机后缀）再 `os.replace` 原子替换，失败清理临时文件，不留下被 manifest 引用的半截报告 |
| 校验值 | 写入后单次读取计算 SHA-256 与字节数，随 `GeneratedArtifact` 返回并由归档服务登记进 manifest |

失败语义与步骤 3/4 一致：适配器把所有**可预期**失败包成 `ArtifactGenerationError`，归档服务
只把该产物登记为 `failed` 并保留正式结果；其它异常上抛，不伪装成“产物生成失败”。

## 3. 完整成功路径的判定

报告不是“运行结束就生成”，而是由归档服务按 manifest 推导，因此下面这些情况都不会产生
“完整测试报告”：

| 边界 | 报告产物 | 说明 |
| --- | --- | --- |
| 主功放完整成功（阶段 `completed` + 运行 `completed`） | `completed`（失败时 `failed`） | 唯一会自动生成报告的路径 |
| 主功放阶段完成但运行仍 `running`（部分完成） | 本次归档结果里 `not_applicable`，**不写** manifest 记录 | 避免把“还没跑完”登记成终态不适用，挡住以后的完整成功 |
| 线损、驱动映射成功 | `not_applicable`，写入 manifest | 这两类没有交付产物 |
| 取消、异常、无正式结果 | `not_applicable` | 取消路径会删除阶段结果，不生成报告 |

主功放必须在 `complete()` 与 `complete_run()` **都成功后**才归档：`complete_run()` 失败时
归档不执行，运行停在 `running`，页面看到的是未完成而不是“完整的报告已生成”。

## 4. 失败、幂等与重试

- 报告生成失败（写入失败、结果不可读、空数据、运行标识不一致）只把 `report` 记录标成
  `failed`，`error` 写明原因；正式 JSON、`csv` 产物、阶段状态与运行状态都不变，
  `archive_status` 变 `partial`。
- CSV 与报告彼此独立：CSV 失败不阻止报告生成，报告只是**省略**指向该 CSV 的链接，
  因此交付产物里不会出现死链；报告本身仍登记为 `completed`，`archive_status` 为 `partial`。
- 失败产物默认**不重复生成**：再次归档时保持 `failed`，不会悄悄覆盖成成功或反复重试。
- 唯一重新生成入口是 `archive(..., retry_failed=True)`：`retry_artifact()` 把该产物从
  `failed` 回到 `pending` 后再生成；`(source_result, kind)` 幂等键保证同一运行内报告只有
  一条记录。
- 已完成报告是终态：再次归档时先经 `RunRepositoryPort.verify_artifact()` 复核文件仍存在且
  与登记值一致，缺失或被改写按 `ArchivalRequestError` 拒绝本次归档（`archive_completed_stage()`
  只写错误日志），manifest 记录不被就地改判；显式重新生成留待步骤 7/9 的历史重试入口。
- 组合端口在装配阶段就拒绝不一致：同一产物类型注册两个实现、实现未声明 `supported_kinds`、
  声明了未知类型都会直接 `TypeError`，不会留到运行期才发现派发不了。

## 5. 明确不属于本步骤

- 不生成报告图表（PNG/PDF）：`ArtifactKind` 注释与归档契约允许图表与报告同目录，但本步骤
  不写图表，报告也不引用不存在的文件；图表渲染留给可视化/历史页的显式动作。
- ~~不改页面状态展示（步骤 6）~~：三个测量页已在步骤 6 显示归档结果，见
  [测试结果归档：主测试页面显示归档结果](测试结果归档结果展示.md)；历史页的失败产物重试入口
  已在步骤 7 接通，失败/重试/幂等的最终口径见
  [失败重试与幂等](测试结果归档失败重试与幂等.md)。
- 不收敛 `ExportPage`、可视化页与 `ResultExportUseCase` 的手动导出语义（步骤 7/8）；
  手动导出的报告仍由 `ResultExportAdapter.export_report` 生成到 `test_results/report-*`。
- 不改变阶段结果路径、manifest 校验顺序、取消/异常路径。

`tests/test_report_artifact_generator.py`（31 项）覆盖：

- 适配器：报告落在 `artifacts/amplifier_report.html`、返回路径与摘要/大小与文件一致；HTML
  含运行标识、测量类型、状态与指标表；报告**不含**运行目录绝对路径；
- 同目录 CSV 链接：CSV 已登记为 `completed` 且校验一致时写 `<a href="amplifier.csv">`；
  单独生成报告（manifest 无已完成 CSV）或已登记 CSV 文件被删除时**省略**链接，不写死链，
  也不因此让报告失败；
- 运行标识一致性：正式结果 DTO 的 `run_id` 与归档运行不一致时显式失败、不写报告；
- 报告写入边界：`render_html_report()` 的 `data_file` 必须是单一文件名（拒绝绝对路径、
  盘符、目录分隔符、`..`、空值、空字符），图表路径必须能取到文件名，否则 `ValueError`；
- 显式失败：空数据、未登记结果、非主功放阶段、CSV 类型请求、写入失败（目标被同名目录占住）
  ——都不产生半截产物，正式结果保持原样；
- 目标边界：真实路径守卫拒绝越出 `artifacts/` 的目标；`artifacts/` 被重定向到运行目录外时
  拒绝生成，目录外不留下文件；临时文件每次带随机后缀且失败后不残留；
- 装配边界：报告适配器要求运行仓储提供 `read_run_json()`/`load_manifest()`/`verify_artifact()`，
  缺失时 `TypeError`；CSV 适配器不因此被要求 manifest 校验能力；
- 组合端口：声明 `{CSV, REPORT}`、按类型派发、未注册类型显式失败、重复注册/未声明的实现
  在装配阶段 `TypeError`；
- 服务集成：完整成功时 CSV 与报告都是 `completed`、`archive_status=completed`、manifest
  登记真实摘要并通过 `verify_artifact_files()`；部分完成不生成报告也不写产物记录；线损只登记
  两条 `not_applicable`；报告失败只影响该产物、默认不重试、显式 `retry_failed` 后转为
  `completed`；CSV 失败时报告仍为 `completed` 且不含 CSV 链接（`archive_status=partial`）；
  重复归档复用已完成报告（只生成一次、文件不被重写）；已删除的已完成报告再次归档按
  `ArchivalRequestError` 拒绝复用。

`tests/test_archival_success_path.py`（11 项）同步把主功放的验收口径更新为
“CSV + 报告都自动生成、`archive_status=completed`”，并保留 CSV 失败时报告照常生成、
