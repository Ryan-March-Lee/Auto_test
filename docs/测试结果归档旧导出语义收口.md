# 测试结果归档：旧导出页面语义收口（步骤 10）

本文对应 [测试结果自动归档与导出流程重构计划](测试结果自动归档与导出流程重构计划.md) 的
**步骤 10：删除旧导出页面语义并完成门禁**。它建立在
[历史运行/结果管理页](测试结果归档历史管理页.md)（步骤 7）、
[可视化页报告入口收敛](测试结果归档可视化页收敛.md)（步骤 8）与
[失败重试与幂等](测试结果归档失败重试与幂等.md)（步骤 9）之上，不改变归档契约、运行目录
结构或 manifest 校验。

本步骤完成三件事：

1. 页面语义彻底收口：模块、类、装配函数与路由都以“历史运行”命名，不再保留“导出页”作为
   正常测试流程的一个必经页面；
2. 删除不再使用的页面专属状态与页面级重复导出入口：窗口不再复制页面的表格/按钮，页面只
   保留 `export(format)` 一个导出入口；
3. 复跑完整离线门禁，并把“旧导出语义不得回流”固定成自动化测试。

---

## 1. 入口与模块

| 模块 | 名称 | 职责 |
| --- | --- | --- |
| `presentation.qt.run_history_page` | `RunHistoryPage`、`build_run_history_page()` | 历史运行/结果管理页：运行表格、结果表格、失败产物重新生成、导出副本；步骤 10 由 `export_page.py` / `ExportPage` / `build_history_page()` 更名而来 |
| `presentation.qt.pages` | `PageDefinition("run_history", "历史运行", ...)`、`PageContext.build_run_history` | 页面注册的唯一位置：路由 key 为 `run_history`，用户可见标题仍为“历史运行” |
| `presentation.qt.main_window` | `create_run_history_tab()`、`refresh_history()` | 只装配页面并转发测量完成的刷新动作；不再持有页面的表格或导出按钮 |
| `application.export_service` | `ResultExportUseCase`、`ExportRequestError` | **保留**：历史页导出副本、可视化页报告副本与外部调用仍使用该唯一实现 |
| `application.ports.gui_data_service` | `ResultExportServicePort`、`ExportRequest` / `ExportOutcome` | **保留**：页面只描述导出意图，应用层执行 |
| `tests/test_export_semantics_retirement.py` | `ExportPageSemanticsRetirementTests` | 步骤 10 回归门禁：旧模块/路由/窗口状态/页面级格式转发都不得回流 |

## 2. 删除的旧语义与页面状态

| 旧名称 | 现名称 | 说明 |
| --- | --- | --- |
| `presentation/qt/export_page.py` | `presentation/qt/run_history_page.py` | 整文件更名；不保留旧模块的兼容再导出 |
| `ExportPage` | `RunHistoryPage` | 页面类名不再暗示“导出是主流程” |
| `build_history_page()` | `build_run_history_page()` | 装配函数与页面语义一致 |
| 路由 key `export` | 路由 key `run_history` | 页面定义不再登记“导出”这一功能入口 |
| `PageContext.build_export` | `PageContext.build_run_history` | 页面构造上下文同步更名 |
| `MainWindow.create_data_export_tab()` | `MainWindow.create_run_history_tab()` | 窗口装配方法同步更名 |
| `MainWindow.export_page` | `MainWindow.run_history_page` | 窗口只持有页面对象本身 |
| `MainWindow.file_table` / `export_json_btn` / `export_csv_btn` / `export_report_btn` | 已删除 | 页面内部控件归页面所有，窗口不再复制一份可被误用的状态 |
| `ExportPage.export_json()` / `export_csv()` / `export_report()` | 已删除 | 按钮直接调用 `export(ExportFormat)`，不再为每种格式各写一份转发方法 |
| `MainWindow.refresh_file_list()` | `MainWindow.refresh_history()` | 测量完成后的刷新动作按历史结果命名 |

用户可见标题保持“历史运行”；“导出”只作为历史管理里的辅助动作出现：

- 历史运行表格：运行、阶段、正式结果、交付产物状态与阻塞原因；
- 历史结果表格：导出副本的数据来源；
- 操作：重新生成失败的产物（写回原运行目录）、导出 JSON/CSV/测试报告副本（用户选择目标）。

## 3. 明确保留的应用层导出能力

计划要求不能因为 UI 页面更名就删除应用层导出服务。以下全部保留且仍被使用：

- `application.export_service.ResultExportUseCase`：唯一的导出入用例，执行前核对
  `result_id` 属于历史查询端口返回的列表，并判定格式适用性；
- `application.dto.export_requests`：`ExportFormat`、`ExportRequest`、`ExportOutcome`；
- `application.ports.gui_data_service.ResultExportPort` / `ResultExportServicePort`；
- `infrastructure.gui_data_service.ResultExportAdapter`：JSON/CSV/报告副本的实际写入；
- `GuiDataService.export_requests`：历史页与可视化页共用的门面入口；
- `application.run_history_service.RunHistoryService.regenerate_failed_artifacts()`：历史页
  对失败 CSV/报告的重新生成，复用自动归档的同一套产物生成实现。

## 4. 兼容导入与调用检查

- 全仓检查 `presentation.qt.export_page`、`from .export_page`、`ExportPage`、
  `build_history_page`、`create_data_export_tab`、`build_export`、`refresh_file_list`：
  生产包与测试中已无调用（历史文档保留旧步骤叙述，不影响运行）；
- 旧路由 key `export` 不再出现在 `PAGE_DEFINITIONS` 中；
- 旧模块属于 `INTERNAL_MODULES`，不是公共 API；确认无调用后按计划直接删除，不保留
  “两边都能用”的过渡导入，避免旧语义重新扩散；
- 架构门禁同步改为读取 `presentation/qt/run_history_page.py`，静态质量门禁的宽泛捕获
  站点身份从 `ExportPage.export#1` 改为 `RunHistoryPage.export#1`。
