# 测试结果归档：主测试页面显示归档结果（步骤 6）

本文对应 [测试结果自动归档与导出流程重构计划](测试结果自动归档与导出流程重构计划.md) 的
**步骤 6：在主测试页面显示归档结果**。它建立在
[测试结果归档契约](测试结果归档契约.md)（步骤 2）、[测试结果归档服务](测试结果归档服务.md)
（步骤 3）、[CSV 自动生成](测试结果归档CSV自动生成.md)（步骤 4）与
[报告自动生成](测试结果归档报告自动生成.md)（步骤 5）冻结的 DTO 之上，不重新定义归档状态。

本步骤完成三件事：

1. 三个测量页面新增“归档结果”分组：测试结束后用户在当前页面就能确认结果是否已保存、
   哪些交付产物已生成；
2. 归档状态与测试状态分别表达：成功、部分产物失败、测试异常、取消/停止各有独立提示，
   产物失败提示带可定位的运行 ID 与重新生成入口；
3. 提供“打开结果目录 / 打开测试报告”的快捷动作，但不强制用户操作。

---

## 1. 入口与模块

| 模块 | 名称 | 职责 |
| --- | --- | --- |
| `presentation.qt.archival_status` | `summarize_archival()` 等 | 纯 Python：把 `ArchivalOutcome` 与终端状态转成 `ArchivalSummary`（标题、说明、语气、运行 ID、报告位置）；不读文件、不判断路径存在、不依赖 Qt |
| `presentation.qt.archival_view` | `ArchivalStatusView` | Qt 分组控件：显示标题/说明，按 `ArchivalSummary` 启用“打开结果目录/测试报告”，位置由窗口注入的 provider 提供；动态文案按纯文本渲染 |
| `presentation.qt.archival_page` | `ArchivalPageMixin` | 三个测量页面共用的归档状态机：等待归档、保存中、结果展示、终止事件与运行切换后的旧摘要清理；页面不再各写一套 |
| `presentation.qt.workers` | `WorkerSignals.archival` / `BaseWorker._emit_archival()` | 测量 worker 在发出结构化结果后转发用例的 `last_archival_outcome`；没有归档结果时不发事件 |
| `presentation.qt.measurement_controller` | `_on_archival()` / `signals.archival` | 只转发与当前测量类型对应的阶段；controller 不解释产物含义，也不读取文件 |
| `presentation.qt.amplifier_page` / `cable_loss_page` / `driver_mapping_page` | `_archival_*` 钩子调用 | 页面只保留自己的按钮/表格逻辑，归档状态全部委托给 `ArchivalPageMixin` |
| `presentation.qt.application_coordinator` | `archival_location()` / `current_run_id()` | 把“运行 ID + 运行目录内产物相对路径”解析成可打开的本地位置；运行必须是当前运行，路径必须落在 `artifacts/`；`current_run_id()` 是给页面做运行归属判断的静默查询（不检查仪器、不弹窗） |
| `presentation.qt.pages` / `main_window` | `PageContext.archival_location_provider` / `archival_run_id_provider` | 页面构造上下文新增两个窄回调，窗口只转发协调器的方法 |

调用形状：

```python
# 应用层：用例在阶段成功提交后归档（步骤 3/4/5）
outcome = archive_completed_stage(service, run_id=run_id, stage=STAGE_AMPLIFIER)

# 表现层：worker -> controller -> 页面，只传结构化 DTO
worker.signals.archival.emit(outcome)      # BaseWorker._emit_archival()
controller.signals.archival.emit(outcome)  # 仅当 stage 与当前测量类型一致
page.show_archival(outcome)                # summarize_archival() -> 文案 + 按钮
```

## 2. 状态到文案的映射

`ArchivalOutcome` 的 `test_status` 与 `archive_status` 决定提示，页面不再自行判断文件是否存在：

| 情形 | 提示标题 | 语气 | 按钮 |
| --- | --- | --- | --- |
| 测量开始 | “……测量结束后将自动归档结果” | info | 全部禁用 |
| 扫描结束（保存/生成中） | “……扫描结束，正在保存结果并生成交付产物…” | info | 全部禁用 |
| 完整成功且产物全部完成 | “……结果已自动归档” | success | 结果目录 + 报告 |
| 完整成功但产物仍在生成 | “……结果已保存，交付产物仍在生成” | info | 结果目录 |
| 完整成功但产物失败 | “……结果已保存，但部分交付产物生成失败” | warning | 结果目录（已完成的报告仍可打开） |
| 阶段完成（线损/驱动映射） | “……阶段结果已自动归档” | success | 结果目录（报告不适用） |
| 测试失败 | “……测试失败：未生成交付产物” | error | 无（运行 ID 见说明） |
| 取消/紧急停止 | “……测试已取消：本次未归档结果” | warning | 无 |
| 完成但没有归档结果 | “……结果已保存，但未收到归档结果” | warning | 结果目录 |

> 表格里的按钮指“该状态下按钮是否可点”。若摘要里的运行已不是当前运行，按钮一律关闭：
> 位置解析只服务当前运行，跨运行查看走“数据导出”页。

组合规则全部来自 DTO：产物失败会给出运行 ID，并提示到“数据导出”页按运行重新生成；
取消与失败不会被描述成完整成功；产物路径只作为 DTO 里的受控相对路径出现在说明中。

## 3. 页面职责与边界

- 页面**只**消费 `ArchivalOutcome` / `ArchivalSummary`：不读文件、不判断文件是否存在、
  不拼接导出规则，也不根据“最新文件”推断产物状态。
- 归档期间的明确状态：开始测量即显示“结束后将自动归档”；进度到 100%（扫描结束、正式结果
  写入与产物生成进行中）切换为“正在保存结果并生成交付产物…”；终端事件后要么给出 DTO 文案，
  要么明确说明“未收到归档结果”，不会静默停留在成功外观。
- “等待归档”只在 controller **接受启动之后**出现：启动被拒绝（已有测量在运行、用例构造失
  败）时不会出现等待外观；上一次真实测量已经显示的归档结果保持可见，不会被一次被拒绝的
  启动清零。
- 测试失败与取消由终止事件驱动（本次没有归档结果），与“产物失败但测试成功”严格区分。
- 三个页面共用 `ArchivalStatusView`、`summarize_archival()` 与 `ArchivalPageMixin`：状态机、
  文案规则与运行归属判断都不在页面里复制。
- 快捷动作只是展示便利：位置由协调器解析（`run_id` + `artifacts/` 内相对路径），
  即使按钮不可用时用户也能从日志或“数据导出”页按运行 ID 定位结果。
- 快捷入口只服务**当前运行**：摘要带运行 ID 但已不是当前运行时按钮不可用，页面被激活
  （`on_activated`）后清除旧摘要并说明去“数据导出”页查看历史运行；本步骤不实现跨运行
  目录查找。
- 动态文本按纯文本渲染：错误原因、产物原因与运行目录内相对路径可能含 `<`、`&` 等字符，
  `QLabel` 显式使用 `Qt.PlainText`，避免异常文本被 Qt 当富文本解析。

## 4. 明确不属于本步骤

- 不实现历史页的重新生成入口（步骤 7/9）：失败产物仍只通过应用层 `retry_failed=True` 重试；
- 不改变 `ExportPage`、可视化页与 `ResultExportUseCase` 的手动导出语义（步骤 7/8）；
- 不生成报告图表（PNG/PDF），也不在归档阶段渲染图表；
- 不改变阶段结果路径、manifest 校验顺序、取消/异常路径。

`tests/test_archival_status.py`（17 项）覆盖：

- 完整成功：标题/语气/运行 ID/报告位置与按钮可用性一致；
- 部分产物失败：说明含失败原因与运行 ID，完成的报告仍可打开，全部失败时报告按钮关闭；
- 产物仍在生成（`pending`）：标题与语气明确，报告不可打开；
- 阶段完成（线损/驱动映射）：成功归档但不提供报告；
- 取消与失败：不提供按钮，失败区分“未保存正式结果”和“保留失败前结果”；
- 完成但没有归档结果：明确“状态未知”并保留运行 ID；
- 扫描结束（进度 100%）的“正在保存/生成”提示；
- 非正式 DTO、未知测量类型、空文案或未知语气一律拒绝。

`tests/test_archival_display.py`（26 项）覆盖：

- 页面初始状态、开始测量的归档说明与扫描结束后的“正在保存”状态；
- 完整成功、部分失败的文案、按钮状态与“打开报告”调用参数；
- 其他阶段的归档结果被页面与 controller 忽略；
- 完成但无归档结果（含非正式载荷）显示“未收到归档结果”，错误与停止显示各自提示；
- 启动被 controller 拒绝（`start_*()` 返回 `False`）时归档分组不出现等待外观，上一次真实结果保持不变；
- controller 先同步发出 `error` 再返回 `False` 时，失败原因不会被“拒绝启动”提示覆盖；
- 已有测量运行时线损页拒绝启动并保持归档分组中性；
- 运行切换后页面激活会清除旧运行的摘要，且跨运行的摘要不提供快捷按钮；
- 含 `<b>`、`&` 的异常文本按纯文本显示（`Qt.PlainText`）；
- 线损页加载历史结果时清空归档分组；
- worker 只在用例给出归档结果时转发，没有结果时保持静默。

`tests/test_application_coordinator.py` 新增 `current_run_id()` 的静默查询断言（不检查仪器、
不产生错误回调），保证页面做运行归属判断时不会因为“未连接仪器”弹窗。

页面测试只验证状态展示与按钮行为，不校验文件格式或路径内容。

## 6. 审查修复记录（本步骤收尾）

| 问题 | 修复 | 技术决定 |
| --- | --- | --- |
| 线损页未检查运行状态：启动被拒绝后仍显示“结束后将自动归档” | 线损页增加活动测量保护；三个页面统一改用 `_archival_try_start()`，只在 controller 接受启动后才进入等待状态 | 归档等待外观必须由“启动已接受”驱动，页面不得先声明再回滚 |
| 归档文案把异常文本交给 `QLabel` 富文本解析 | 标题与详情显式 `Qt.PlainText` | 运行期文本（错误原因、产物原因、相对路径）一律按纯文本渲染 |
| 运行切换后旧摘要仍提供打不开的快捷入口 | 视图按 `current_run_id_provider` 判断归属；页面在 `on_activated()` 清除其他运行的摘要 | 位置解析只服务当前运行，本步骤不引入跨运行目录查找 |
| 三份重复的页面归档状态机容易再次走样 | 抽出 `presentation.qt.archival_page.ArchivalPageMixin` | 状态机单点维护，页面只保留按钮/表格逻辑 |
| 页面为拿运行 ID 调用 `resolve_measurement_run()`（会弹“请先连接仪器”） | 协调器新增静默 `current_run_id()`，经 `PageContext.archival_run_id_provider` 注入 | 展示用的运行归属查询不得有副作用 |
