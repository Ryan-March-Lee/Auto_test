# 测试运行目录与配置结果解耦重构指南

## 当前结论

本指南对应的核心运行目录重构已经完成，但整体计划尚未全部完成，文档暂不删除。

已完成的范围：

- 运行目录、`run_id`、`manifest.json`、相对路径和阶段状态模型已实现。
- `RunRepository` 已支持运行创建、原子 JSON 写入、文件登记、SHA-256/大小校验、完整性检查和失败清理。
- 运行创建会冻结领域配置 `config.json` 和硬件配置 `inputs/hardware_config.json`，两者独立校验并登记到 manifest。
- 线损、驱动映射和主功放的新运行路径使用当前 `run_id` 的阶段输入；缺少必需输入时在连接仪器前失败。
- 驱动模式关闭时不会要求驱动映射输入。
- 阶段结果写入当前运行目录并更新 manifest，隔离、失败、取消、篡改和部分创建场景已有测试覆盖。
- GUI 已提供“创建运行”和按 `run_id` 重新加载运行的入口，测量页面消费 `PreparedRun`，不会在开始测量前覆盖冻结配置。
- 启动器已提供列出运行、查看 manifest、校验文件和恢复前置检查的离线入口。
- 旧全局结果查询、无路径驱动映射读取和 GUI `latest()` 已进入弃用期，并发出弃用警告。

尚未完成的范围：

- 旧兼容配置、旧结果写入/查询、历史测量入口仍保留，尚未完成外部调用方迁移和删除决策。
- GUI 仍保留旧兼容快照入口；新流程已有运行契约，但尚未将所有生产入口强制收敛到运行契约。
- 真实 Hardware Smoke 和三类现场完整测量尚未完成。该事项由
  [重构收尾与真实HardwareSmoke验收.md](重构收尾与真实HardwareSmoke验收.md) 单独跟踪，未取得现场授权前不得执行真实 RF 或电源动作。

补充结论：

1. 生产代码中没有发现显式 `run_contract=False`；但发现三个 GUI worker 在未收到
   `prepared_run` 时调用 `prepare_configuration()`，通过其默认参数进入兼容快照流程。
   `app.gui_runtime.prepare_configuration()` 本身及这三个 worker 后备分支都是待迁移的隐式兼容入口。
2. 生产代码中没有发现直接调用弃用的 GUI `latest()`；正式测量用例通过运行仓储保存权威结果，
   但仍保留 `save_compatibility_copy()` 作为兼容写入。
3. 生产代码中没有发现无参数调用 `driver_mapping_path()`；唯一回退链为
   `ResultInputReader.driver_mapping_path(None) -> repository.latest_path()`，已明确标记为兼容路径。
4. 旧配置保存、三个兼容/回滚测量入口、三个 GUI worker 的隐式兼容后备分支、三类新用例的兼容副本、
   历史结果查看和基线迁移工具均已分类。以上结论限定为仓库内生产代码；外部脚本调用无法由静态仓库
   搜索确认，需在步骤 E 删除兼容层前通过发布使用情况和迁移记录进一步确认。步骤 A 不修改运行行为。
