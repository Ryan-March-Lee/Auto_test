# 电源配置独立化与通道上电计划重构

## 目标

将电源配置从现有测试参数配置页面拆分为独立页面；由用户按物理通道选择启用项、配置上电顺序和通道间隔。通道角色不再控制通道选择、映射或上电行为。

**保留“漏极”这一用户配置的通道语义。** 效率计算需要读取漏极通道的电压、电流，因此用户仍须显式指定哪个已配置通道是漏极。该标记只用于测量数据读取/效率计算，不参与上电排序、延迟、通道启停或安全关断。其他角色（例如 gate、driver）不作为通道配置项。若效率公式或结果目前还依赖 gate 等通道，须先确认并将其改为明确的物理路由/全通道汇总逻辑，不得悄悄以 CH1/CH2 推断。

## 现状与影响面

目前电源详细参数和供电分配由 `presentation/qt/config_power_section.py` 构建，嵌在 `ConfigurationPage` 右侧。配置从 `application/configuration_draft.py` 经 `application/configuration_authoring.py`、`domain/configuration/rules.py` 和 `domain/configuration/models.py` 校验、生成运行快照，再进入 `application/dto/amplifier_inputs.py`、`instrument/measurement_adapter.py` 和 `instrument/session.py`。当前角色语义在这些环节被当作映射键或校验条件；`measurement_adapter.py` 和 `simulation.py` 还有固定角色顺序/成对规则。迁移代码 `infrastructure/config/legacy_power_supply_migration.py` 也按角色派生运行通道。

重构时只移除**供电角色对运行路由/上电的控制作用**。以下“role”并非此处要删除的通道角色：设备发现与绑定中的仪器类别、注册表身份、Qt 控件属性，以及新模型中专供效率测量的用户配置“漏极”标记。

## 设计决定

1. **物理路由是唯一通道身份**：使用 `supply_id + channel` 标识通道；禁止从 `CH1`、`CH2` 推断 gate、drain 或上电顺序。
2. **角色与上电计划分离**：上电计划包含启用通道的有序列表及间隔；漏极标记单独保存并只供测量/效率计算读取。
3. **组级计划**：DUT 与驱动功放分别配置通道计划，沿用当前“先处理 driver、后处理 DUT”的总体阶段顺序；各组内部由用户排序。若设备需求要求跨组交错，作为后续需求另行评估，不在第一版引入全局编排器。
4. **第一版统一间隔**：每组配置一个非负、有限的通道间隔；上一通道确认输出开启后等待该间隔，再启用下一通道。单通道计划无需等待。若后续有真实用例，再扩展逐步延迟。
5. **关断顺序**：按本次已尝试启用顺序逆序关闭；单通道关闭失败不阻止其余通道尝试关闭。
6. **失败策略**：上电中任一步失败即停止后续通道；对本次已尝试（命令已发出即视为可能已启用，含响应丢失的失败通道）的通道逆序 best-effort 关断；未确认关闭的通道保留供后续清理重试；保留启动失败与清理失败信息。
7. **漏极配置约束**：效率计算需要漏极数据的测试模式必须恰有一个有效漏极路由，且该路由必须是有效、已绑定的物理通道。第一版建议漏极必须属于 DUT 已启用通道；如果产品允许漏极仅测量而不供电，需另行定义读取/启用生命周期。
8. **保存边界**：参数页和电源页编辑同一份配置草稿，通过现有 coordinator/session 合并并统一保存、校验、创建运行和连接；不各自写文件。保存前按文档版本把关：1.0 编辑文档只读，须先经迁移器升级，authoring 不做隐式升级。
9. **旧配置兼容**：兼容读取旧角色字段，但不得把它用于推导上电顺序或漏极路由。只有旧配置显式记录的物理路由可直接保留；旧配置写着 drain 且能唯一映射到物理路由时，可迁移为漏极标记，0 条或多条一律标记为待确认并阻止相关运行，不按通道名猜测。

## 分阶段重构计划

每项均为可独立评审的小步骤。各步骤完成后先运行对应模块测试，再进入下一项；步骤 1 的契约和迁移规则是后续实现的依据。

### 阶段一：固定数据契约与基线

#### 步骤 1：盘点现有 schema、样例与实际效率输入

- **工作**：追踪效率公式实际使用的电压/电流字段、当前 DUT/driver 上电流程、run snapshot 格式和现有官方/历史配置样例。
- **执行策略**：从 `application/measurements/services.py`、`application/dto/amplifier_inputs.py`、配置 authoring、迁移器及 golden fixtures 对照数据流；记录漏极数据来源及公式要求。
- **技术决定**：漏极必须是显式 `SupplyChannel` 路由，不以角色键或 CH 名称作为身份；确认是否确实只用漏极电功率，还是仍依赖其他通道数据。
- **验收**：形成字段映射清单；新计划字段名、DUT/driver 分组、漏极约束与兼容行为均确定后再改生产代码。
- **产出**：[`docs/电源配置盘点与目标字段映射.md`](电源配置盘点与目标字段映射.md)（字段清单、样例清单、目标字段与兼容决定；§6 同时冻结步骤 2 的 v1.1 契约）。

#### 步骤 2：写明 schema 形状与版本策略（契约已冻结）

- **工作**：定稿配置字段，不实现 UI 和运行逻辑。
- **执行策略**：在配置契约文档中给出完整 JSON 示例、空计划行为、延迟单位/范围、漏极引用表达、旧配置转换示例。
- **技术决定**：运行映射按组保存 `power_plan: {power_sequence: [{supply_id, channel}], inter_channel_delay_s}`（DUT 为 `run_mapping.dut_power_plan`，驱放为 `run_mapping.driver_mode.power_plan`）；测试方案保存每路由参数 `channel_settings` 与 `drain_channel: {supply_id, channel}`；配置编辑段保存用户顺序与漏极。顺序只在编辑段可写，运行快照只冻结副本；1.1 不再写通道 `role`、`power_roles`、`power_channels`，旧角色仅在读取兼容层处理。
- **验收**：新旧 JSON round-trip 预期清晰，字段不存在双份顺序信息，无法自动安全迁移的配置有可定位状态/错误。
- **产出**：契约、完整示例、校验矩阵与迁移规则见 [`docs/电源配置盘点与目标字段映射.md`](电源配置盘点与目标字段映射.md) §6；版本轴/常量来源/逐入口判据/1.0 写入门槛见 §6.11，round-trip 预期见 §6.1.2，旧配置前后转换片段见 §6.14.1–§6.14.2。

### 阶段二：先改纯配置模型与校验

#### 步骤 3：移除 Draft 中通道角色字段

- **工作**：调整 `PowerChannelDraft` 及解析/序列化。
- **执行策略**：先支持旧输入中存在 `role` 时忽略该字段，写出时不输出；电压、电流和保护参数行为保持不变。
- **技术决定**：漏极不是 `PowerChannelDraft.role`，而是独立的路由引用字段，后续单独加入运行/配置计划模型。
- **验收**：Draft 测试覆盖新字段 round-trip、旧 role 被忽略、数值字段不回归。

#### 步骤 4：增加有序通道计划值对象

- **工作**：在 application/domain 中表达有序启用路由、组间隔和漏极路由。
- **执行策略**：新增不可变 DTO/value object；不在 Qt 控件或裸字典中实现业务校验。
- **技术决定**：路由列表顺序就是上电顺序；拒绝重复 `supply_id/channel`；延迟为有限非负秒数；漏极必须引用配置中存在的通道。运行是否强制漏极属于 DUT 测试校验，不强加到无效率计算的场景。
- **验收**：单元测试覆盖顺序保留、重复/非法路由、延迟边界、漏极不存在和可选性。

#### 步骤 5：删除供电角色校验，保留引用及漏极校验（已完成）

- **工作**：改造 `domain/configuration/rules.py`、`domain/configuration/models.py` 和 `ConfigurationAuthoringService.validate_document`。
- **执行策略**：移除 `validate_power_channel_roles`、`POWER_CHANNEL_ROLES`、角色唯一性与 gate/drain 成对完整性规则；按新计划校验绑定、电源引用、通道存在、重复物理路由和 DUT/driver 冲突。
- **技术决定**：漏极唯一性是测量数据约束，不是上电角色规则；错误路径指向 `drain_channel` 或具体计划项。保留设备绑定角色校验。计划对象必须同时包含 `power_sequence` 与 `inter_channel_delay_s`；缺键按形状错误报告，不以空序列或 `0.0` 补全。
- **验收**：无 role 的通道配置可通过角色相关检查；非法引用/重复路由仍失败；要求效率计算的模式缺少漏极时明确失败。

#### 步骤 6：改造 authoring 与运行快照生成（已完成）

- **工作**：改造 `application/configuration_authoring.py` 和 configuration model 序列化。
- **执行策略**：将用户显式选择的路由、顺序、间隔及漏极引用原样生成到正式计划和 run snapshot；删除 `DUT_CHANNEL_ROLES` 推导及 role-keyed `power_roles` 输出。authoring 同时是版本门禁：输入为 1.0 或其他非当前版本时拒绝保存（路径 `schema_version`），旧配置只能先经迁移器升级。
- **技术决定**：authoring 不推断角色/顺序，也不承担 1.0→1.1 的字段转换；旧身份、参数与漏极只由迁移器处理（§6.14）。漏极只通过独立字段序列化。快照冻结上电顺序和漏极路由，确保后续配置编辑不改变已创建运行。
- **验收**：golden fixture 更新；测试断言新 snapshot 不含通道角色字段且顺序稳定；1.0 输入被拒绝保存、成功迁移后的 1.1 输入按当前版本重写。

### 阶段三：让硬件运行服从用户计划

#### 步骤 7：调整测量输入 DTO 与通道参数寻址（已完成）

- **工作**：改造 `application/dto/amplifier_inputs.py`，把 role-to-channel dict 改为有序路由计划；为每条物理路由关联电压/电流设定。
- **执行策略**：保持 DTO 不可变；测量服务只消费经过校验的计划，不再解析角色名。
- **技术决定**：采集结果以稳定物理路由 token（如 `supply_id/channel`）标识；漏极数据通过 drain route 精确选择，其他已启用通道仍可采集并参与全通道汇总时必须有明确定义。
- **验收**：DTO 测试覆盖多个电源、任意顺序、漏极路由定位和缺失设置。

#### 步骤 8：按顺序上电并实现失败清理（已完成）

- **工作**：改造 `instrument/measurement_adapter.py` 与电源编排接口。
- **执行策略**：按序逐通道 set output；成功后按组间隔等待；追踪已尝试项（命令发出即视为可能已有输出）；失败停止后续并逆序关闭已尝试项。关断逐项尝试并汇总错误，未确认关闭的通道保留重试。
- **技术决定**：延迟由可注入 sleep/clock 执行，便于确定性测试；取消检查放在等待前后及每次通道操作边界；不得把“角色顺序”留在硬件适配层。
- **验收**：fake PSU 测试断言调用顺序、等待位置、失败停止、取消与逆序清理；一次关断失败仍继续关闭剩余通道。
- **实现补充**：上电失败使用 `PowerOnControlError`（测量类别）保留启动失败与回滚失败；失败通道本身也进入逆序回滚（设备可能已执行上电但响应丢失），关断失败的通道保留在 `remaining_channels` 供后续重试。关断超时贯穿到每个通道；取消清理失败以 `cleanup_failures_of()` 可读的结构化属性附加到原取消异常；驱动功放与 DUT 两组按全局上电顺序逆序收尾（先 DUT、后驱放，组内再逆序）。`PowerGroupPlan` 是适配器唯一输入，已移除 `{slot: token}` 过渡入口。

#### 步骤 9：移除 Session/Simulation 的 gate-drain 固定逻辑（已完成）

- **工作**：改造 `instrument/session.py`、`instrument/simulation.py`、测试 doubles 和相关端口调用。
- **执行策略**：session 接收物理通道序列或由 adapter 管理逐通道输出，不再接收 `roles`/gate/drain 参数；保留资源连接、RF 关闭和清理生命周期。
- **技术决定**：安全关闭对象以“本次已尝试/成功的物理通道集合”为依据，不通过 role 反查；历史兼容包装只在明确必要时短期保留，并不得恢复固定角色顺序。
- **验收**：session/simulation 状态测试通过；搜索确认生产调用不再传 `power_on(roles=...)`。
- **实现摘要**：`ManagedInstrumentSession` 的通道参数改为有序物理 token 序列，`power_on`/`power_off` 接收显式序列，按本次已尝试（命令发出即可能已有输出）的通道逆序关断；上电失败时失败通道也回滚，未确认关闭的通道保留并可由 `close()`/后续 `power_off()` 重试。`mark_powered(channels=...)` 把适配器按计划操作过的物理通道登记进会话，`end_stage()` 不再依赖适配器内部状态。`measurement_factory` 直接把 `power_routing` 生成的 `PowerGroupPlan` 传给适配器，装配计划不再携带 role→token 映射；`simulation.py` 删除未使用的 `_LegacySafetyInstrumentSession`；`instrument/flow/power_on_flow.py`、`power_off_flow.py` 是未被生产调用的重复角色流程，已随旧入口删除。适配器不再接受 `dut_power_channels` / `driver_power_channels` 过渡参数，生产与测试只使用计划。

#### 步骤 10：让效率计算只读用户指定漏极（已完成）

- **工作**：调整测量计算输入和结果字段。
- **执行策略**：从冻结 run snapshot 获取 drain route，从该物理通道的测量值读取漏极电压/电流并计算所需直流功率；其他通道数据按现有结果兼容策略保存。
- **技术决定**：漏极标签本身不触发/改变上电；该路由若未启用则按步骤 1/2 定下的约束在连接前拒绝，不运行中静默补开。若公式使用多路功率，明确列出纳入集合及单位。
- **验收**：测试将漏极设为非 CH1 通道并验证计算选中正确读数；更换上电顺序不改变效率输入路由。
- **实现摘要**：`AmplifierMeasurementService` 构造时要求 `inputs.drain_channel` 已配置，缺失时抛 `AmplifierInputError`（配置类别），不把 `dc_power` 静默算成 0；`perform_power_sweep` 仍按上电计划逐通道读取全部 DUT 通道并写入 `voltages` / `currents`，但 `dc_power` 只取漏极的 V×I，效率公式与 `efficiency` / `efficiency_percent` 字段名不变。漏极选择比较 `SupplyChannel` 物理路由对象，**不用**结果键反推：路由两段都允许下划线，`PS_1/CH1` 与 `PS/1_CH1` 会拼出同一个历史结果键，按键取值可能读到错误通道。漏极只从冻结的 `test_plan.drain_channel` 读取，不参与上电、间隔或关断；非漏极通道数据继续按原键名入库（历史拼接键的碰撞语义保持不变）。`tests/test_measurement_loop_regression.py` 的 `DrainEfficiencyTests` 覆盖非 CH1 漏极（CH2）选中、交换上电顺序不改变效率输入、拼接键碰撞时仍按物理路由取数、切换漏极不改变电源生命周期（设置/上电/等待/关断）以及缺漏极拒绝。

### 阶段四：拆出页面并接入统一会话

#### 步骤 11：抽离电源表单状态与控件构建（已完成）

- **工作**：从 `ConfigurationPage` 拆出电源控件的构建/读写状态，复用现有 `config_power_section.py` 与 `ConfigurationFormAdapter` 的边界。
- **执行策略**：先让电源 UI 由独立组件构建，但暂不改页面导航；增加顺序编辑和间隔、漏极通道选择控件。
- **技术决定**：电源参数、启用选择、排序、间隔和漏极标记分别读写到各自字段；绑定变更重建控件时保留未提交编辑。
- **验收**：纯 UI 测试覆盖列表排序、启用开关、漏极选择、表单回填和重建保留。
- **实现摘要**：`config_power_section.py` 新增 `PowerFormSection`（独立电源表单）与 `PowerPlanEditor`（勾选 + 上移/下移 + 组间隔 + 状态行），页面只把组件放进右栏并转发 PA 单元数量/驱放供电方式；同名电源控件保留为页面只读属性，现有调用点不变。组计划写入 `power_supply_assignment.<group>.power_plan`，漏极写入 `dut_config.drain_channel`。**分配与计划分工**：`supplies.<slot>.channel` 仍是该 PA 单元声明的通道集合，计划只决定它们的启用/顺序/间隔，二者集合是否相等由 `validate_power_plan` 比较；计划候选也只来自各槽位声明的通道，同一台电源供两个 PA 单元时不会互相复制通道。漏极候选在计划已配置时只取计划中的 DUT 通道，未配置时退回分配通道；旧漏极失效时保留为“（无效）”项交给正式校验。`ConfigurationFormAdapter` 在回填时把计划与漏极交给组件，`ConfigFormState` 从计划控件读取序列、间隔与漏极，分配写出只含 `supply_id`（不再写过渡别名 `name`）。丢弃旧通道 `role` 控件、投影分支与类型声明。测试见 `tests/ui/test_power_form_section.py` 及更新后的页面/投影/草稿测试。

#### 步骤 12：创建独立 PowerConfigurationPage（已完成）

- **工作**：增加 `presentation/qt/power_configuration_page.py`，把电源参数、分配和上电计划移入该页。
- **执行策略**：新页通过窄接口向 coordinator/session 提交表单片段，不导入基础设施或硬件模块；原 ConfigurationPage 移除电源控件责任。
- **技术决定**：漏极选择只能从有效 DUT 物理通道中选；明确显示“漏极仅用于效率测量，不影响上电顺序”。
- **验收**：新页面独立创建、绑定状态展示、driver 模式变化和校验消息均有 UI 测试。
- **实现摘要**：新增 `PowerConfigurationPage`（`PageControllerBindingMixin` + `QWidget`），页面自己持有 `PowerFormSection`、设备绑定状态行、PA 单元可见性与整个电源片段读写；`build_fragment()` 只交出 `instruments.power_supplies`、`power_supply_assignment`、`dut_config.drain_channel` 与 `driver_mode.power_source`，`build_config(base)` 把这些字段合并进共享基线，`apply_config()` 只回填这些字段并保留未提交的通道参数/顺序/间隔/漏极。`ConfigFormState` 新增 `read_power_fragment`、`build_power_config`、`power_validation_errors`，`config_projection` 新增 `project_power_config` / `reset_power_controls`，`ConfigurationFormAdapter` 新增电源片段读写与投影入口；校验仍只调用应用边界的正式 authoring/domain 规则。`ConfigurationPage` 删除电源控件、电源分配、计划/漏极、PA 单元派生可见性和电源选项刷新，改为单列测试参数 + 运行区，保存/回填仍保留基线中的电源字段（统一合并由步骤 13 接线）。页面全程不导入 `infrastructure`、`instrument` 或硬件模块。UI 测试见 `tests/ui/test_power_configuration_page.py`；`tests/ui/test_config_page.py`、`test_config_power_section.py` 与仓库门禁同步改为“参数页不再拥有电源控件”。导航、共享草稿、dirty 汇总及绑定回写后两页同时刷新由步骤 13 完成。

#### 步骤 13：接入导航、dirty 与统一保存（已完成）

- **工作**：更新 `main_window.py`、`pages.py`、协调器/page protocol、配置会话和返回路径。
- **执行策略**：页面切换共享一份编辑草稿；最终动作仍由统一入口执行校验、保存、冻结运行与连接；仪器发现页绑定回写后两个配置页都刷新且保留脏数据。
- **技术决定**：独立页面不拥有独立保存文件或互相持有具体页面实例；dirty 状态由共享会话/视图模型汇总。打开 1.0 编辑文档时只读并提示先迁移；保存路径不做隐式升级（§6.1.2、§6.11.3）。调整状态面板可见性以覆盖新的页面位置。
- **验收**：集成测试验证两页往返、应用设备绑定、driver mode 切换、未保存修改保留、一次最终提交写入整份配置。
- **实现摘要**：新增 `presentation/qt/configuration_editor.py`（`ConfigurationEditor`）作为两页的共享装配器：只依赖页面窄接口，负责 `apply_config` / `set_test_mode` / `is_dirty` / `mark_clean` / `set_finalizing` 的统一转发，并连接“PA 单元数量”与“设备绑定写回”两个跨页派生事件；窗口只创建页面并把它们交给编辑器，页面之间不互相持有实例。`pages.py` 新增 `power_configuration` 页签（标题“电源配置”）与 `PageContext.build_power_configuration`；`main_window.py` 使用编辑器完成模式切换、返回欢迎页 dirty 判断、保存后清理与最终动作禁用，状态面板在参数页和电源页都隐藏。`ApplicationCoordinator` 新增 `PowerConfigurationPagePort` 与 `bind_power_page()`：`build_configuration_from_ui()` 按“参数页 → 电源页”合并片段，`validate_configuration()` 先合成唯一草稿再让两页校验，`apply_run_configuration()` 同时回填两页，最终保存成功后两页一起标记干净。正式校验按页面归属拆分：`application.configuration_authoring` 新增 `validate_power_document` / `validate_parameter_document` 与 `is_power_validation_issue()`，参数页只报测试参数与设备连接等非电源问题，电源页只报通道参数、供电分配、上电计划与漏极；两页合起来仍是完整校验，不会把测试频率故障写成“电源配置校验失败”。两页回填由 `configuration_editor.apply_config_to_pages()` 统一执行：先取两页快照再逐页回填，任一页抛出 `ConfigBackfillError` 时恢复已回填的页面，运行快照回填也走同一入口，不留下半新半旧的界面。电源页补上通道电压/电流/保护值的 `fragment_changed` 通知与重建后重连，回填/重建期间静默；`set_test_mode()` 不再清 dirty 基线。**1.0 只读门禁**：`ConfigurationAuthoringService.save_block_reason()` 复用保存时的版本门禁给出原因，协调器在加载/回填/保存后把它同步到两页；两页显示只读提示、禁用参数/电源表单与保存、最终动作入口，保留返回欢迎页与加载运行。集成/UI 测试覆盖两页往返保留未保存修改、一次保存写入整份配置、设备绑定刷新电源页并保留未提交的通道/计划/漏极编辑、driver mode 同步、校验错误归属、回填失败整体回滚，以及 1.0 文档打开后两页只读且两个写入口都被禁用。

## 风险控制

- **漏极误迁移**：不猜通道名；迁移不确定时禁止相关测量运行，用户确认后再生成正式快照。
- **页面拆分丢编辑**：新旧 UI 转换期间以共享 draft 为唯一数据源，绑定变更和页面重建均测试编辑保留。
- **部分上电留下输出**：记录成功启用路由，失败与取消路径都执行逆序 best-effort 关断，继续尝试其余通道并报告全部失败。
- **新旧结构混写**：Authoring 统一生成新结构；兼容读取与新格式写入分离，golden 测试禁止新快照重新输出旧角色结构。
