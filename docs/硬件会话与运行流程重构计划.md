# 硬件会话与运行流程重构计划（先配置，最后确认连接）

## 0. 本次修订

上一版把“连接仪器”提前到配置之前，引入独立 `HardwareSession` 与一整套会话契约。本次回到现有流程的先后关系：**发现并勾选设备 → 下一步 → 配置全部参数 → 创建运行并在同一步确认连接 → 测量**。修订理由三条：

1. **配置不依赖硬件在线。** 电源分配、通道角色、电压/电流/保护值都来自已应用的设备绑定与设备表声明的通道，配置阶段不需要一个活着的会话。
2. **连接先行的收益只有一个：配置前就知道连不上。** 代价却是与运行无关的会话生命周期、会话与可变配置的兼容校验，以及“已创建未连接”状态的退出删除策略。配置本身可保存、可重试，一次失败重做的代价是再点一次最终动作。
3. **“查到设备就能连上”不是事实，也不能当作省掉检查的理由。** 探测与连接不是同一条通道，连接阶段还做型号与输出检查（见第 4 节）。这一点不改变流程顺序，但必须由计划补上。

| 上一版主张 | 本次结论 | 原因 |
|---|---|---|
| 连接先行，配置在已连接的会话上进行 | 取消 | 见上；连接改为运行最终化事务的组成部分 |
| `HardwareSession` 作为一等契约与独立入口 | 取消 | 资源所有权已经落在 `ManagedInstrumentSession` / `_VisaSession`，`PortMeasurementAdapter` 只负责路由，缺的只是“阶段之间复用”的状态转换 |
| “已创建未连接”是常态，退出时统一删除未测量运行 | 收窄 | 连接失败就地补偿撤销；退出策略只覆盖“已连接但从未开始测量” |
| 会话与运行分离、按运行重建适配器 | 取消 | 运行创建后不再允许改配置，适配器只在提交时构造一次 |
| `connection_address` 视为可达性证据 | 修正 | 绑定应用时补一次可达性确认；探测地址与连接地址的差异写进文档与测试 |

## 1. 目标与产品决策

1. 保持现有步骤顺序：仪表配置页（发现/勾选）→ 下一步 → 仪器配置页（全部参数）→ 唯一最终动作（创建运行 + 确认连接）→ 测量区。
2. 连接确认是进入测量前的最后一道门，发生在“创建运行”的同一次事务中；失败不提交运行，界面停在配置页可重试。
3. `prepared_run` 一旦提交，即表示本次运行已完成连接确认。失去端口是后续事件（清理失败、设备掉线），运行保留并显示为“需重新连接”。
4. 每个测量阶段结束执行 RF 关闭与相关电源关闭，但**不关闭 VISA 资源**；阶段之间复用同一个端口。
5. 用户放弃 / 正常退出：先完成硬件安全关闭，再撤销“从未开始测量”的当前运行；已进入测量阶段的运行保留。
6. 崩溃/强杀不承诺清理，运行目录保留，首期不做启动时自动删除。
7. 可达性确认放在“下一步”，只做 `open_resource` + `*IDN?` + `close`；它不是连接确认，也不替代连接确认（见 5.1、步骤 2.1）。
8. 最终动作合并为一个按钮。仪表配置页的“连接仪器”按钮与其转发链整体删除，连接确认归入最终动作，同一入口在“需重新连接”状态下承担重连。

## 2. 设计结论

- **顺序固定**：连接只在运行冻结之后发生。`connect_instruments(prepared_run)` 继续是唯一生产连接入口，只接受运行契约对象、不接受任何配置路径，硬件配置取自 `runs/<run_id>/inputs/hardware_config.json`。
- **单一连接入口**：端口只由 `ApplicationCoordinator` 持有与释放；页面只发一个“完成配置”的用户意图信号，不直接调用连接工厂，也不持有端口。
- **两阶段提交**：校验并保存配置 → 释放旧端口 → 冻结新运行（pending）→ 后台连接确认 → 全部成功才同时提交 `prepared_run`、端口、运行状态文字；任何一步失败都不改动当前已提交的运行。
- **失败补偿**：连接确认失败时对新冻结的运行调用 `discard_run()`（事务内补偿，不是用户可触发的删除），旧运行与旧状态不变。
- **连接只读**：连接确认只发送 `*IDN?` 与逐通道 `OUTP?`，不写设定值、不打开输出；发现输出已开就整次失败，交给操作者现场处理。
- **阶段复用**：安全关闭与资源释放在语义上分开。每阶段安全清理由 `SafetyCleanupAdapter` 完成（`release_resources=False`）；VISA 资源只在放弃、退出或清理失败时关闭。
- **未测量运行撤销**：只在两个入口发生——最终化事务的补偿，以及放弃/退出时对“当前运行且 manifest 显示未开始”的守卫式撤销。

## 3. 术语与边界

| 名称 | 含义 | 生命周期 |
|---|---|---|
| 设备发现结果 | 扫描读到的身份、地址、角色与卡片状态 | 单次扫描；不占用硬件资源 |
| 设备绑定 | 用户选定的设备集合及其地址/身份，由 `ApplyDeviceSelectionRequest` 整批写入 | 写入配置页内存；保存配置时落盘 |
| 可达性确认 | 对已选绑定逐台执行 VISA `open_resource` + `*IDN?` + `close`，不保留资源 | 一次绑定应用；不产生会话、不创建运行 |
| PreparedRun | 完整测量配置、运行目录与硬件快照组成的正式运行契约 | 完整配置通过校验并完成连接确认后提交；开始测量后保留审计 |
| 端口（MeasurementPort） | `PortMeasurementAdapter`，持有 `ManagedInstrumentSession` 与本运行的路由/设定投影 | 提交时构造；阶段间复用；放弃/退出/清理失败时关闭 |
| 未开始测量 | manifest 为 `RunStatus.CREATED` 且没有任何阶段离开 `StageStatus.PENDING` | 撤销守卫的唯一判据 |

职责边界：`instrument` 定义装配计划、会话与安全流程；`app` 是生产装配入口；`application` 持有运行创建、未测量运行撤销等用例与端口；`presentation/qt` 编排用户动作、导航、状态展示，不直接创建 VISA 资源。

## 5. 目标流程与失败语义

### 5.1 流程

1. 欢迎页选测试模式 → 仪表配置页。
2. 查找设备 → 勾选 → **下一步**：`apply_selection` 整批写入绑定 → **可达性确认**（逐台 VISA open + `*IDN?` + close）→ 全部可达才进入仪器配置页。
3. 仪器配置页：编辑全部参数，包括电源分配、通道角色、电压/电流/保护值与测试参数。此时没有任何 VISA 资源被持有。
4. **完成配置并连接仪器**（唯一最终动作）：页面校验 → 保存配置 → 释放旧端口 → 冻结新运行（pending）→ 后台连接确认（打开设备、电源身份、全部声明通道输出检查）→ 一次性提交运行、端口与状态文字。
5. 测量区：每个测量阶段都要求 `prepared_run` 且端口存在。
6. 阶段结束：RF 关闭 + 相关电源关闭，端口保留；下一阶段直接复用。
7. 放弃 / 退出：停止测量并等待 worker → 关闭端口（安全清理）→ 按守卫撤销未开始测量的当前运行 → 释放页面资源。

### 5.2 状态

| 状态 | 进入条件 | 允许动作 | 资源所有者 |
|---|---|---|---|
| 未绑定 | 无可用设备绑定 | 扫描、勾选、返回欢迎页 | 无 |
| 已绑定未配置 | 绑定已应用且可达性确认通过 | 编辑参数、保存、完成配置、上一步 | 无硬件资源 |
| 已连接 | `prepared_run` 与端口同时提交 | 进入测量、放弃、退出 | 协调器 |
| 测量中 | controller 处于活动状态 | 停止/取消、紧急停止 | 协调器（测量线程只借用） |
| 需重新连接 | 端口被关闭但运行保留（清理失败、设备异常、重连失败） | 重新连接、放弃、退出（不删除运行） | 无端口，运行保留 |
| 已放弃 | 放弃用例完成 | 返回欢迎页 | 无 |

### 5.3 失败矩阵

| 失败点 | 已提交的东西 | 用户可见 | 可重试动作 |
|---|---|---|---|
| 绑定应用被拒 | 无 | 面板状态行 + `validation_failed` | 重新勾选或扫描 |
| 可达性确认失败 | 绑定已写入页面内存（配置未保存） | 逐台地址与原因 | 重试确认、重新扫描；停在仪表配置页 |
| 配置校验失败 | 无 | 页面错误汇总 | 修正参数 |
| 配置保存失败 | 无（运行未创建） | “创建运行失败：配置保存失败” | 重试最终动作 |
| 旧端口释放失败 | 旧运行与旧端口引用保留 | “上一次连接的仪器未能完成安全清理” | 现场确认后重试 |
| 冻结运行失败 | 无 | “创建运行失败：<原因>” | 重试最终动作 |
| 连接确认失败（打开/身份/输出/协议） | 刚冻结的运行 | 逐台原因 + “运行未生效” | 自动撤销刚创建运行；重试最终动作 |
| 补偿撤销失败 | 刚创建的运行目录 | 明确告知运行目录位置与清理失败 | 人工处理；禁止继续测量 |
| 阶段安全清理失败 | 运行与已完成结果 | 安全清理错误 + “需重新连接” | 关闭端口；人工确认后重连 |
| 退出时关闭失败 | 运行保留 | 二次确认对话框（可能仍有输出） | 人工确认 |

## 6. 阶段一：冻结目标契约与行为基线

### 步骤 1.1：登记流程、状态与失败语义

**执行策略**

- 更新《配置编辑行为基线》“创建运行”一行：改为“完成配置并连接”，成功输出是“新运行目录 + 已连接端口 + 状态文字”，失败提示按 5.3 的失败矩阵分列。
- 在《无运行契约调用方清单》登记两处新调用点：协调器的最终化事务（创建 pending 运行后连接）与未测量运行撤销（守卫式 `discard_run`）。二者都只消费运行契约，不新增连接旁路。
- 固定不变量：**提交 `prepared_run` 的时刻，端口已存在且已完成连接确认**；`requires measurement` 的页面在端口缺失时只提示“重新连接”，不自行打开设备。

**技术决定**

- 不新增“运行之前的会话”契约，也不让 `connect_instruments()` 接受可选运行对象。
- `has_run_contract()` 与 `PreparedRun` 判据不变；本次只新增最终化事务与撤销用例，不放宽任何既有判据。

**完成标准**：5.2 与 5.3 的每一行都能映射到唯一入口与唯一失败处理；文档、API 清单与门禁的更新项已列明。

### 步骤 1.2：调用清单

**执行策略**

- 以现有入口为锚点记录调用图：`ConnectionPage.request_next` → `DeviceBindingPort.apply_selection` → `MainWindow._open_configuration_page`；`ConfigPage.request_create_run` → `ApplicationCoordinator.create_prepared_run` → `prepare_configuration` → `InstrumentWorker` → `connect_instruments` → `create_measurement_port` → `PortMeasurementAdapter`。
- 记录每条电源信息的来源：绑定地址/身份、声明通道、角色、分配、设定值、保护值、急停序列。
- 列出所有释放端口或重建运行的入口：`release_instrument_for_new_run`、`release_instrument_port`、`release_port_after_measurement`、`accept_instrument_controller`、`MainWindow.closeEvent`、`MainWindow._return_to_welcome`。

**完成标准**：清单可映射到代码符号；实施单个步骤时不需要跨层探索。

## 7. 阶段二：把“连接确认”做成一步可测的硬件动作

### 步骤 2.1：绑定边界的可达性确认

**执行策略**

- 新增 `instrument/reachability.py`：`probe_addresses(addresses) -> tuple[ReachabilityResult, ...]`，逐台 `open_resource` → `*IDN?` → `close`，异常收敛为逐台结果；不写任何设定、不做通道检查、不保留资源。
- 生产装配入口放在 `app/gui_runtime.py`（`probe_instrument_addresses`）；Qt 侧新增 `ReachabilityWorker`，在“下一步”应用绑定成功后运行，成功才切页。
- 新增公开方法 `ConnectionPage.begin_reachability_check()` / `finish_reachability_check(results)`：检查期间禁用查找设备、卡片选择与“下一步”，禁止改变输入绑定。
- 失败留在仪表配置页并逐台显示地址与原因，不进入配置页。

**技术决定**

- 这一步存在的唯一理由：探测（raw socket）与连接（VXI-11）不是同一条通道；它把“查到”升级为“能连”，并顺带确认 VISA 运行时可用。
- **它不能替代连接确认**：只发 `*IDN?`、不做型号核对、不做 `OUTP?`、不保留资源；阶段三（第 8 节）的连接确认仍然是唯一决定“能不能测”的门。测试必须锁定这一点（命令只有 `*IDN?`，检查结束后资源关闭）。
- 它**不是**会话，也不冻结任何东西；检查结果只用于决定是否允许进入配置页，不写进配置或运行快照。
- 这次检查让仪表配置页原有的“连接仪器（测试连接）”按钮失去存在意义：该按钮在创建运行前必然失败，其转发链随步骤 5.1 一并删除。
- 若现场连续确认 VXI-11 对所有设备都可用，按证据删除本步骤（只删一个入口、一个 worker 与一组测试），不得保留成运行时开关。

**完成标准**：假 VISA 测试覆盖全部可达、单台失败、全部失败、异常与超时，并断言命令序列只有 `*IDN?`、结束后资源已关闭；检查期间界面无第二入口；失败不遗留任何资源。

### 步骤 2.2：连接确认的结果与错误分类

**执行策略**

- 保持 `_create_hardware_measurement_port` 的命令顺序与失败分类，补充一条结构化连接结果（每台设备：地址、身份原文、身份核对结论；每台电源：被检查的通道与结论），由协调器写进运行状态文字与日志。
- 明确三类失败互不冒充：`DeviceConnectionError`（打不开）、`DeviceCapabilityError`（型号不符或输出已开）、`ProtocolError`（查询失败）。界面按类别给不同下一步建议。

**技术决定**

- 连接确认继续只发只读命令；不得为了“通过检查”主动关闭已开启的输出。
- 失败时按逆序关闭已打开资源与 ResourceManager（现有行为），补偿撤销由协调器负责，不在 `instrument` 里删运行。

**完成标准**：`instrument` 单测锁定命令顺序、检查范围（每台电源的全部声明通道）与逆序清理；失败类别可被界面区分。

### 步骤 2.3：不拆分会话与适配器

**执行策略**

- 保留现有结构：`_VisaSession` / `ManagedInstrumentSession` 拥有资源，`PortMeasurementAdapter` 只做路由、设定与安全动作。本次不引入独立的 `HardwareSession` 公开类型。
- 为阶段复用补一个明确的会话转换（见步骤 11.1），而不是靠重建适配器绕过状态机。

**完成标准**：所有权注释与测试说明一致：“适配器关闭 == 会话关闭 == 资源释放”，且没有任何第二个关闭资源的路径。

## 8. 阶段三：运行最终化事务

### 步骤 3.1：协调器实现两阶段提交

**执行策略**

- 把 `ApplicationCoordinator.create_prepared_run` 改为 `finalize_configuration()`，流程固定为：
  1. 页面校验（`validate()`）并 `update_configuration_from_ui()`；
  2. `save_configuration()`，失败即返回，不创建运行；
  3. `release_instrument_for_new_run()`，失败即返回（不新建运行，旧运行与旧引用保留）；
  4. `prepare_configuration(..., hardware_config=self.config)` 冻结新运行，保存在 `self._pending_run`，**不切换** `prepared_run`；
  5. 用 `_pending_run` 启动 `InstrumentWorker`。
- `accept_instrument_controller(controller)` 提交：`prepared_run = _pending_run`、清空 pending、注入端口、更新运行状态文字；失败时按 5.3 处理，不提交。
- 连接失败或停止（`on_instrument_error` / `on_instrument_stopped`）时，协调器新增 `abort_pending_finalization()`：安全关闭仍可能存在的端口引用 → 对待提交运行调用未测量撤销用例（步骤 9.1）→ 清空 pending，保持旧 `prepared_run` 不变。
- 保留“重新连接”入口 `reconnect_instruments()`：仅在已有 `prepared_run` 且端口为空时可用，复用同一个 `InstrumentWorker`，成功只提交端口。

**技术决定**

- 运行先冻结、后连接：这是既有契约（连接只来自冻结快照）的必然顺序；因此失败补偿必须显式，而不是把顺序反过来。
- 页面不感知 pending：`ConfigPagePort` 仍只有 5 个能力，运行状态文字由协调器写入。
- 新增的 `finalize_configuration()` 是唯一能产生新运行的入口；删除旧方法，避免出现能绕开连接确认的第二条路径。

**完成标准**：每个失败点都有可重复的失败测试，且失败后 `prepared_run`、端口、运行状态文字三者不出现半提交。

### 步骤 3.2：运行状态文字与重连状态

**执行策略**

- `run_status_text()` 扩展为四种：未创建 / 已创建并已连接（运行 ID）/ 需重新连接（运行 ID + 原因）/ 不可用（契约失效）。
- `resolve_measurement_run()` 的两条失败提示改为指向配置页的最终动作：“请先完成配置并连接仪器” / “端口已释放，请在仪器配置页重新连接”。

**完成标准**：测量页在两种缺失条件下都只提示、不打开设备；状态文字不含歧义。

## 9. 阶段四：未开始测量的运行撤销

### 步骤 9.1：增加守卫式撤销用例

**执行策略**

- 在 `application` 新增 `discard_unstarted_run(run_repository, run_id)`：读取 manifest，只有 `status is RunStatus.CREATED` 且所有阶段仍为 `StageStatus.PENDING` 时才调用 `discard_run()`；其他状态返回拒绝原因，不删除。
- 仓储层的 `discard_run()` 保持现状（补偿语义），守卫只加在应用用例里；两个入口都必须经这个用例。

**技术决定**

- 判据只认 manifest，不按目录名、时间或内存变量猜测。
- 目录缺失按幂等成功处理；仓储错误原样上抛，不得吞掉。

**完成标准**：已开始/已完成/已失败的运行无法被删除；缺目录幂等；失败补偿与退出撤销共用同一实现。

### 步骤 9.2：接入两个入口

**执行策略**

- 最终化事务补偿：连接确认失败后撤销刚冻结的运行（步骤 3.1）。
- 放弃/退出：当前运行未开始测量时撤销；已进入测量阶段（运行状态或任一阶段离开 `PENDING`）时保留，并在日志说明原因。

**完成标准**：业务入口无法删除已测量运行；撤销失败时不关闭对话框也不假装成功。

## 10. 阶段五：页面与导航

### 步骤 5.1：仪表配置页只留“下一步”

**执行策略**

- 整体删除“连接仪器”按钮与其转发链：
  - `ConnectionPage`：`connect_btn`、`connect_requested` 信号与 `_build_connect_button()`（该按钮由 Python 构造，`.ui` 里只有“返回欢迎页 / 下一步”两个页面动作，不受影响）；
  - `MainWindow`：`connection_page.connect_requested → configuration_session.request_connect` 接线、`_set_connect_enabled` 及其对连接页按钮的引用；`connect_instruments()` 槽改名为最终动作的启动槽（步骤 3.1 的 `finalize_configuration()` / `reconnect_instruments()`）；
  - `ConfigurationSession.request_connect` 与 `ConfigurationBindingTarget.request_connect`；
  - `ConfigPage.request_connect` 与 `connect_requested`。
- 仪表配置页只保留：查找设备、卡片勾选、返回欢迎页、下一步。
- 按钮消失后，旧按钮承担的“测试连接”语义由“下一步”的可达性确认（步骤 2.1）与最终动作里的连接确认（步骤 3.1）分别承担；**不要**把 `app.gui_runtime.connect_instruments` 一起删掉，它是最终化事务的连接实现。

**技术决定**

- “连接入口只有一个”的约束从“位置在仪表配置页”改为“唯一入口是协调器的最终化事务”；页面不持有端口、不调用连接工厂。
- 忙碌状态改为由最终动作驱动：连接确认进行中禁用最终动作与回退动作，而不是禁用连接页按钮。

**完成标准**：`grep` 在生产代码中找不到 `connect_btn` / `request_connect` / `connect_requested`（配置页与连接页）；仪表配置页无法在未创建运行时触发连接；相关 UI 测试、《配置编辑行为基线》《设备发现MVP》与 `README` 的步骤说明同步更新。

### 步骤 5.2：配置页成为最终动作的落点

**执行策略**

- 配置页新增页面级动作 `finalize_run_requested`（按钮文案“完成配置并连接仪器”），由窗口转给 `coordinator.finalize_configuration()`；页面只发意图，不连接、不持有端口。
- 同一入口在“需重新连接”状态下承担重连：窗口根据 `coordinator.run_status` 决定按钮文案与动作（完成配置 / 重新连接），页面只渲染传入的文案。
- 运行状态、连接中状态、失败原因、运行 ID 都在当前页可见；连接中禁用最终动作与“上一步/返回欢迎页”。
- 保留“保存配置”与“加载运行”；加载运行前后若有端口，按现有 `release_instrument_for_new_run()` 释放。

**技术决定**

- 配置页不增加连接相关能力到 `ConfigurationPagePort`；重连是协调器行为，窗口只做信号转发。
- “上一步：仪表配置”在已连接状态下禁止回退（会改变设备集合）；未连接时可回退，回退前不释放资源（此时没有资源）。

**完成标准**：连接成功后无法返回更改设备集合；参数与分配可编辑；最终动作失败可原地重试。

### 步骤 5.3：放弃与退出

**执行策略**

- `MainWindow._return_to_welcome` 改为“放弃本次配置”：确认 → 停止 worker → 关闭端口 → 撤销未开始测量的运行 → 清空运行状态 → 回欢迎页。多个分支不再各自删目录。
- `closeEvent` 顺序固定为：停止测量（若活动）→ 等待连接 worker → 关闭端口（安全检查）→ 未测量运行撤销 → 释放页面资源。清理未完成时保留运行与未决端口引用，并用现有二次确认提示风险。

**完成标准**：放弃与退出共用一条用例；任何已启动测量的运行都不被删除；线程未停止时不释放其资源。

## 11. 阶段六：阶段间复用与安全清理

### 步骤 11.1：会话支持“阶段完成回到可复用状态”

**执行策略**

- 在 `ManagedInstrumentSession` 增加显式转换 `end_stage()`（`MEASURING`/`POWERED` → `PREPARED`），只在安全清理记录为“RF 已关闭、电源已关闭”后调用。
- 测量用例在阶段成功或取消后调用该转换；失败、紧急停止不调用。
- 纯 Python 单测：同一会话连续两个阶段，第二次 `power_on()` 与 `start_measurement()` 成功，`open_resource` 次数不增加。

**技术决定**

- 不通过放宽 `power_on()` 的状态前置条件来“顺便”支持复用；转换必须是显式、可审计的一步。
- 会话不可复用时（清理失败、紧急停止后状态未知）必须关闭资源并把端口置空，禁止下一阶段复用。

**完成标准**：连续阶段复用有测试；任何安全清理失败都会阻止复用。

### 步骤 11.2：端口复用判据

**执行策略**

- `release_port_after_measurement()` 改为 `settle_port_after_measurement()`：最近阶段以 `COMPLETED` 结束且清理记录为已执行时保留端口；其余终态（失败、紧急停止、取消但清理失败）关闭端口并置空引用，状态改为“需重新连接”。
- 保留“端口为空时测量入口拒绝启动”的现有判据，只改提示文案。

**技术决定**

- 复用期间保持 VISA 连接打开，但 RF 与电源输出在每阶段结束都是关闭状态；这是复用的前提，不是附加条件。
- 端口关闭仍走 `close_instrument_port()`，清理失败进入未决清单，引用不丢。

**完成标准**：阶段之间资源打开次数不增加；RF/电源输出被关闭；清理失败会阻止复用并可见。

## 14. 已确认与剩余假设

已确认（本次修订据此定稿）：

- 可达性确认放在“下一步”，只做 `open_resource` + `*IDN?` + `close`，不替代连接确认。
- 最终动作合并为一个按钮；仪表配置页的“连接仪器”按钮与转发链整体删除，重连复用同一入口。

剩余假设（实施前复核）：

- 电源声明通道是连接检查范围的权威事实；本期不新增设备未声明的物理通道。
- 用户正常放弃时删除仅创建且从未开始测量的运行；崩溃/强杀留下的目录首期保留。
- 可达性确认是新增步骤：若现场连续确认 VXI-11 对所有设备都稳定可用，可按证据删除，而不是保留成运行时开关。

## 15. 推荐实施顺序与阶段出口

| 阶段 | 交付物 | 阶段出口条件 |
|---|---|---|
| 一：契约与基线 | 状态/失败语义、调用清单、文档更新项 | 每个状态与失败点都有唯一入口和唯一处理 |
| 二：连接确认 | 可达性确认、结构化连接结果 | 假 VISA 测试证明检查范围与只读语义 |
| 三：最终化事务 | 两阶段提交、补偿、重连 | 失败无半提交，`prepared_run` 与端口同生 |
| 四：撤销用例 | `discard_unstarted_run` 与两个入口 | 已测量运行无法被删除 |
| 五：页面与导航 | 唯一最终动作、移除仪表配置页连接按钮 | 连接成功才可测量，失败可原地重试 |
| 六：阶段复用 | `end_stage()`、端口留存判据 | 连续阶段不重连，清理失败阻止复用 |
| 七：门禁与验证 | API/文档/测试与官方 runner | 适用范围与 gates 全绿 |
