# 硬件会话与运行流程重构计划

## 目标与已确认的产品决策

本计划调整仪器连接与运行创建的先后关系，支持“先选并连接设备，再配置电源分配/通道/参数，最后创建正式运行”。计划基于以下已确认决策：

1. 连接后进入配置页，后续会配置电源电压、电流、保护值，也会更改电源分配、通道角色等。
2. 连接成功后不允许返回上一步重新选择仪器。
3. 中途放弃视为无效；应用正常退出时关闭硬件会话，并删除尚未开始测量的运行。

## 设计结论

- “查找设备”仍是网段级、临时 TCP、只读 `*IDN?` 探测；它不等于持久仪器连接。
- “连接仪器”改成建立独立的硬件会话：按已应用的设备绑定打开信号源、频谱仪和**所有本次勾选的电源**，完成电源身份及所有声明通道输出状态检查，不创建正式运行，也不写设定值或打开输出。
- 后续配置可改变分配和角色。正式运行创建时，用最终配置生成运行映射，再把该映射应用到已连接会话，生成测量端口适配器；只要硬件地址集合不变，不重连 VISA。
- 正式运行只在完整参数配置通过校验后创建，快照包含最终配置。连接不依赖运行契约是一次有意的契约调整，应新增显式硬件会话契约及受控入口，而不是弱化 `PreparedRun` 判据或添加任意配置路径回退。
- 配置阶段被放弃时不创建正式运行；如果正式运行已创建但尚未开始任何测量，正常退出时先安全关闭会话，再删除该运行。运行已经开始测量后，保留运行及结果，不因退出而删除。
- 会话在多个测量阶段之间保留 VISA 连接。每阶段仍执行 RF/电源安全关闭；会话只在用户放弃、应用退出或清理失败需要隔离时关闭。

## 术语与边界

| 名称 | 含义 | 生命周期 |
|---|---|---|
| 设备发现结果 | 扫描读到的身份、地址、角色与卡片状态 | 单次扫描；不占用硬件资源 |
| 设备绑定 | 用户本次选定的设备集合及其地址/身份 | 连接后冻结；不允许返回重选 |
| HardwareSession | 已打开并完成连接安全检查的 VISA 资源、驱动与设备身份 | 连接成功至放弃/退出/不可恢复清理失败 |
| PreparedRun | 完整测量配置、运行目录与硬件快照组成的正式运行契约 | 完整配置通过校验后创建；开始测量后保留审计 |
| MeasurementPort | 使用某个 PreparedRun 的通道路由、电源设置和安全顺序，对 HardwareSession 的轻量适配 | 创建运行后注入测量；每次完成配置时从会话重建 |

职责边界：`instrument` 定义纯硬件计划与资源会话；`app` 是生产装配入口；`application` 持有运行创建/未测量运行撤销等用例和端口；`presentation/qt` 编排用户动作、导航、状态展示，不直接创建 VISA 资源。

## 阶段一：冻结目标契约与行为基线

### 步骤 1.1：登记流程、状态与失败语义

**执行策略**

- 更新《无运行契约调用方清单》，新增“早期硬件会话”受控调用场景，明确它只接收已校验的设备绑定/硬件连接草稿，不接受任意路径，不创建运行。
- 更新本计划引用的配置行为基线，定义状态顺序：未绑定 → 正在连接 → 已连接待配置 → 正在创建运行 → 已就绪测量 → 已开始测量/终态。
- 固定失败边界：会话连接失败回到可重试的仪器选择；运行创建或适配失败不提交新 PreparedRun；清理失败保留硬件引用且禁止继续测量。
- 为“正常退出删除未测量运行”定义精确判据与入口，避免根据目录名、时间或空结果目录猜测。

**技术决定**

- 保留 `has_run_contract()`、`PreparedRun` 与测量命令对正式运行的强校验；新增会话契约，而非让 `connect_instruments()` 接受可选 PreparedRun。
- 用户主动放弃与系统异常分开：主动放弃可触发未测量运行撤销；应用崩溃/强制结束不能保证执行清理，先保留目录，后续通过启动恢复策略处理，不做未经确认的自动删除。
- “测量已开始”以运行 manifest/阶段记录进入 running 或存在任何已完成阶段为准；一旦达到该界线，退出不删除运行。

**完成标准**：契约文档能回答每个状态下允许的动作、资源所有者及失败后的可重试动作；相关 AST/库存门禁有明确更新项。

### 步骤 1.2：提取当前依赖与调用清单

**执行策略**

- 以现有入口为锚点绘制调用图：扫描器、设备选择应用、配置组装/保存、运行快照创建、硬件连接工厂、测量端口注入、阶段清理、窗口退出。
- 记录每条电源信息的来源：绑定地址/身份、声明通道、角色、分配、设定值、保护值、急停序列。
- 列出所有会释放端口或重建运行的入口，特别是 `release_port_after_measurement`、新建/加载运行、退出事件。

**技术决定**

- 清单只登记现状与目标归属，不改生产代码。
- 所有运行路径继续从 PreparedRun 快照读取测量配置；不新增运行期间读取全局可变配置的旁路。

**完成标准**：有一份经测试可映射到代码符号的变更清单；后续实现不需要在单个步骤里同时探索多个层次。

## 阶段二：建立可独立测试的硬件连接计划

### 步骤 2.1：定义连接事实与身份校验 DTO

**执行策略**

- 在 `instrument` 新增不可变连接计划类型，包含信号源、频谱仪、所有已选电源的地址、身份事实和声明通道。
- 连接计划从已经应用的真实设备绑定与配置得到；校验地址唯一、必需设备存在、电源身份完整、地址格式合法、通道声明非空。
- 单独覆盖空选择、重复地址、缺失身份、非法引用、未知/未声明通道等失败案例。

**技术决定**

- 计划必须包含本次选中的**全部电源**，不根据 `power_supply_assignment` 过滤；后续可能分配任意一台。
- 设备集合/地址/稳定身份属于不可变连接事实；通道角色、DUT/驱放分配及电压电流设置属于后续可变测量配置，不写入连接计划作为路由依据。
- 模拟扫描的绑定在真实连接计划构造前拒绝，错误明确指向模拟来源。

**完成标准**：纯 Python 测试证明连接计划不依赖分配，且只使用已选择绑定中的硬件身份/地址。

### 步骤 2.2：实现连接时的输出安全快照

**执行策略**

- 纯函数/策略计算每台已选电源必须检查的声明通道集合，初次连接时逐通道执行 `OUTP? CHx`。
- 连接计划保存“已检查通道”事实；加入清晰的结构化结果，供后续验证是否引入了未检查通道。
- 覆盖某通道输出为 `ON` 时整次连接失败，并确认已经打开的 VISA 资源按逆序释放。

**技术决定**

- 初次连接继续只发只读命令：电源 `*IDN?` 与 `OUTP?`；信号源和频谱仪只打开连接、不配置频率/功率/RF。
- 连接不能主动关闭已开启输出来“修复”初态；发现输出开启就拒绝，让操作者现场处理。
- 通道安全检查必须由受控会话方法执行，禁止页面直接发送 SCPI。

**完成标准**：instrument 单测覆盖全部绑定电源与所有声明通道，并锁定命令顺序和清理行为。

### 步骤 2.3：拆开资源会话与测量适配器

**执行策略**

- 将 `measurement_factory.py` 的现有硬件工厂拆成“打开 HardwareSession”和“从会话构造 MeasurementPort”两个操作。
- 资源会话拥有 ResourceManager、VISA 资源、底层 drivers、身份与通道检查记录；MeasurementPort 只拥有运行特定的路由/设置策略，不拥有底层资源。
- 保留 `create_measurement_port()` 兼容为旧调用的组合封装，内部复用新函数，避免一次删除所有既有装配路径。
- 用 fake VISA manager/resource 验证：适配器重建不重复 `open_resource()`；关闭会话只关闭资源一次。

**技术决定**

- HardwareSession 不导入 `PreparedRun`/运行目录概念。
- 适配器配置（`dut_channels`、`driver_channels`、`power_settings`、急停通道）只从最终运行 plan 构造。
- 不能让新旧适配器同时控制同一 VISA 资源；切换适配器采用原子替换，旧适配器不得单独关闭 session。

**完成标准**：会话、适配器分别具有单一资源所有权；已有 `create_measurement_port()` 测试仍通过。

## 阶段三：连接后允许重新分配与通道配置

### 步骤 3.1：把运行分配校验与连接资源集合解耦

**执行策略**

- `hardware_assembly_plan()` 仍为正式运行配置校验供电分配、角色冲突、通道引用，并生成最终测量路由。
- 新增会话兼容校验：信号源/频谱仪地址与已连接会话完全一致；运行引用的每台电源都存在于会话，地址与身份一致。
- 对运行引用但连接时没有检查过的物理通道，通过 session 的只读检查方法补做 `OUTP?`；不安全或查询失败就阻止最终化。
- 覆盖分配在会话内电源之间切换、gate/drain 角色交换、驱放/DUT 路由改变、多电源并用。

**技术决定**

- 连接会话可以包含运行未使用的电源；运行只能引用会话已连接的电源。
- 不允许运行配置更改信号源/频谱仪/电源地址或新增绑定电源；这类变化不能靠已有物理连接满足，明确提示该会话无效并要求从受控入口重新建立硬件会话。
- 对“运行配置新增通道”不假设通道名；先以设备能力/声明通道校验，只有设备声明且尚未检查的通道才可补查。

**完成标准**：会话兼容逻辑为纯测试或通过端口测试，逐项区分“可复用”“补检查”“拒绝重连”。

### 步骤 3.2：建立运行专属 MeasurementPort 工厂

**执行策略**

- 给最终运行配置构造 `HardwareAssemblyPlan`，将其路由/设定投影到已连接 HardwareSession，返回新的 MeasurementPort adapter。
- 将适配器注入 `MeasurementController`；只有完整构造成功后才切换当前运行和 controller 端口。
- 若运行快照创建成功但端口适配失败，撤销这次新建运行并保持连接会话，用户可修正配置后重试。

**技术决定**

- 不把用户界面中的可变配置对象直接交给测量端口；必须使用已冻结运行快照生成计划。
- 新运行端口切换前先完成完整性校验和会话兼容校验，提交采用两阶段方式：新运行与适配器全部就绪后再更新 `prepared_run`、状态文字与 controller。
- 连接阶段允许无分配；正式运行阶段仍要求完整合法分配。

**完成标准**：调整 V/I/保护、角色或供电分配后，最终适配器反映新快照，底层 VISA 打开次数不增加。

## 阶段四：调整应用层用例与运行事务

### 步骤 4.1：增加早期连接用例入口

**执行策略**

- 在 `app/gui_runtime.py` 增加唯一生产 `open_instrument_session(connection_document)` 入口。
- 入口只接受已应用绑定构成的显式配置 DTO/映射，经应用边界校验模拟来源和硬件连接计划后调用 instrument 会话工厂。
- 将后台 `InstrumentWorker` 从“PreparedRun -> MeasurementPort”改为“ConnectionRequest -> HardwareSession”；增加 session 结果、失败和取消的确定性清理。
- 保留旧测量/脚本调用者需要的 `connect_instruments(prepared_run)`，将其实现为“按运行创建 session + adapter”的兼容组合，但清点并在迁移后逐步删除重复路径。

**技术决定**

- 新入口不是无契约回退：会话 DTO 必须有明确 schema、来源和校验规则；禁止配置路径参数或从全局可变文件暗中读地址。
- Qt worker 只编排后台动作、发信号，不实现设备规则。
- session 未成功交接给协调器时由 worker 负责清理；交接后所有权唯一归协调器。

**完成标准**：worker 成功、失败、取消三条路径均无资源泄漏；扫描模式模拟结果无法触发真实会话。

### 步骤 4.2：增加“最终配置并创建运行”事务

**执行策略**

- 新增协调器入口：读取完整 UI 配置、验证、编写并保存配置、创建 PreparedRun、校验会话兼容、由快照构建 MeasurementPort。
- 只有每一步成功才提交 `prepared_run`、运行状态、MeasurementPort，并允许进入测量区。
- 对保存失败、运行校验失败、快照写入失败、会话不兼容、新通道输出开启、adapter 构造失败分别给出错误和可重试状态。
- 将现有“校验并创建运行”流程改为这一入口，避免存在一个能绕开硬件会话/适配器最终化的新运行按钮。

**技术决定**

- 正式运行创建发生在所有将冻结进本次测试的参数配置完成之后。
- 配置全量校验失败不写配置、不创建运行；保存成功但运行快照创建失败时，全局配置可能已保存，但当前 PreparedRun 与 session 不切换，错误明确说明。
- `create_run_snapshot()` 的补偿清理继续使用 `discard_run()`；新运行创建后后续步骤失败也必须由协调器显式补偿撤销。

**完成标准**：每个失败点可重复操作，不遗留“界面显示新运行但端口仍对应旧配置”的状态。

### 步骤 4.3：增加未测量运行撤销用例

**执行策略**

- 在 application 增加 `discard_unstarted_run` 用例/服务，只通过 RunRepositoryPort 查询 manifest 并在满足条件时调用 `discard_run()`。
- 为“created 且没有任何 running/completed/failed/cancelled 阶段”的运行定义明确判据；拒绝删除 running、任何已进入测量阶段或含已完成阶段的运行。
- 为受控放弃路径测试成功删除、运行已开始拒绝、目录缺失幂等、仓储错误返回等情况。

**技术决定**

- `discard_run()` 的底层仓储能力保留为补偿清理；正常产品行为经 application 用例并执行状态守卫。
- 用户正常放弃：先做硬件安全关闭，确认资源清理成功后再删除未开始运行；清理失败则保留运行和端口引用供重试。
- 进程崩溃/强杀不承诺删除；首期不做启动时按时间自动删。后续若要恢复清理，需增加显式“未完成配置会话”记录及用户可见的恢复策略。

**完成标准**：业务入口无法删除已测量运行；关闭失败时运行目录不被删除。

## 阶段五：接入页面与导航

### 步骤 5.1：连接按钮一次性应用选择并连接

**执行策略**

- `ConnectionPage` 按钮点击时先从卡片生成 `ApplyDeviceSelectionRequest`，要求必需角色及至少一台可用电源选择完整。
- 成功应用绑定后启动 HardwareSession worker；连接成功才导航至配置页；校验/连接失败留在选择页并展示原因。
- 连接中禁用扫描、卡片选择和连接按钮，展示明确状态/进度；避免连接 worker 运行时改变其输入绑定。
- 移除“下一步”作为绕过连接前进的路径；若仍保留“返回欢迎页”，其语义定义为取消会话并走清理，而不是直接切换页面。

**技术决定**

- 卡片选择只是 UI 暂存；点击连接时整批应用，绑定应用成功是连接请求的输入边界。
- 连接失败后可以留在选择页重试，因为本次没有成功建立被锁定会话；连接成功后仪器集合冻结。
- 真实测量不可使用模拟绑定；此限制在应用/硬件会话边界验证，不依赖 UI 提示。

**完成标准**：端到端测试证明未点连接不进入配置页；无效选择/连接失败可见且不遗留端口。

### 步骤 5.2：将配置页定义为连接后的参数配置页

**执行策略**

- 首期复用现有 `ConfigPage`：其中已有电源详细配置、通道角色、供电分配和测试参数；必要时只调整布局/标题和主要动作文案。
- 移除或禁用“上一步：仪表配置”、设备绑定编辑及运行加载入口；连接成功后的地址/身份以只读摘要展示。
- 将“返回欢迎页”替换为“放弃本次配置”，经确认后调用协调器安全清理/撤销未开始运行，并返回欢迎页。
- 增加“完成配置并创建运行”动作，连接状态、修改状态、创建中状态、运行 ID、失败原因都在当前页可见。

**技术决定**

- 配置页只编辑会话已连接的电源集合；供电分配和通道角色可变，绑定身份/地址不可变。
- 如保留 `load_prepared_run` 功能，必须与本次 session 模式隔离，不能让加载另一运行替换当前锁定硬件集合；首期连接会话流程中隐藏/禁用加载入口。
- 页面动作通过 ConfigurationPagePort/ViewModel 或协调器 facade；不得让 `ConnectionPage` 直接持有 `ConfigPage` 或协调器内部实现。

**完成标准**：连接成功后无法返回或更改设备集合；电源参数和分配可以编辑；完成动作走唯一事务。

### 步骤 5.3：调整退出确认与放弃行为

**执行策略**

- 扩展窗口关闭生命周期：按“停止测量（若在运行）→ 等待 worker → 安全关闭硬件会话 → 决定未测量运行保留/删除 → 释放页面资源”执行。
- 尚未开始测量的运行退出时按产品决策删除；已开始测量的运行保留。清理失败提示风险、保留运行，并保留未决端口引用。
- 欢迎页返回、窗口关闭、创建运行后取消等入口共用一条协调器放弃用例，避免多个分支自行删目录。

**技术决定**

- 测量过程中的退出仍需先经过停止/安全清理，不允许测量 worker 与删除运行并发。
- 运行是否删除由 manifest 状态和阶段记录判定，不以页面当前状态、按钮点击次数或内存变量单独决定。
- 异常终止无法保证退出处理执行；目录保留优先于误删正式数据。

**完成标准**：正常放弃删除合规的未测量运行；任何已启动测量运行均保留；线程未停止时不释放/删除其资源或运行。

## 阶段六：维持测量生命周期安全

### 步骤 6.1：让 HardwareSession 跨测量阶段存活

**执行策略**

- 测量使用运行专属 MeasurementPort，但资源所有权仍由 HardwareSession/协调器持有。
- 阶段结束执行 RF OFF、所有相关电源 OFF；成功时保持 VISA 资源打开，供下一个阶段继续使用。
- 修改 `release_port_after_measurement()` 行为：成功清理后不释放硬件会话；清理失败时将会话标记为不可复用，尝试受控关闭并显示状态。
- 覆盖线损→驱动映射→功放连续阶段、取消、普通停止、异常、紧急停止及连接清理失败。

**技术决定**

- 适配器拥有“如何路由”，会话拥有“连接资源”；两者清理语义必须拆开。
- `close_rf=True` 代表彻底关闭会话时的最终安全动作；每阶段安全清理不得通过 `close_all()` 关闭资源。
- 只有清理记录明确证明 RF/电源已安全，session 才可复用；否则禁止启动后续阶段。

**完成标准**：测量阶段之间资源打开次数不增加、RF/电源输出被关闭；任何安全清理失败都会阻止复用。

### 步骤 6.2：按需对新通道补充输出检查

**执行策略**

- 运行最终化时比较分配通道与 session 已检查通道集合；若目标通道是设备已声明且未检查通道，通过已连接驱动查询输出状态。
- 查询结果为 OFF 后登记本次检查事实；ON、未知或通信失败都拒绝创建可测量 adapter。
- 若目标通道超出设备声明/驱动能力，配置校验报可修复错误，不猜测设备支持范围。

**技术决定**

- 所有连接时已声明通道初始就检查；此步骤只处理运行配置变化导致的新引用，不重复对已检查通道发送查询。
- 输出检查属于读操作，可在建立运行后适配前执行；若失败，运行补偿撤销，session 保留供用户修正/重试。

**完成标准**：未检查通道不能无声进入路由；同一个通道的查询次数受测试约束。

**执行策略**

**完成标准**：适用测试与仓库 gates 通过；真机验证仅在经授权时进行并记录结果。

## 推荐实施顺序与阶段出口

| 阶段 | 交付物 | 阶段出口条件 |
|---|---|---|
| 一：契约 | 状态/失败语义和调用清单 | 新旧运行约束与放弃语义无歧义 |

## 尚未改变的产品假设（实施前复核）

- “连接仪器”要求信号源、频谱仪和至少一台电源均已选中；若某测试模式允许不接某类设备，应由明确的模式规则决定，而非隐式缺省。
- 电源在设备表中声明的通道集合是连接时检查范围的权威事实；本期 UI 允许改变通道角色/分配，不新增硬件未声明的物理通道。
- 用户正常放弃时删除仅创建未开始测量的运行；崩溃/强杀留下的目录首期保留并在后续提供显式恢复/清理 UX。
- 正式运行仍在最后一个运行配置步骤完成时创建；若将来增加会影响测量的配置页，创建点随之移到最后一个此类配置完成之后。
