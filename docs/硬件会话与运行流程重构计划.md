# 硬件会话与运行流程重构计划

> 命名约定（计划步骤 13）：下文的 `ConnectionPage` / `ConfigPage` 现在分别对应
> `InstrumentSetupPage`（`presentation.qt.instrument_setup_page`）与
> `ConfigurationPage`（`presentation.qt.configuration_page`）。旧名称只保留兼容
> 再导出，本文保留原流程记录中的旧称呼，不改变已确认的产品流程。

## 1. 目的与已经确认的产品流程

现有文档把“设备发现、提前连通性检查、参数配置、创建运行、连接仪器、测量”拆成了多条相互重叠的路径，导致按钮语义、运行提交时机和失败后的状态都不清楚。本计划以用户确认的单一路径为准，删除早期连接概念，不引入独立的 `HardwareSession`。

目标流程只有一条：

```text
欢迎页选择测试模式
    ↓
仪表配置页：查找设备 → 勾选设备 → 下一步
    ↓ 只应用设备绑定，不访问 VISA
参数配置页：配置电源、频率、功率及其它测试参数
    ↓
完成配置并连接：校验 → 保存配置 → 创建待提交运行 → 完整连接检查
    ↓ 成功才提交运行和端口
测量区
```

已确认的产品决策：

1. “下一步”不做 VISA 可达性检查，也不创建运行；它只接受本次查找结果并整批应用设备绑定，然后进入参数配置页。
2. 用户必须先执行一次“查找设备”，并在本次结果中选择设备，才能点“下一步”。不再允许未查找时沿用旧绑定直接进入参数页。
3. 参数配置页的最终按钮统一负责“连接性检查、保存配置、创建运行”。按钮文案为“完成配置并连接仪器”。
4. 最终动作成功后直接进入测量区；不自动开始任何测量，测量仍由测量页面的“开始”动作触发。
5. 连接检查沿用现有完整语义：所有声明设备必须成功打开；每台电源必须核对 `*IDN?` 型号；每台电源的全部声明通道必须查询 `OUTP?` 且全部处于关闭状态。
6. 连接检查只读，不写设定值、不打开输出；发现已有输出时拒绝本次最终动作并提示现场处理，绝不自动关闭后继续。

## 2. 调研结论：现状与目标差异

### 2.1 当前真实调用链

当前代码仍是旧流程：

```text
ConnectionPage.request_next
  → ApplyDeviceSelectionRequest
  → MainWindow._open_configuration_page

ConfigPage.request_create_run
  → ApplicationCoordinator.create_prepared_run
  → save_configuration
  → prepare_configuration
  → release_instrument_for_new_run
  → prepared_run = prepared

ConnectionPage 的“连接仪器”
  → ConfigurationSession.request_connect
  → ConfigPage.request_connect
  → MainWindow.connect_instruments
  → ApplicationCoordinator.connect_instruments
  → InstrumentWorker
  → accept_instrument_controller
```

因此目前存在三个问题：

- 创建运行与连接是两个动作，可能出现“运行已创建但端口未连接”。
- 连接按钮位于设备发现页，用户还没有完成参数配置时就能触发；协调器又要求已有 `prepared_run`，所以该入口的语义和可用性互相矛盾。
- `create_prepared_run()` 当前只保存和冻结配置，不做硬件检查；测量区在端口缺失时只能事后报错。

### 2.2 当前硬件边界

- 设备发现：`infrastructure.discovery.instrument_discovery` 使用 5025/5555 的 SCPI Raw socket 发送 `*IDN?`，不持有 VISA 资源。
- 设备绑定：`application.device_binding` 通过 `ApplyDeviceSelectionRequest` 整批替换绑定，配置页负责把结果投影到电源标签页和分配选项。
- 真实连接：`app.gui_runtime.connect_instruments(prepared_run)` 是生产连接入口，连接配置必须来自运行目录内冻结的 `inputs/hardware_config.json`。
- 完整检查：`instrument.measurement_factory` 打开信号源、频谱仪和电源；电源执行 `*IDN?` 型号核对，并对全部声明通道执行 `OUTP?`。
- 资源所有权：`_VisaSession` / `ManagedInstrumentSession` 持有资源，`PortMeasurementAdapter` 做路由和测量动作；没有必要再增加公开 `HardwareSession`。
- 阶段清理：当前 `ApplicationCoordinator.release_port_after_measurement()` 会无条件释放端口，后续需要改为成功阶段可复用、异常阶段释放。

### 2.3 本计划明确删除的旧概念

- 删除设备发现页的“连接仪器”按钮及其 `connect_requested` 转发链。
- 删除参数配置页的 `request_connect` / `connect_requested` 入口。
- 删除“先创建运行、再单独连接”的用户可见流程。
- 删除计划中新增的“下一步可达性确认” worker、结果模型和失败分支。设备发现成功不是连接成功的证据，但本产品选择把这两次检查合并到最终动作，不在中间增加一次检查。
- 不创建独立的 `HardwareSession` 公共契约；继续使用现有会话、适配器和协调器所有权边界。

## 3. 目标契约与状态模型

### 3.1 三个阶段对象

| 阶段 | 对象 | 是否写文件 | 是否占用硬件 |
|---|---|---:|---:|
| 发现 | 扫描结果 + 用户选择 | 否 | 否 |
| 配置草稿 | 页面内存中的设备绑定和参数 | “保存配置”或最终按钮时写入 | 否 |
| 最终运行 | `PreparedRun` + `MeasurementPort` | 运行快照写入 | 是，连接成功后持有 |

“待提交运行”是最终动作的内部事务对象，不是用户可见的已创建运行状态。连接成功前不得把它写入协调器的 `prepared_run`，也不得让测量页消费它。

### 3.2 协调器状态

状态由 `ApplicationCoordinator` 唯一写入，页面只渲染状态文字。

| 状态 | 含义 | 允许动作 |
|---|---|---|
| `DEVICE_SELECTION` | 还在查找/选择设备 | 查找、勾选、下一步、返回欢迎页 |
| `CONFIGURING` | 设备绑定已应用，正在编辑参数；无硬件资源 | 编辑、保存、上一步、完成配置并连接 |
| `FINALIZING` | 已保存并冻结待提交运行，正在连接检查 | 仅等待、取消最终动作 |
| `CONNECTED` | 运行和端口已原子提交 | 进入/操作测量区、放弃、退出 |
| `MEASURING` | 测量阶段活动 | 停止、取消、紧急停止 |
| `RECONNECT_REQUIRED` | 运行保留但端口丢失 | 重新连接、放弃、退出 |
| `MANUAL_CLEANUP_REQUIRED` | 端口清理或待提交运行补偿失败 | 只允许现场清理和重试；禁止测量与新事务 |

核心不变量：

1. `prepared_run` 提交时，连接检查已经成功且端口已经被协调器接管。
2. 连接失败不得留下“已提交运行 + 未连接端口”。
3. 设备选择未完成时不能进入参数配置；参数校验未通过时不能保存、冻结或连接。
4. 测量页面永远不自行创建端口；端口缺失只显示“请完成配置并连接”或“请重新连接”。
5. 未决清理存在时，最终动作、重连和测量均拒绝启动。

## 4. 目标交互与失败语义

### 4.1 仪表配置页

1. “查找设备”启动扫描；扫描结果只在本页内存中存在。
2. 用户必须从本次扫描结果中选择设备。扫描失败、无结果或没有选择时，“下一步”保持在本页并显示明确原因。
3. 点“下一步”时调用 `ApplyDeviceSelectionRequest` 整批替换绑定，成功后进入参数配置页；不做 VISA open，不发送额外 SCPI，不保存文件，不创建运行。
4. 绑定应用失败时保留本页选择和错误信息，不能进入参数页。
5. 删除“连接仪器”按钮；页面只保留查找、选择、下一步和返回欢迎页。

### 4.2 参数配置页

页面编辑电源分配、通道角色、电压/电流/保护值、频率、功率和其它测试参数。页面不持有端口，不直接调用 VISA。

最终按钮行为：

1. 校验表单和正式运行配置。
2. 从当前页面读取完整配置，并保存全局配置。保存失败时不创建运行、不释放旧端口，留在本页可重试。
3. 检查未决清理；存在未决端口时阻止最终动作并进入人工处理提示。
4. 释放旧端口。释放失败时保留旧运行信息，记录未决端口，阻止新事务。
5. 调用 `prepare_configuration(..., hardware_config=current_config)` 创建待提交运行；此时只保存到 `_pending_run`，不替换当前 `prepared_run`。
6. 后台使用 `_pending_run` 做完整只读连接检查。
7. 检查成功后一次性提交 `_pending_run`、新端口和 `CONNECTED` 状态；成功信号触发主窗口进入测量区。
8. 检查失败时关闭新端口，守卫式撤销待提交运行；清空 `_pending_run`。旧运行若已因第 4 步失去端口，状态为 `RECONNECT_REQUIRED`。

成功按钮文案固定为“完成配置并连接仪器”。已有运行但端口丢失时，同一入口改为“重新连接仪器”：不保存配置、不创建新运行，只使用已有运行快照连接并提交端口。

### 4.3 失败矩阵

| 编号 | 失败点 | 结果 | 用户动作 |
|---|---|---|---|
| F1 | 未查找、无结果或未选择设备 | 留在仪表配置页，不写绑定 | 重新查找并选择 |
| F2 | 绑定应用拒绝 | 留在仪表配置页，绑定不改变 | 修正选择 |
| F3 | 参数/正式配置校验失败 | 不保存、不创建运行 | 修正参数 |
| F4 | 配置保存失败 | 旧运行和旧端口不变 | 重试最终动作 |
| F5 | 旧端口释放失败 | 旧运行保留，端口进入未决清理 | 现场清理后重试 |
| F6 | 创建待提交运行失败 | 配置可能已保存，当前运行不切换 | 重试最终动作 |
| F7 | 新端口打开失败 | 待提交运行撤销；旧运行无端口时标记需重连 | 重试最终动作 |
| F8 | 电源身份/型号不符 | 同 F7；不自动修改设备 | 更正设备或绑定后重试 |
| F9 | 任一声明通道输出开启 | 同 F7；不自动关输出 | 现场关闭输出后重试 |
| F10 | 协议查询或装配失败 | 逆序关闭新端口，执行待提交运行补偿 | 重试或人工处理 |
| F11 | 待提交运行撤销失败 | 运行目录保留，进入人工处理 | 人工清理，禁止继续 |
| F12 | 阶段安全清理失败 | 端口不可复用，运行保留并需重连 | 人工处理后重连 |
| F13 | 退出/放弃撤销失败 | 对话框保持打开，进入人工处理 | 完成清理后再退出 |

## 5. 生产实现分解

### 阶段一：先收敛页面流程

1. `ConnectionPage` 删除 `connect_btn`、`connect_requested`、构建连接按钮和对应说明；`request_next()` 强制要求本次扫描结果和至少一个选择。
2. `MainWindow` 删除设备发现页到配置页的连接接线、`_set_connect_enabled()` 和旧连接槽；保留窗口对最终动作 worker 的信号接线。
3. `ConfigPage` 删除 `connect_requested`、`request_connect()` 和旧连接入口；将 `create_run_requested` 改为 `finalize_run_requested`，按钮改为“完成配置并连接仪器”。
4. `ConfigurationSession` 只保留设备绑定视图和提交转发，不再转发连接意图。
5. 更新页面状态：最终动作进行中禁用最终按钮、返回和参数编辑；成功后由窗口切到 `workspace_page`，不自动开始测量。

阶段出口：代码中不存在配置页/连接页的 `connect_requested`、`request_connect`、`connect_btn`；页面测试能证明“查找选择→下一步→参数配置→最终动作”的单一路径。

### 阶段二：实现最终化事务

1. 将 `ApplicationCoordinator.create_prepared_run()` 原地演进为 `finalize_configuration()`，避免保留可绕过连接检查的第二入口。
2. 新增 `_pending_run` 和明确的事务状态；不要把 pending 运行暴露给 `resolve_measurement_run()`。
3. 将保存、旧端口释放、运行冻结、worker 启动、成功提交、失败补偿拆成可测试的步骤。
4. `accept_instrument_controller()` 改为只负责验证和提交新端口；最终化流程负责将它与 `_pending_run` 原子提交。
5. 连接 worker 的 `result`、`error`、`stopped` 必须分别落到成功提交、连接失败补偿或用户取消路径，不能由通用错误槽直接释放并宣称完成。
6. `finalize_configuration()` 成功返回后由 `MainWindow` 导航到测量区；失败留在参数配置页并展示逐设备原因。

阶段出口：所有失败路径均能证明 `prepared_run`、端口和状态不会形成非法半提交；成功时运行快照和端口同时可用。

### 阶段三：补偿与放弃

1. 在 `application.run_service` 增加 `discard_unstarted_run()`：只有 manifest 状态为 `CREATED` 且全部阶段仍为 `PENDING` 才允许撤销；已开始或已完成运行禁止删除。
2. 连接失败补偿和“放弃/退出”共用该用例；仓储层 `discard_run()` 仍只承担底层删除，不增加业务判断。
3. 连接 worker 未停止、端口未清理或补偿撤销失败时，不能关闭窗口，也不能报告为成功。
4. 崩溃/强杀首期不自动扫描和删除残留目录，残留运行通过历史/诊断工具处理。

阶段出口：连接失败不留下可被误认为有效的运行；已进入测量的运行永远不会被放弃流程删除。

### 阶段四：阶段间端口复用

1. 在 `ManagedInstrumentSession` 增加显式 `end_stage()`：仅在 RF 和相关电源已确认关闭后，将 `MEASURING`/`POWERED` 转回 `PREPARED`。
2. 成功完成阶段后保留端口；取消、异常、急停或安全清理失败时关闭端口并标记需重连。
3. `release_port_after_measurement()` 演进为按阶段结果决定 `settle` 或 `close`，不允许通过放宽状态前置条件隐藏清理失败。
4. 下一阶段复用同一端口，禁止重复 `open_resource`；每个阶段开始前仍必须满足输出关闭和会话状态条件。

阶段出口：连续两个阶段的 VISA 打开次数不增加；安全清理失败必然阻止复用。

### 阶段五：契约、文档与测试同步

必须同步以下文件和门禁：

- `README.md`：更新用户操作顺序和按钮文案。
- `tests/test_presentation_boundaries.py`、`tests/test_static_quality_gate.py`：删除旧按钮/旧入口基线，增加最终化和补偿基线。

## 6. 测试设计

### 6.1 纯 Python / instrument 测试

- 设备选择未查找、无结果、未选择时不能提交。
- `ApplyDeviceSelectionRequest` 成功后只改变页面/配置内存，不调用 VISA、不创建运行。
- 完整连接命令顺序：所有设备打开；电源 `*IDN?`；每个声明通道 `OUTP?`；输出开启、型号错误、查询异常分别归类。
- 连接失败时资源按逆序关闭，ResourceManager 关闭；任何输出开启都不触发自动关闭后继续。
- `finalize_configuration()` 的 F3–F11 三元组测试：释放前失败保留旧运行和端口；释放失败进入人工处理；释放成功后失败进入需重连；补偿失败阻断后续事务。
- `discard_unstarted_run()` 只撤销未开始运行，目录缺失幂等，已开始运行拒绝。
- `end_stage()` 后第二阶段不增加 VISA 打开次数；异常和清理失败禁止复用。

### 6.2 UI / integration 测试

- 页面动作只剩：查找、选择、下一步、返回；不存在“连接仪器”按钮。
- 未查找时点下一步不会切页；完成查找并选择后才进入参数页。
- 参数页最终按钮触发一次最终化事务；执行中禁用回退和重复提交。
- 连接成功后自动显示测量区，但不自动启动测量。
- 连接失败停留参数页，错误原因可见，最终按钮可重试。
- 保存配置成功但连接失败时，配置仍可再次编辑；pending 运行被撤销或进入人工处理。
- 成功连接后测量页面消费已提交运行；无端口时不自行连接。

## 7. 实施顺序与完成定义

| 顺序 | 交付物 | 完成定义 |
|---|---|---|
| 1 | 页面入口收敛 | 下一步只应用绑定；旧连接按钮和转发链删除 |
| 2 | 最终化事务 | 保存、冻结、连接、提交成为一个可补偿事务 |
| 3 | 失败补偿 | pending 运行可安全撤销，人工处理态可见且阻断 |
| 4 | 测量区导航 | 成功后进入测量区但不自动开始测量 |
| 5 | 阶段复用 | 成功阶段保留端口，异常阶段安全释放 |
| 6 | 文档与门禁 | README、测试库存与实现一致 |

最终验收场景：

1. 查找并选择设备，下一步进入参数页；期间没有 VISA 操作。
2. 配置频率、功率、电源和保护参数，点击“完成配置并连接仪器”。
3. 所有设备打开、身份正确、所有声明通道输出关闭后，配置被保存，运行被创建，端口被提交，界面进入测量区。
4. 任一设备打不开、型号不符、查询失败或输出开启时，运行不生效，端口被清理，界面留在参数页并可重试；输出不会被自动关闭。
5. 测量阶段正常结束后下一阶段复用端口；异常或清理失败时进入需重新连接，不允许静默复用。
