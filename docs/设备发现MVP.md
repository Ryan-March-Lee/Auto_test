# 设备发现（MVP）

“仪表配置”页（欢迎页选定测试模式后的整屏页面，不占标签栏，页面标题就是“仪表配置”）
里的设备发现面板：按网段探测 SCPI 端口、读取 `*IDN?`，把发现到的设备以**卡片**列在
页面中间的圆角结果框里，用户点选本次测试所需的设备后，一键写入仪器连接配置；框外
右下角的“连接仪器”连接本次应用的仪器，点“下一步”进入“仪器配置”页配置测试参数。

**测试角色由设备表登记，界面不让用户选**：现场每台仪器只承担一种角色，`instruments.json`
里的 `role` 字段就是唯一来源；卡片正面写“型号（短标签）”与角色（如 `SMW200A（5462）`、
`SMW200A · 信号发生器`），也不显示 IP 地址——地址只是本次可达的连接细节。没登记角色的设备
在卡片上写明“未分配角色 · 不能应用”，不能选中。

这是配置页上**唯一**的仪器连接入口：页面不再提供逐台填写 VISA 地址或勾选“启用”的控件。
连接地址只来自用户明确应用过的扫描结果；需要换设备或换地址时重新扫描并应用。

`device_bindings` 是仪器连接的**唯一来源**：保存出的 `instruments.<角色>.address/enabled`
由它派生，电源分配的可选项也由它决定。没有绑定的角色一律写成“未启用、无地址”。

本文记录这一版的能力边界，避免把 MVP 当成完整的设备资产管理。

## 1. 做什么

- **按网段扫描**：默认取已绑定设备（或配置里已有仪器地址）所在的 `/24`，也可以直接填
  `192.168.1.0/24` 或单个地址（单个地址按 `/24` 处理）。单次扫描上限 1024 个地址，超过直接报错。
- **读取身份**：对每个地址依次尝试 `5025`、`5555` 端口，发送一条 `*IDN?` 并解析。
  探测只读：只建立 TCP 连接、读一行响应，不发送任何会改变仪器状态的命令。
- **匹配设备表**：`*IDN?` 解析出的 `厂商:序列号` 与 `instruments.json` 比对，
  命中的显示短标签与登记角色（如 `SMW200A（5462）`、`SMW200A · 信号发生器`），未命中的
  显示为**未知设备**并保留型号、序列号。卡片正面不显示 IP 地址。
- **点选并应用**：点一下卡片即选中（再点取消），不需要选择测试角色——角色取自设备表的
  `role`。点击“应用所选设备到配置”后：该角色的仪器连接配置写入本次发现的地址并标记启用，
  设备身份写入 `device_bindings`，随配置一起保存；面板结果框里只列设备卡片与一行操作结果，
  不再罗列“当前配置”摘要。
  模拟模式下写入的绑定带 `source: simulated` 标记，状态行和日志也会明确说明这是演示数据。
- **应用即整批替换**：本次勾选结果就是完整的设备绑定，没勾选的旧角色会被移除，其地址
  与启用状态一并失效。这样更换设备不会残留上一台设备的连接，电源分配也不会再指向
  本次没有选中的电源；被移除的角色会在状态栏里列出。
- **清除设备绑定**：删除 `device_bindings`，并让相关仪器的地址与启用状态一并失效
  （保存出的配置变成“未启用、无地址”）。用于放弃一次错误的绑定或解除模拟绑定的运行阻断；
  需要重新扫描应用才能再次连接。


## 2. 身份与地址

- 设备身份是 `厂商:序列号`（见 `domain/instruments/models.py`）；IP 只是本次运行可达的地址。
- 保存后的 `device_bindings` 记录角色对应的 `device_key` 与 `serial`。**下一次扫描时，
  即使设备换了 IP，也会按身份自动预选**；角色始终以设备表登记为准。
- 预选只认 `厂商:序列号`：记录里有 `device_key` 就用它；只有厂商与序列号时重新拼出同一个
  键；**只有序列号时不做猜测**（不同厂商可能有相同序列号），该记录不参与预选。
  配置里的旧角色与设备表不一致时，状态栏会说明“角色以设备表为准”，不静默改接线。
- **探测端口与连接地址是两件事**：探测走 5025/5555 的 SCPI Raw 端口，只用于读出身份；
  写入配置的地址统一是 `TCPIP0::<ip>::inst0::INSTR`（VXI-11）。原因是测量链路
  （`instrument/transport/visa_transport.py`）用 `resource.query()` 收发，而 SOCKET 资源
  在未配置读终止符时会一直读到超时。探测端口作为元数据留在 `last_port` / `idn_port`。
- 当前测量链路仍然按配置里的 `instruments.<角色>.address` 连接仪器；该地址由**已应用的
  设备绑定**写入（`visa_address`），页面没有单独的地址控件。身份绑定同时给“下次识别”
  使用，尚未进入运行快照的 `run_mapping`——把身份冻结进运行快照是下一步工作。
- **旧配置迁移**：只有 `instruments.<角色>.address`、没有 `device_bindings` 的配置在加载
  时把信号源与频谱仪一次性迁移成绑定记录（`source: legacy_config`，没有序列号，下次扫描
  不会按身份预选）。只迁移“启用且地址非空”的仪器；面板把这类记录显示为“沿用已保存的
  配置，未扫描确认”。**电源不按地址迁移**：一个地址不能说明是哪一台电源，必须重新扫描
  并应用。迁移后保存的配置都带显式绑定，旧地址不会在清除绑定后重新变回可连接状态。
- **电源分配只认绑定**：电源分配的可选项来自已绑定的 `supply_id`（短标签，如
  `DP8B1519`）；配置里引用了未绑定（或已被替换掉）的电源时，下拉框保持空选择，配置页
  校验直接报错，不保存也不创建运行。页面不会把未知电源临时补进下拉框来“凑”一份看起来
  合法的配置。下拉框显示 `DP8B1519（DP832A）`，业务值保存在 `itemData`（`supply_id`），
  型号相同时也不会选错设备；控件没有 `itemData` 时按“未选择电源”报错，不会读出显示文本。

## 2.1 测试角色

现场设备是专用的：一台仪器只承担一种角色，因此角色登记在设备表，界面不再让用户选。

- `instruments.json` 的每条设备记录有 `role` 字段，取值是 `signal_generator`、
  `spectrum_analyzer`、`power_supply`（旧设备表里还有槽位编号 `PS1`..`PS4`，读取后折叠成
  `power_supply`）；`null` 表示尚未登记角色。
- 扫描结果的卡片：标题按设备类别取“身份在前”的写法，具体格式由
  `domain.instruments.labels` 统一生成：
  - 电源：标题是短标签（如 `DP8B1519`），型号行是 `DP832A · 电源`——现场核对实物靠短标签，
    短标签同时是配置里的 `supply_id`，不再用“电源 PS3”这种槽位编号；
  - 信号源与频谱仪：标题是 `型号（短标签）`（如 `SMW200A（5462）`），型号行是
    `信号发生器`；同型号的另一台靠括号里的短标签区分，不再靠资产名后缀 `-1` / `-2`。
  短标签只来自设备表（发现过程绝不生成标签）；旧设备表还没保存过时标题退回资产名
  （如 `SMW200A-1`），悬浮提示说明“保存一次设备表后自动补上”。**没有角色或未登记的设备
  不能选中**，卡片写明“未分配角色 · 不能应用”“未登记 · 不能应用”或“无法识别”；
  “有没有角色”按折叠后的类别判断，与卡片能否选中和配置页接受的角色集合同一个判据。
- 多台电源是同一个类别下的多台设备：卡片各自独立，选中几台就传递几台，短标签、序列号和
  设备键（`厂商:序列号`）随每条记录一起交给配置页，不再按角色键互相覆盖。只有信号源与
  频谱仪保持“一个角色一台设备”。
- 地址写进哪一路配置由短标签决定：电源按 `instruments.power_supplies.<supply_id>` 写入，
  没有短标签的电源不能应用（短标签就是配置引用 ID）；一次应用多台电源会得到多条独立
  绑定与多条独立地址，不按角色键互相覆盖，也不会只保留其中一台。
- 需要给新设备登记角色时：用 `InstrumentRegistry.set_role(...)`，或直接改
  `instruments.json` 的 `role` 后重新扫描。角色是设备资产属性，不是每次测试的选择。

## 3. 没有设备网络时（模拟扫描）

扫描方式下拉框：

- `模拟设备（离线演示）`：使用 `infrastructure/discovery/simulated_network.py` 的预置
  `*IDN?` 响应（含一台设备表中没有的 Keysight N9020A，用于演示未知设备）。**开发机上
  默认使用这一项**，不会发起任何真实连接；扫描完成后的状态栏会注明“模拟数据，仅用于
  离线演示”，应用后写入的绑定也会带 `source: simulated`。
- `真实网络扫描`：走 `TcpIdnProbe`，对网段内的地址建立短连接。

两种模式共用同一套解析、身份匹配与结果展示逻辑，因此现场行为与演示一致；模拟响应
不会被写入设备表，也不会被当成现场扫描结果。

**模拟绑定不能进入真实运行**：带 `source: simulated` 的绑定可以保存（便于演示与回看），
但 `domain.configuration.rules.simulated_binding_issues` 会把它报为正式校验错误，
`app.gui_runtime.prepare_configuration` 在创建任何运行目录之前就拒绝。
解除方式：用“真实网络扫描”重新获取并应用，或点击“清除设备绑定”。

## 4. 结果状态

| 发现状态 | 含义 | 卡片显示 | 能否选中 |
| --- | --- | --- | --- |
| `known`（已登记角色） | 身份可解析，命中设备表且登记了 `role` | 仪器图片 + 标题（电源为 `短标签`，其它仪器为 `型号（短标签）`）+ 型号/角色行 + 身份码 | 可以（点击卡片选中） |
| 已登记但无角色 | 身份可解析，命中设备表但没有 `role` | 卡片 + “未分配角色 · 不能应用” | 不可以 |
| `unregistered` | 身份可解析，设备表没有 | 卡片 + “未登记 · 不能应用”，名字为 `未知设备 (型号)` | 不可以（没有角色可写） |
| `unidentified` | 端口有应答，但 `*IDN?` 为空或无法解析 | 空底板卡片 + “无法识别”，名字为 `未识别设备 #n` | 不可以 |

卡片上的**缩减版身份码**：电源就是它的短标签（如 `DP8B1519`，等于配置里的 `supply_id`），
不再拼 `PS/型号/序列号`——电源没有“第几台”，短标签才是现场核对实物与配置引用的同一个字符串；
旧设备表还没有标签时退回 `PS/型号/序列号` 的旧写法，不凭空造标签。其它仪器仍是
`角色/型号/序列号`（如 `SG/SMW200A/105462`、`SA/4082F/QZNI000866`），未登记角色写作 `NA`；
读不出身份时写 `未识别 #n`（同一地址两次刷新编号不变）。卡片的悬浮提示给出完整身份
（`DP8B1519（DP832A） · 序列号 … · 设备键 …`，由 `domain.instruments.labels.supply_identity_text`
统一生成）、`*IDN?` 原文与连接地址，不占卡片正面。

“卡片状态”（已登记 / 未分配角色 / 未登记 / 无法识别）与 `instruments.json` 里的资产状态
（`DeviceStatus`：`online` / `unreachable` / `offline` / `unknown`）是两套语义：
前者描述“这次扫描看到了什么、能不能应用”，后者描述“这台资产现在是否可用”。未登记设备的
资产状态记为 `unknown`，不冒充 `online`。

结果区是一条**可展开/收起的抽屉**：还没点“查找设备”时框里不放卡片，也不写常驻提示文字，
而是一块**浅灰底的落点**，“查找设备”是一张深色卡片按钮、就在框的正中（扫描网段与扫描方式
居中排在“仪表配置”标题下面；这张卡片一直是“亮着”的：正中一行渐变标题写着“查找设备”，
四周有柔光、光带与粒子在动；鼠标进来时卡片底下那张紫→蓝渐变底卡在 0.6s 里转出去、
霓虹光斑同时加厚，移开又转回来，见 `presentation/qt/scan_card.py`）；
点下去之后**按钮与浅灰底一起消失**，框中央换成“正在查找设备 …”与进度，结果回来
后展开卡片。`收起结果` 收起后框里只剩扫描统计那一行状态，框心给出“查找设备”（换个网段
再查一次）与“查看结果”（把卡片放回来）两个按钮，不需要为了看一眼结果再扫一次。扫描失败、
取消或一台设备都没读到时，框里放不出卡片，中央的“查找设备”会回来（浅灰底不再出现，用户
已经点过一次），改网段后可以直接重试。

结果框的**大小是固定的**：高度按“两行卡片 + 框内的按钮与状态行”算出来（正好放下场地上
的 5 台仪器），不随状态和结果数量变化，所以点一次“查找设备”时整个页面不会跳动；设备多到
超过这个高度时，卡片区在框内滚动。

## 5. 失败、取消与去重

| 情况 | 表现 |
| --- | --- |
| 网段非法 / 过大 | “扫描失败: …”，结果区保持为空，按钮恢复可用 |
| 端口不可达 | 该地址不出现在结果里（扫描本来就会大量空响应） |
| 单个地址探测异常（IO/超时） | 记为一条失败说明，其余地址继续扫 |
| 端口有应答但 `*IDN?` 为空或不可解析 | 保留一张“无法识别”的卡片，给出原因 |
| 身份可解析但设备表没有 | 保留卡片并标为“未登记”，不可选中（没有登记的测试角色） |
| 设备表没有登记角色 | 卡片标为“未分配角色”，不可选中 |
| 角色重复 / 身份缺失 | 不应用，状态栏说明原因（整批拒绝） |
| 电源分配引用了未绑定的电源 | 该分配下拉框保持空选择，配置页校验报错，禁止保存/创建运行 |
| 用户取消或关闭页面 | 停止提交新探测、丢弃排队任务，只等已启动的少数任务按超时结束；结果标注“不完整” |
| 同一 IP 多个端口身份不同 | 保留确定性优先的一条，并在“提示”里要求人工确认 |
| 同一序列号出现在多个地址 | 只保留一个地址，并在“提示”里给出被忽略的地址 |

去重与取舍不依赖探测完成顺序：每个 IP 先按“能读出身份 → 已登记 → 端口小”选代表，
再按 IP 排序；同一 `device_key` 只保留第一个地址。

| `domain/configuration/rules.py` | `simulated_binding_issues`：模拟绑定不能通过真实运行校验 |
| `app/gui_runtime.py` | 创建运行前拒绝模拟绑定 |

## 7. 已知限制（下一步）

- 发现只覆盖直接可达的 TCP SCPI 端口（5025/5555），不支持 VXI-11 / HiSLIP 端口发现；
  没有 ARP/MAC 采集，也不跨 VLAN。只有 Raw Socket、不支持 VXI-11 的仪器目前无法自动
  写入可用地址（配置页已不再提供手工填写地址的入口）。
- 未知设备只展示、不能应用，也不会自动登记到 `instruments.json`（避免扫描动作静默
  建档，更避免替用户猜一个测试角色）。新设备要先登记角色才能使用。
- `device_bindings` 只存在于配置编写文档，未进入正式 `run_mapping` 与运行快照；
  测量仍按 IP 地址连接。
- 扫描线程属于配置页；页面关闭时请求取消并等待，但不做强杀。
- 卡片图片按“角色 → 型号关键字”在 `assets/instrument_pic/` 里查找（`signal_generator` →
  `signal_source.png`、`spectrum_analyzer` → `spectrum_analyzer.png`、`power_supply` →
  `DC_source.png`，型号兜底 `SMW*` / `FPL|FSU|FSV|4082*` / `DP8|DP2*`）。没有匹配的图片时
  卡片只显示空底板；新增仪器要补图时把图片按角色命名放进同一目录即可，不用改代码。
- 仪器照片的留白不一致（现有三张图里主体占画布的比例从 70% 到 96% 不等），所以图片区
  缩放的是**仪器主体的包围盒**而不是整张照片：填充或透明留白先被找出来并排除，只把主体
  等比放进 166×96 的图片区。这样换一张留白更多的照片，仪器在卡片上的视觉大小也不变；
  主体边界在原图的 128px 缩略图上找（背景色取四角），照片本来没留白时退回整张图。
