# 运行配置说明

本文说明配置页和正式运行配置中的 **DUT 输入功率扫描计划**。当前正式配置版本为
`schema_version: "1.2"`，一段扫描计划由起始功率、步长和终止功率组成；一份配置可以按
用户填写顺序执行多段计划，用粗步长覆盖低功率区、用细步长覆盖接近增益压缩的区段。

## 1. 多段计划示例

编辑页的测试参数区（以及正式 `test_plan.signal_source`）使用同一个字段形状：

```json
{
  "signal_source": {
    "power_scan_plans": [
      {"start_power": -38.0, "step": 1.0, "stop_power": -10.0},
      {"start_power": -10.0, "step": 0.25, "stop_power": -2.0}
    ],
    "unit": "dBm",
    "power_reference": "dut_input"
  }
}
```

- 列表顺序就是执行顺序，程序不会按起点自动排序。
- `start_power` / `stop_power` 的单位是 dBm，表示 **DUT 输入功率**，不是信号源输出功率。
- `step` 的单位是 dB，表示该段目标 DUT 输入功率网格的间隔。
- 两段计划共享 `-10.0 dBm` 这个边界，合并后的目标点列中该点只出现一次。
- `power_reference` 固定写 `"dut_input"`；缺少它的旧配置仍可读取，但校验只提示确认，
  不会根据历史数值猜测原来的功率语义。

上面的示例在低功率段每个 dB 取一点，进入高功率细扫段后每 0.25 dB 取一点。配置页会为
每一行显示该段实际生成的点位；点多时只显示首尾和总数，鼠标悬停可查看完整点列。

## 2. 点位生成规则

每段点位和最终目标点列由同一套规则生成，配置页预览、驱动映射和正式测量不会各算一套：

1. 每段按 `start_power + n × step` 生成点，要求不超过该段 `stop_power`。
2. 如果 `stop_power` 不在步长网格上，仍然把 `stop_power` 作为该段最后一个点补入。
3. 相邻计划必须首尾相接：后一段的 `start_power` 等于前一段的 `stop_power`。
4. 后一段起点高于前一段终点表示**空档**；低于前一段终点表示**重叠**。两种都不能保存，
   也不能进入运行。
5. 相邻计划的公共边界在合并后的目标点列中只保留一次。
6. 最终目标点列按升序排列，不重复；调用方不需要再自行补点或去重。

浮点比较使用统一容差，因此 `-10.0` 与 `-9.999999999999998` 这类计算噪声不会被误报为
空档；真正填写的空档或重叠会明确指出两段的编号和功率值。

## 3. DUT 最大输入功率

`dut_config.max_input_power`（正式段为 `test_plan.dut.max_input_power`）是最终硬上限，
不会因为多段计划而放宽：

- 有效上限取“最后一段的终止功率”和“DUT 最大输入功率”中的较小值。
- 上限落在某段中间时，该段到达上限后停止，后续完全高于上限的段不产生目标点。
- 上限正好落在步长网格上时只出现一次；不在网格上时补入为最后一点。
- 首个目标点高于有效上限时，配置无效，保存和创建运行都会被阻止。
- 配置页汇总会显示最终目标点总数与首尾范围；被 DUT 上限截断时同时给出提示。

## 4. 配置页操作

- 测试参数区的 **DUT功率扫描计划** 区域每行是一段计划，输入顺序固定为
  “起始功率、步长、终止功率”。
- 点击 **+ 添加计划** 追加一行；新增行默认从上一行终点开始，步长沿用上一行，
  终点先等于起点，避免凭空生成业务范围。
- 每行的 **删除** 可以移除该段；至少保留一行。
- 修改任一段后，该段点位预览和整份计划的汇总立即更新。输入暂时非法时该行显示具体
  错误，不保留上一次的旧预览。
- 空档或重叠显示在后一段附近，并汇总到页面校验结果；页面不会自动修改输入来“修复”
  衔接问题。
- 旧配置里的计划无法完整读取时（例如某个计划条目不是对象、缺少必需字段），页面显示
  **重建计划** 按钮，汇总标注“计划未完整读取，预览只按当前可见行估算”；用户确认前
  保存会被阻止，不会静默丢掉读不出来的段。
- 保存、重新打开和取消均以整份计划列表为单位，行数、顺序和数值保持一致。

## 5. 旧配置升级

正式配置的版本策略如下：

| 版本 | 读取 | 保存 | 说明 |
| --- | --- | --- | --- |
| `1.0` | 可以读取 | 不能直接保存 | 先运行现有电源配置迁移器升级 |
| `1.1` | 可以读取 | 保存时升级为 `1.2` | 旧的三标量扫描在保存边界包装成一段计划 |
| `1.2` | 可以读取 | 按当前格式保存 | 只写 `signal_source.power_scan_plans` |

- 1.1 的 `start_power` / `stop_power` / `step` 只作为**单段兼容读取**：读取时显示为一行，
  保存时改写为 1.2 列表。旧文件不会被静默修改。
- 读取不完整时（计划条目结构错误）不会自动补全或丢弃：页面按“配置页操作”一节的
  **重建计划** 流程要求用户先确认，再允许保存。
- 1.2 文档只允许 `power_scan_plans`；同一份文档里同时出现旧标量和新列表会直接报错，
  不会选择其中一个来源继续运行。
- 缺少 `power_reference` 的旧配置只给出兼容提示，需要用户按“主功放输入功率”核对后
  重新保存；程序不会根据历史数值猜测或换算。
- 1.0 配置继续只能通过现有迁移器升级，不走自动转换。

升级后建议执行：

```powershell
& "D:\Anaconda\envs\Auto_test\python.exe" launcher.py --validate-config
```

校验通过后，配置才能进入创建运行流程。

## 6. 与驱动映射、正式测量的一致性

- 驱动映射、无驱动正式测试和驱动模式正式测试都消费同一组目标 DUT 输入功率点。
- 无驱动模式使用 `信号源设定功率 = 目标 DUT 输入功率 + 线损` 反算；结果文件中
  `input_power_dut` 记录目标 DUT 输入功率，`sg_power` 记录实际信号源设定功率。
- 驱动模式从当前运行目录的驱动映射目标表读取源功率，并对目标点数量、顺序和唯一性做
  校验；映射目标表缺点、重复或仍是旧单计划结果时，在硬件动作前失败。
- 配置页预览与实际测量使用同一个点位入口，避免“页面看到一段、仪器扫另一段”。

`git status` 中没有被误改的现场字段。
