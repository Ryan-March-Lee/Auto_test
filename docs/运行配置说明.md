# 运行配置说明

本文说明配置页和正式运行配置中的 **DUT 输入功率扫描计划**。当前正式配置版本为
`schema_version: "1.2"`，一段扫描计划由起始功率、步长和终止功率组成；一份配置可以按
用户填写顺序执行多段计划，用粗步长覆盖低功率区、用细步长覆盖接近增益压缩的区段。

## 1. 多段计划示例

编辑页的测试参数区（以及正式 `test_plan.signal_source`）使用同一个字段形状：

```json
{
  "signal_source": {
    "power_scan_plans": [
      {"start_power": -38.0, "step": 1.0, "stop_power": -10.0},
      {"start_power": -10.0, "step": 0.25, "stop_power": -2.0}
    ],
    "unit": "dBm",
    "power_reference": "dut_input"
  }
}
```

- 列表顺序就是执行顺序，程序不会按起点自动排序。
- `start_power` / `stop_power` 的单位是 dBm，表示 **DUT 输入功率**，不是信号源输出功率。
- `step` 的单位是 dB，表示该段目标 DUT 输入功率网格的间隔。
- 两段计划共享 `-10.0 dBm` 这个边界，合并后的目标点列中该点只出现一次。
- `power_reference` 固定写 `"dut_input"`；缺少它的旧配置仍可读取，但校验只提示确认，
  不会根据历史数值猜测原来的功率语义。

上面的示例在低功率段每个 dB 取一点，进入高功率细扫段后每 0.25 dB 取一点。配置页会为
每一行显示该段实际生成的点位；点多时只显示首尾若干点与总数，鼠标悬停可查看完整点列。

## 2. 点位生成规则

每段点位和最终目标点列由同一套规则生成，配置页预览、驱动映射和正式测量不会各算一套：

1. 每段按 `start_power + n × step` 生成点，要求不超过该段 `stop_power`。
2. 如果 `stop_power` 不在步长网格上，仍然把 `stop_power` 作为该段最后一个点补入。
3. 相邻计划必须首尾相接：后一段的 `start_power` 等于前一段的 `stop_power`。
4. 后一段起点高于前一段终点表示**空档**；低于前一段终点表示**重叠**。两种都不能保存，
   也不能进入运行。
5. 相邻计划的公共边界在合并后的目标点列中只保留一次。
6. 最终目标点列按升序排列，不重复；调用方不需要再自行补点或去重。

浮点比较使用统一容差，因此 `-10.0` 与 `-9.999999999999998` 这类计算噪声不会被误报为
空档；真正填写的空档或重叠会明确指出两段的编号和功率值。

## 3. DUT 最大输入功率

`dut_config.max_input_power`（正式段为 `test_plan.dut.max_input_power`）是最终硬上限，
不会因为多段计划而放宽：

- 有效上限取“最后一段的终止功率”和“DUT 最大输入功率”中的较小值。
- 上限落在某段中间时，该段到达上限后停止，后续完全高于上限的段不产生目标点。
- 上限正好落在步长网格上时只出现一次；不在网格上时补入为最后一点。
- 首个目标点高于有效上限时，配置无效，保存和创建运行都会被阻止。
- 配置页汇总会显示最终目标点总数与首尾范围；被 DUT 上限截断时同时给出提示。

## 3.1 驱放最大输入功率

`driver_mode.max_input_power`（正式段为 `test_plan.driver_mode.max_input_power`）是
**有驱放链路**中信号源输出设定值的硬上限，单位 dBm。它不是 DUT 输入目标：DUT 目标仍
由 `dut_config.max_input_power` 与扫描计划共同决定。

- 驱放测试模式开启时必须填写；旧配置缺少该字段仍可读取，但在补齐前不能保存新配置或
  开始新的驱动映射/驱动正式测量。
- 驱动映射的搜索起点、推进候选与初始占位功率都不会超过
  `min(驱放最大输入功率, 信号源硬件上限)`；目标在到达该上限后仍无法命中时，驱动映射
  明确失败并说明“受驱放最大输入功率限制”，不生成可供正式测试使用的完整映射。
- 正式主功放测试复用其他运行或旧配置的驱动映射文件时，会在连接仪器前检查目标表中
  每个目标点的 `source_power_dbm`；任一源功率超过本次配置的上限就拒绝。
- 无驱放链路不读取该参数，信号源仍按目标 DUT 输入与线损反算，并受信号源硬件范围限制。
- 配置值高于信号源硬件上限时，实际生效上限仍是硬件上限；低于信号源最小可设功率时，
  驱动映射在构造阶段直接失败。

## 4. 配置页操作

- 测试参数区的 **DUT功率扫描计划** 区域每行是一段计划，输入顺序固定为
  “起始功率、步长、终止功率”。
- 点击 **+ 添加计划** 追加一行；新增行默认从上一行终点开始，步长沿用上一行，
  终点先等于起点，避免凭空生成业务范围。
- 每行的 **删除** 可以移除该段；至少保留一行。
- 修改任一段后，该段点位预览和整份计划的汇总立即更新。输入暂时非法时该行显示具体
  错误，不保留上一次的旧预览。
- 空档或重叠显示在后一段附近，并汇总到页面校验结果；页面不会自动修改输入来“修复”
  衔接问题。
- 旧配置里的计划无法完整读取时（例如某个计划条目不是对象、缺少必需字段），页面显示
  **重建计划** 按钮，汇总标注“计划未完整读取，预览只按当前可见行估算”；用户确认前
  保存会被阻止，不会静默丢掉读不出来的段。
- 保存、重新打开和取消均以整份计划列表为单位，行数、顺序和数值保持一致。

## 5. 旧配置升级

正式配置的版本策略如下：

| 版本 | 读取 | 保存 | 说明 |
| --- | --- | --- | --- |
| `1.0` | 可以读取 | 不能直接保存 | 先运行现有电源配置迁移器升级 |
| `1.1` | 可以读取 | 保存时升级为 `1.2` | 旧的三标量扫描在保存边界包装成一段计划 |
| `1.2` | 可以读取 | 按当前格式保存 | 只写 `signal_source.power_scan_plans` |

- 1.1 的 `start_power` / `stop_power` / `step` 只作为**单段兼容读取**：读取时显示为一行，
  保存时改写为 1.2 列表。旧文件不会被静默修改。
- 读取不完整时（计划条目结构错误）不会自动补全或丢弃：页面按“配置页操作”一节的
  **重建计划** 流程要求用户先确认，再允许保存。
- 1.2 文档只允许 `power_scan_plans`；同一份文档里同时出现旧标量和新列表会直接报错，
  不会选择其中一个来源继续运行。
- 缺少 `power_reference` 的旧配置只给出兼容提示，需要用户按“主功放输入功率”核对后
  重新保存；程序不会根据历史数值猜测或换算。
- 1.0 配置继续只能通过现有迁移器升级，不走自动转换。

升级后建议执行：

```powershell
& "D:\Anaconda\envs\Auto_test\python.exe" launcher.py --validate-config
```

校验通过后，配置才能在“连接仪器”时冻结为执行上下文并进入测量。

### 命名配置快照

配置页底部“保存配置”会先要求输入名称，然后把当前配置写入：

```text
test_results/configurations/<名称>_<YYYYMMDD_HHMM>/<名称>.json
test_results/configurations/<名称>_<YYYYMMDD_HHMM>/metadata.json
```

- 目录名使用本地时间到分钟；同一名称再次保存会整代替换同名快照（保留首次创建的时间
  后缀，`metadata.json` 记录最近保存时间）。配置与元数据先写暂存目录再一起提交，
  失败时保留上一代完整快照。
- 保存只写配置：不创建 `runs/<run_id>/`、不连接仪器。保存是可编辑草稿，不要求电源
  上电计划已经可运行；完整运行校验在点击“连接仪器”时执行。
- 欢迎页两个测试模式按钮下方的“加载配置”会列出已保存快照（名称 + 保存时间），
  选中后只更新编辑草稿、不创建执行上下文，并直接进入工作区的“测试配置”页；仍需
  点击“连接仪器”才会创建运行并开始测量。
- 加载时窗口会按配置重建仪器排布页，并把保存时记录的九宫格格位恢复到电源配置页，
  因此测试配置 → 电源配置 → 仪器排布可以来回查看和修改。格位只作为界面恢复信息
  写在快照的 `metadata.json` 里，不进入正式配置文档，也不参与运行校验；旧快照没有
  格位时按配置里的电源顺序补位。
- 从仪器排布页继续“上一步”会回到仪表配置页；已保存的设备绑定只用于恢复排布页的
  卡片身份，不会冒充本次扫描结果，继续“下一步”前仍需重新查找设备。
- 加载后还没有已提交会话时，配置里的驱放模式会同步到徽标、驱动映射标签页与阶段条。
- 只允许加载由 `metadata.json` 登记的配置文件；手工放进快照目录的其它 JSON 不会被
  当作快照。
- 当前工作配置（根 `config.json`）与命名快照是两次写入：任一失败都会如实提示；命名
  快照失败时会明确说明“当前工作配置已保存”。
- 执行上下文只在点击“连接仪器”时创建；连接失败且运行尚未开始时会被自动撤销，
  不在磁盘上留下孤儿运行目录。

## 6. 与驱动映射、正式测量的一致性

- 驱动映射、无驱动正式测试和驱动模式正式测试都消费同一组目标 DUT 输入功率点。
- 无驱动模式使用 `信号源设定功率 = 目标 DUT 输入功率 + 线损` 反算；结果文件中
  `input_power_dut` 记录目标 DUT 输入功率，`sg_power` 记录实际信号源设定功率。
- 驱动模式从当前运行目录的驱动映射目标表读取源功率，并对目标点数量、顺序和唯一性做
  校验；映射目标表缺点位、重复或仍是旧单计划结果时，在硬件动作前失败。
- 配置页预览与实际测量使用同一个点位入口，避免“页面看到一段、仪器扫另一段”。

## 7. 仓库中的样例

- 根目录 `config.json`：现场配置文件当前的 1.2 形态，展示 `power_scan_plans` 的正式
  写法。它的设备绑定以现场实际扫描结果为准；模拟扫描产生的绑定只能离线演示，配置校验
  会给出警告。
- `tests/fixtures/config_driver_enabled_no_assignment.json`：驱动模式启用但未配置驱动
  供电分配时的完整配置样例，包含“粗扫 + 细扫”两段计划。
- `tests/fixtures/configuration_authoring/official_configuration_golden.json`：正式配置
  编写基线，其中 `multi_plan_scan_1_2` 用例展示 1.2 多段计划原样透传、不合并、不排序。
- `tests/fixtures/power_supply_identity/config_slots_migrated_partial.json`：旧电源配置
  迁移到 1.2 后的样例（包含仍需人工补全的计划状态）。

修改样例时只改计划结构所在的字段，不要覆盖与本任务无关的用户配置；提交前确认
`git status` 中没有被误改的现场字段。
