# 配置快照与执行上下文分离重构计划

- 状态：已实施（阶段 1–5，含 2026-11-14 审查修订）
- 日期：2026-11-14
- 范围：`application`、`infrastructure`、`presentation/qt` 与对应测试；不改测量算法、
  阶段结果格式和运行目录内部结构。
- 前置：`docs/测量结果独立管理与运行降级重构计划.md`（阶段结果独立保存、运行只做后台
  隔离与审计）。

## 1. 目标与已确认决定

1. **保存与运行分开**：配置页“保存配置”不再要求先创建运行；点击后弹出命名输入，写入
   一份可复用的命名配置快照。
2. **命名规则**：目录名为 `<名称>_<YYYYMMDD_HHMM>`（本地时间到分钟）；同名再次保存
   直接覆盖，不生成第二个目录。
3. **界面移除运行概念**：删除“输入 run_id 加载运行”入口与 `load_run_requested` 信号；
   最终按钮文案从“完成配置并连接仪器”改为“连接仪器”。
4. **后台执行上下文保留**：`PreparedRun`、`runs/<run_id>/`、manifest、阶段记录、结果
   引用、端口生命周期和补偿逻辑都不删除，只在“连接仪器”时创建。
5. **配置与执行解耦**：保存配置不创建运行目录；连接失败且运行尚未开始时自动撤销，
   避免孤儿运行目录。

## 2. 分层与接口契约

```text
presentation/qt/configuration_snapshot_actions.py   Qt 对话框 + 窗口动作 mixin
presentation/qt/application_coordinator.py           编排：保存命名快照 / 加载快照 / 最终化
presentation/qt/composition.py                       组合根：装配快照仓储
application/dto/configuration_snapshots.py           名称与目录命名规则（唯一实现）
application/ports/configuration_snapshots.py         ConfigurationSnapshot / SaveOutcome / 端口
infrastructure/persistence/configuration_snapshot_repository.py
                                                     文件系统适配器（暂存提交、同名覆盖、登记校验）
infrastructure/filesystem/paths.py                   configuration_snapshots_dir
```

### 接口契约

- `ConfigurationSnapshotRepository.save(display_name, configuration, *, now=None)`
  - 校验名称 → 查找同名快照 → 在暂存目录写 `<名称>.json` 与 `metadata.json` →
    整代替换目标目录 → 返回 `ConfigurationSnapshot`。
  - 同名覆盖保留首次创建的时间后缀；名称非法时在写盘前抛 `ValueError`。
  - 保存与列举在进程内串行化；提交前失败删除暂存目录，目标保持上一代完整快照。
    进程中断留下的暂存/备份目录在下次访问时清理或恢复。
- `ConfigurationSnapshotRepository.load(path)`
  - 只接受由 `metadata.json` 登记、且登记文件名与路径完全一致的直接配置文件；
    越界、`metadata.json`、嵌套路径与手工放进快照目录的未登记 JSON 一律拒绝。
- `ConfigurationSnapshotRepository.list()`
  - 跳过损坏/不完整快照，按 `saved_at` 倒序返回；不列举暂存/备份目录。
- `ApplicationCoordinator.save_named_configuration(name)`
  - 先同步两页读数并校验测试配置页，再 `save_configuration()`（编写 + 写
    `config.json`），最后写快照。
  - 返回 `ConfigurationSaveOutcome`：`configuration_saved` 与 `snapshot` 分开表达。
    根配置成功、快照失败时返回**部分成功**，界面提示“当前工作配置已保存，但命名
    配置快照未保存”，不把它混成完全失败。
  - 命名快照是**可继续编辑的配置草稿**，不要求电源上电计划已经可运行；完整运行
    校验仍由“连接仪器”执行。
  - **不创建执行上下文**。
- `ApplicationCoordinator.load_named_configuration(path)`
  - 只回填两页编辑草稿；失败写 `last_load_error`，草稿保持原样。
  - 窗口在还没有已提交执行会话时，用加载配置的驱放模式同步徽标、驱动映射标签页与
    阶段条；已提交会话保留自己的冻结模式。
- `ApplicationCoordinator.finalize_configuration()`（保持不变）
  - 校验 → 保存 → 释放旧端口 → 冻结执行上下文 → 连接检查。

### 不变式

- `config.json` 仍是“当前工作配置”的唯一写入口（`JsonConfigurationRepository.save_document`）；
  命名快照是独立文件，不复用该入口，也不写运行目录。两者是两次持久化，不承诺跨文件
  原子性；部分成功必须如实报告。
- 命名快照内部按“代”提交：配置 JSON 与元数据先完整写入暂存目录再整代替换，读取方
  不会看到“新配置配旧元数据”。
- 执行上下文只在最终化事务中创建；补偿只撤销本次事务新建且尚未开始的目录。
- `_saved_configuration_pending` 只表达“编辑草稿与当前执行会话语义不同”，用于让最终
  入口回到“连接仪器”而不是静默重连旧会话。

## 3. 阶段与任务拆分

每一步都可以独立提交、独立验证；依赖关系见括号。

| 阶段 | 任务 | 主要文件 | 依赖 |
| --- | --- | --- | --- |
| 1 | 命名规则与端口 | `application/dto/configuration_snapshots.py`、`application/ports/configuration_snapshots.py` | — |
| 2 | 文件系统仓储 + 路径 | `infrastructure/persistence/configuration_snapshot_repository.py`、`infrastructure/filesystem/paths.py` | 1 |
| 3 | 协调器保存/加载编排 | `presentation/qt/application_coordinator.py`、`presentation/qt/composition.py` | 1、2 |
| 4 | 页面与窗口接线 | `config_page_widgets.py`、`test_configuration_page.py`、`configuration_snapshot_actions.py`、`main_window.py` | 3 |
| 5 | 门禁与文档 | `tests/test_config_write_boundary.py`、`tests/ui/test_main_window.py`、本文件、`运行配置说明.md` | 1–4 |

### 可并行的工作面

- **A. 应用与基础设施**（阶段 1、2）：名称规则、端口、文件适配器、单元测试。与 UI 完全
  独立，可先合并。
- **B. 协调器编排**（阶段 3）：依赖 A 的端口与命名函数，但不依赖具体按钮与弹窗。
- **C. 窗口与页面**（阶段 4）：依赖 B 的两个方法签名；对话框集中在
  `configuration_snapshot_actions.py`，与 A 的文件布局无耦合。
- **D. 门禁与文档**（阶段 5）：可随各阶段同步更新，尤其是
  `tests/test_config_write_boundary.py` 必须与阶段 2 同一提交，否则全量门禁失败。

### 共享改动点（必须先定契约，避免并行冲突）

1. `ApplicationCoordinator.__init__` 新增 `configuration_snapshots` 注入参数——后续所有
   协调器测试替身都要传或允许缺省。
2. `SaveConfiguration` 的语义：`save_configuration()` 保持“写当前工作配置”，新增
   `save_named_configuration()`；不要让两个方法互相调用成环。
3. `ConfigurationPort` 不新增方法；快照使用独立端口，避免第二个用户配置写入口。
4. 阶段结果与配置快照都位于 `test_results/` 下：`configurations/` 与
   `cable_loss/`、`driver_mapping/`、`amplifier/` 平级，互不解析。
5. 门禁文件 `tests/test_config_write_boundary.py` 是串行点：任何新增 JSON 写入点都要在
   同一提交登记用途与类别。

## 4. 明确不做的事

- 不删除 `runs/<run_id>/`、manifest、阶段记录、归档或历史数据。
- 不把运行目录改名为会话目录；内部标识继续使用 `run_id`。
- 不为并行而拆分配置文档格式；配置快照就是完整编辑文档本身。
- 不要求命名快照在保存时即可运行：保存是可编辑草稿，完整运行校验在连接事务。
- 不自动迁移旧 `config.json` 到命名快照；用户首次保存时才生成快照。

## 5. 审查修订（2026-11-14）

实施后的代码审查发现并修复了以下边界，相关决定固化在本文件与测试中：

1. **快照代际一致性**：配置与元数据改为暂存目录整代替换；失败保留上一代，中断的
   目录交换在下次访问时恢复。
2. **加载边界**：只加载 `metadata.json` 登记且路径一致的文件，拒绝手工放入的 JSON。
3. **部分成功**：新增 `ConfigurationSaveOutcome`；根配置已写、快照失败时界面提示
   “当前工作配置已保存”，不报告为完全失败。
4. **保存语义**：命名快照是可编辑草稿；保存前合并两页读数并校验测试配置页，但不以
   电源上电计划已可运行为前提，完整运行校验留给“连接仪器”。
5. **模式同步**：加载配置后，在没有已提交执行会话时同步驱放模式到工作台；已提交
   会话保留冻结模式。
6. **用户文案**：把仍会出现在弹窗/异常中的“创建运行/重新创建运行”改为
   “创建执行上下文/重新连接仪器”；内部运行模型与方法名不变。
