# 配置编辑行为基线

本文是 [GUI 业务逻辑重构计划](GUI业务逻辑重构计划.md) 步骤 1“冻结当前行为清单”的交付物。

它只记录**现在已经在代码和测试里成立的行为**，不新增、不修饰业务规则。后续每一步在移动
代码之前先对照本表；表里的“失败提示”“副作用”“不变量”都是回归判据。

## 1. 用途与边界

- 覆盖对象：欢迎页选择测试模式 → 仪表配置（设备发现与绑定）→ 仪器配置页（本表主角）。
- 覆盖动作：加载配置、编辑参数、应用设备、切换驱动模式、保存配置、创建运行、加载运行。
- 不覆盖：三类测量页面、实时绘图、历史结果、导出与自动归档（属于后续步骤）。
- 不以控件变量名作为长期契约：表中的“输出”指用户可见结果或正式文档内容，不指
  `self.freq_edit` 这类内部变量。控件名只在本表“现状位置”列出现，用于定位当前实现。
- 本步骤不移动生产代码，只新增本文和两组缺失的行为测试（共 4 个用例，见第 7 节）。

## 3. 动作总表

| # | 动作 | 触发 | 输入 | 成功输出 | 失败提示（用户可见） | 文件/运行副作用 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | 加载配置 | 窗口构造 `MainWindow.__init__`；欢迎页选择模式时再次读取 | 配置文件路径（`ConfigurationPort.load`） | 协调器 `config` 为读到的文档；配置页按文档构造 | 告警对话框标题“配置加载”，正文“无法加载配置文件: <原因>” | 只读；失败时协调器 `config` 变为空对象 |
| 2 | 编辑参数 | 控件编辑 + 保存/校验/创建运行时读数 | 控件值 | 组装出的配置编写文档（含未知字段保留） | 点击保存/创建运行/连接/校验时由页面校验汇总；“配置校验失败: <原因>”（写日志） | 无（纯组装，不写盘） |
| 3 | 应用设备 | 仪表配置页“下一步” | 本次勾选的设备发现结果（`assignments`） | 页面 `device_bindings` 被整批替换；电源标签页与分配选项刷新 | 面板状态行 + `validation_failed` 信号；整批拒绝，页面停留在仪表配置页 | 无文件写入；未保存前不产生配置变更 |
| 4 | 切换驱动模式 | 欢迎页选择“无驱放测试 / 有驱放测试” | 布尔 `driver_enabled` | 配置 `driver_mode.enabled` 更新；配置页显示驱动供电与分配区 | 无（选择本身不失败） | 无；配置页基线重置，不算“已修改” |
| 5 | 保存配置 | 配置页“保存配置” | 当前控件读数，基数为协调器持有的配置 | 正式配置文档写入唯一配置路径；页面基线标为干净 | 页面校验失败 → 不保存；写入失败 → 对话框“保存失败” + “配置保存失败: <原因>” | **写配置文件一次**（临时文件 + fsync + 原子替换）；不改当前运行快照 |
| 6 | 创建运行 | 配置页“校验并创建运行” | 当前控件读数 | 新运行目录与冻结快照；`prepared_run` 切换；页面状态文本更新 | “创建运行失败”（校验/保存/冻结失败）或“创建运行未生效”（旧端口未能安全释放） | **写配置文件 + 创建运行目录**（`config.json`、manifest、`inputs/hardware_config.json`）；释放旧仪器端口 |
| 7 | 加载运行 | 配置页“加载运行” + `run_id` | 运行标识 `run_id` | 冻结配置回填到页面；`prepared_run` 切换；状态文本更新 | 空 `run_id`：“请输入要加载的 run_id”；失败：“加载运行失败”；回填失败：“配置页回填失败，运行未切换…”；释放失败：“加载运行未生效” | **只读运行目录**；释放旧仪器端口；不写配置文件 |

## 4. 逐动作细节

### 4.1 加载配置

**现状位置**：`MainWindow.__init__` → `ApplicationCoordinator.load_configuration` →
`GuiDataService.configuration.load`（`ConfigurationPort.load`）；页面侧是 `ConfigPage.__init__`
（初次建页）与 `ConfigPage.apply_config`（运行回填）。

**输入**

- 配置文件路径由 `ApplicationCoordinator.config_path` 决定，不由页面拼接。
- 读取入口只有一个：`ConfigurationPort.load` → `JsonConfigurationAdapter` →
  `infrastructure.config.json_io.load_config_file`。

**成功输出**

- `coordinator.config` 是读到的文档（`dict(...)` 浅拷贝后的顶层副本）。
- 配置页用该文档建控件：测试参数、DUT、电源标签页、电源分配选择、设备绑定。
- 欢迎页选模式时：`apply_test_mode(dict(load_configuration()), driver_enabled)` 再回填页面，
  即每次进入工作区都按**磁盘最新配置**重写 `driver_mode.enabled`。

**失败提示**

- 读取抛异常时：`warn("配置加载", f"无法加载配置文件: {failure}")`；异常不外抛。
- `coordinator.config` 被置为 `{}`，绝不保留上一份配置继续运行。

**副作用**：无写入、无运行创建、无仪器连接。

**不变量**

- 读取失败不得留下旧配置冒充新配置。
- 页面不直接打开配置文件。

### 4.2 编辑参数

**现状位置**：`ConfigPage._build_ui`（控件）、`ConfigFormState.build_config`（组装）、
`ConfigFormState.read_test_parameters` / `read_power_supply_config` / `read_power_assignment`
（分段读数）、`ConfigFormState.validation_errors`（页面自校验）、
`application.configuration_authoring.ConfigurationAuthoringService`（正式段与正式校验）。

**输入与输出**

| 字段 | 控件读数规则 | 组装结果 |
| --- | --- | --- |
| 测试频率 | 文本必须是**非空、元素全为有限数字**的列表字面量（`ast.literal_eval`，不执行任意代码） | 合法：`test_frequencies: list[float]`；非法：不写入该键，并报“测试频率必须是非空数字列表” |
| 信号源 | 起始/结束功率、步进的数值框 | `signal_source: {start_power, stop_power, step}` |
| 压缩点 / 衰减器 | 下拉框可见文本 | `compression_point.type`、`attenuator.type`；正式段把 `"30dB"` 解析为 `attenuator.value=30.0` |
| DUT | 最大输入功率、PA 单元数量 | `dut_config.max_input_power`、`dut_config.power_supply_count` |
| 电源通道 | 通道角色 + 电压/电流值 + 保护值/开关 | `instruments.power_supplies.<supply_id>.channels.<CHx>`；配置里控件未覆盖的通道原样保留 |
| 电源分配 | 下拉框只读 `itemData`（`supply_id`），不从显示文本反解析 | `power_supply_assignment`：引用写 `supply_id`，过渡期同写同名 `name`；`channel` 固定 `["CH1","CH2"]` |

**失败提示**（`ConfigPage.validate` 汇总后用 `；` 连接，经 `validation_failed` 转日志
“配置校验失败: …”）

- `测试频率必须是非空数字列表`
- `<电源键> 存在未选择供电角色的通道`
- `<电源键> 的通道供电角色重复: <角色列表>`
- `<驱动功放/DUT>(<槽位>) 未选择电源：请先在“仪表配置”页应用电源设备`
- `<驱动功放/DUT>(<槽位>) → <supply_id> 引用的电源没有已应用的设备，不能保存或运行`
- `无法按当前配置生成正式运行映射: <原因>`（配置作者给出、用户可修正的失败）
- 正式 `test_plan` / `run_mapping` 的校验消息，以及 `validate_hardware_connections` 的
  地址重复 / 同一物理通道冲突消息
- `设备绑定不可用：<原因>`（读入时已判为不可用的电源绑定，见 4.3）

**副作用**：无。`build_config` 不修改页面配置（返回深拷贝/新对象），也不写盘。

**不变量**

- 组装以协调器持有的配置为基线（`build_config(base)`），页面只是视图。
- 组装保留未覆盖的未知字段；不写回已退役的 `wiring` 块。
- 非法输入不猜测、不静默修正：要么保持空/缺失，要么报结构化文案。
- `is_dirty()` = 当前组装结果 ≠ 上次基线；保存成功后基线更新。

### 4.3 应用设备

**现状位置**：`ConnectionPage.request_next` → `ConfigPage.apply_discovered_devices` →
`config_form_bindings`（绑定规范化）与 `config_projection.apply_power_choice`（分配选项）。

**输入**

- 发现面板交付的勾选结果列表；角色来自设备表登记（`power_supply` 等），不由用户选择。
- 每条记录的 `role`、`address`、`vendor`、`full_code`、`device_key`、`supply_id` /
  `label`、`ip`、`port`、`known`、`simulated`、`model`。

**成功输出**

- `device_bindings` **整批替换**为本次勾选结果：信号源/频谱仪按角色键，电源按
  `device_bindings.power_supplies[<supply_id>]`。
- 绑定记录写入：`vendor`、`model`、`full_code`、`device_key`（统一为
  `厂商:完整设备码` 的小写形式）、`visa_address`（去空白）、`last_ip`、`last_port`、
  `known`、`source`（`simulated` 或 `scan`）；非电源另有 `label`。
- 电源标签页按配置条目 + 本次绑定重建；电源分配下拉框只列本次绑定的电源。
- 面板状态行与 `discovery_message` 收到成功摘要：
  `已应用发现设备: …`；有移除时追加 `；已移除本次未勾选的旧绑定: …`；含模拟数据时追加
  `（模拟数据，仅用于离线演示，不能用于真实测量）`。
- 读入时记录的 `binding_problems` 清空。

**失败提示**（整批拒绝，返回 `False`，不产生半份绑定；同时写面板状态行和 `validation_failed`）

| 条件 | 提示 |
| --- | --- |
| 空选择 | `请先在发现结果中勾选本次测试所需设备` |
| 未知角色 | `未知的测试角色: <role>` |
| 电源缺少引用 ID | `电源 <model/ip> 还没有缩写设备码（label/supply_id）…` |
| 引用 ID 不可用（空白/含 `/`） | `电源缩写设备码 '<id>' 不能作为配置引用（<原因>）…` |
| 两行指向同一电源 | `本次应用有两行发现结果都指向电源 <supply_id>（<ip1> 与 <ip2>）…` |
| 唯一角色重复 | `角色 <role> 在本次应用中被重复指定（<ip1> 与 <ip2>）…` |
| 地址为空 | `<role> 的发现地址为空，未应用` |
| 缺少完整设备码 | `<role> 缺少设备身份（完整设备码），未应用` |
| 身份无法解析 | `<role> 的设备身份无法解析: <原因>` |
| 身份与完整设备码矛盾 | `<role> 的设备身份与完整设备码不一致（<a> ≠ <b>），未应用` |
| 电源没有可用身份 | `电源 <supply_id> 缺少可用于绑定的设备身份…，未应用` |
| 同一台设备绑定两次 | `电源 <a> 与 <b> 是同一台设备（<key>），同一台设备不能重复绑定…` |

**副作用**：无文件写入、无仪器连接、无运行创建。变更只存在于页面状态，随下一次保存落盘。

**不变量**

- “本次勾选结果替换旧绑定”是业务规则，不依赖面板是否重新扫描。
- 未勾选的旧角色/旧电源被移除，其配置条目地址清空并 `enabled: false`；已保存的通道参数
  保留。
- 被移除电源的分配引用保持**空选择**，绝不改指另一台已绑定电源。
- 旧槽位（`PS1`..`PS4`）不是可用引用。

### 4.4 切换驱动模式

**现状位置**：`WelcomePage` → `MainWindow._enter_test_mode` → `welcome_page.apply_test_mode`
与 `ConfigPage.set_test_mode`；读数在 `ConfigFormState._read_driver_mode`；
供电方式推断在 `config_projection.driver_power_source_label`。

**输入**

- 布尔 `driver_enabled`（欢迎页两个模式按钮）。
- 配置里既有的 `driver_mode.power_source` 与 `power_supply_assignment.driver_amplifier.power_supply_count`。

**成功输出**

- 配置副本的 `driver_mode.enabled` 被改写；其余键（如 `power_source`）保留；非对象
  `driver_mode` 视为空后重建。
- `apply_test_mode` 是**原地改写**：它直接修改传入字典的 `driver_mode` 并返回同一个对象。
  调用方若还要用原文档（例如配置页回填的另一份基线），必须先自行复制
  （`MainWindow._enter_test_mode` 传入 `dict(load_configuration())` 得到的顶层副本）。
- 配置页：
  - 电源分配分组仅在驱放模式下可见；
  - 驱动功放槽位仅在“驱放模式 + 直流电源”时可用，否则清空选择并显示提示；
  - 供电方式文本按 `power_source` 优先、缺失时按驱动分配条数推断（有本机分配 →
    “直流电源”，否则“自带供电”）；
  - 页面基线重置（切换模式本身不算“已修改”）；
  - 发出 `driver_mode_changed`。

**组装结果**

- 关闭驱放：`driver_mode = {"enabled": False}`（不带 `power_source`）；驱动分配不被提交。
- 打开驱放：`driver_mode = {"enabled": True, "power_source": "dc_supply" | "external_ac"}`；
  `external_ac` 时驱动分配条数为 0 且不占本机电源。

**失败提示**：无。模式选择本身没有失败路径。

**副作用**：无文件写入；不连接仪器。

**不变量**

- 供电方式推断只有一处实现，初次建页、回填、切换模式三处共用。
- 关闭驱放不会让配置页提交驱动功放分配（避免正式校验以“驱放关闭却配置驱动通道”拒绝）。

### 4.5 保存配置

**现状位置**：`ConfigPage.request_save` → `save_requested` →
`MainWindow.save_config` → `ApplicationCoordinator.update_configuration_from_ui` /
`save_configuration` → `application.configuration_authoring` →
`ConfigurationPort.save`。

**输入**：当前控件读数；组装基线是协调器持有的配置。

**成功输出**

- 协调器 `config` = 当前控件组装结果，再被正式配置作者改写为带
  `schema_version` + `test_plan` + `run_mapping` 的正式文档。
- 同一份正式文档推回页面，页面 `config` 与协调器一致。
- 配置写入唯一配置路径：`ConfigurationPort.save` →
  `JsonConfigurationAdapter` → `JsonConfigurationRepository.save_document`
  （`indent=4`、UTF-8、非 ASCII 原样；临时文件 + fsync + 原子替换）。
- 页面基线更新为干净；日志“配置已保存”；对话框“保存成功 / 配置文件已保存”。
- 若已有 `prepared_run`：额外日志提醒“当前运行的配置已冻结，如需应用请重新创建运行”。

**失败提示**

- 页面校验不通过：不发出保存请求，日志“配置校验失败: <原因>”。
- 写入失败：`save_configuration()` 返回 `False` 并保留 `last_save_error`；
  日志“配置保存失败: <原因>”，对话框“保存失败 / 配置保存失败: <原因>”。页面不标干净。

**副作用**：写配置文件一次。不创建/切换运行，不改冻结快照，不连接仪器。

**不变量**

- 正式配置文档只由 `application.configuration_authoring` 的配置编写服务生成，页面不手写
  `test_plan` / `run_mapping`；正式运行校验也由该服务的 `validate_document` 编排，页面
  只展示消息。
- 界面不接触文件、序列化格式或临时文件。
- 保存失败不得把页面标为干净。

### 4.6 创建运行

**现状位置**：`ConfigPage.request_create_run` → `create_run_requested` →
`ApplicationCoordinator.create_prepared_run` → `app.gui_runtime.prepare_configuration`。

**输入**：当前控件读数（经 `validate()` 与 `build_config()`）；运行目录服务与配置文件路径。

**成功输出**

- 先更新并保存配置（与 4.5 同一条写入路径）。
- `prepare_configuration` 在 `runs/<run_id>/` 下冻结快照（`config.json`、manifest、
  `inputs/hardware_config.json`）。
- 释放上一次连接的仪器端口；`prepared_run` 切换；页面状态文本
  `当前运行: <run_id>`；日志“已创建运行 <run_id>，运行目录: …”。

**失败提示**

| 失败点 | 提示 |
| --- | --- |
| 页面校验不通过 | `validation_failed`（同 4.2 文案），不进入后续步骤 |
| 配置保存失败 | 日志“配置保存失败: <原因>”；对话框“创建运行失败 / 配置保存失败: <原因>” |
| 冻结/创建失败 | 日志“创建运行失败: <原因>”；对话框“创建运行失败 / <原因>” |
| 旧端口未能安全释放 | 日志说明运行已冻结但未生效；对话框“创建运行未生效 / 上一次连接的仪器未能完成安全清理…” |

**副作用**：写配置文件 + 创建运行目录（新文件）；释放旧仪器端口（可能是硬件动作）；
当前运行只在全部成功后切换。

**不变量**

- 创建运行只做参数校验；现场接线由各测量页开始前的连接图对话框确认。
- 失败按阶段提交：任何一步失败都**不提交新的 `prepared_run`、运行状态文本与旧端口所有权**；
  但失败点之前已经发生的副作用照实保留——页面校验失败不写盘，配置保存失败不冻结快照，
  冻结失败时全局配置文件已写入，旧端口释放失败时新运行目录已经存在。
- 未创建运行时，连接仪器与测量都必须明确失败（`RunNotResumable`）。

### 4.7 加载运行

**现状位置**：`ConfigPage.request_load_run` → `load_run_requested(run_id)` →
`ApplicationCoordinator.load_prepared_run` → `load_prepared_run(run_id, …)` →
`apply_run_configuration` → `ConfigPage.apply_config`。

**输入**：文本 `run_id`（去首尾空白）；配置路径与运行目录服务。

**成功输出**

- 运行目录快照通过完整性校验后，`hardware_config` 回填到配置页控件。
- 页面绑定、电源标签页、分配选项、派生界面状态按新文档重建；`dirty` 基线重置。
- 协调器 `config` 替换为该快照；释放旧端口；`prepared_run` 切换；状态文本
  `当前运行: <run_id>`；日志“已加载运行 <run_id>，运行目录: …”。

**失败提示**

| 失败点 | 提示 |
| --- | --- |
| `run_id` 为空 | `请输入要加载的 run_id`（`validation_failed`，不发信号） |
| 运行不存在/快照缺失/篡改/已终止 | 日志“加载运行失败: <原因>”；对话框“加载运行失败 / <原因>” |
| 配置页回填失败（非对象文档、投影异常） | 日志“…配置页回填失败；当前运行保持不变”；对话框“加载运行失败 / 配置页回填失败，运行未切换…” |
| 旧端口未能安全释放 | 日志“…上一次连接的仪器未能安全释放；当前运行保持不变”；对话框“加载运行未生效 / …” |

**副作用**：只读运行目录；释放旧仪器端口；不写配置文件。

**不变量**

- 两阶段提交：回填成功前不切换运行、不释放旧端口、不更新状态。
- 回填失败不得报告为加载成功；但回填之后旧端口释放失败时，配置页已经是新快照内容，
  只有 `prepared_run` 与状态文本保持原样——这条“页面已回填、运行未提交”的中间态必须
  由提示文案明确告知，不能当成整体回滚。
- 运行期间的测量输入仍来自运行目录内的冻结快照，不读全局可变配置。

### 4.8 冻结配置回填（`apply_config`，4.7 的内部步骤）

**输入**：一份配置编写文档（必须是 `dict`）。

**成功输出**

- 先把全部受控控件重置到空配置基线，再逐字段投影；结果与“用同一份文档直接构造页面”
  完全一致。
- 缺失或类型不正确的字段落到明确默认值（不用字符串/布尔强制转换）。
- 非法频率列表、非法布尔、非法数字都回落默认值。
- 电源分配：文档里有该条分配且引用仍绑定时选中它；声明了但引用为空/失效时保持空选择；
  文档里没有该条分配时选第一台可用电源；没有可用电源时保持空选择。
- 成功后更新页面 `config`、记录的坏绑定问题、派生界面状态与 `dirty` 基线。

**失败提示**

- 非 `dict` 输入抛 `ConfigBackfillError("冻结配置必须是 JSON 对象（dict）…")`。
- 投影中途失败：恢复原绑定、原问题清单、原供电方式并重建标签页，再抛出；页面不留在
  半新半旧状态。

**副作用**：无文件写入、无硬件动作。

**不变量**

- 显示文本与业务值分离：电源引用只从 `itemData` 读取。
- 回填不把配置引用的电源临时塞进下拉框，不按位置恢复选择。

## 5. 跨动作不变量（后续步骤必须保持）

1. 配置页向外只暴露窄接口：`validate`、`build_config(base)`、`apply_config`、
   `set_run_status`、`driver_mode_requested`（`ConfigurationPagePort`）。
2. 协调器不读控件；页面不打开文件、不连接仪器、不持运行契约。
3. 正式配置文档只有一个生产者（`application.configuration_authoring`，步骤 4 已迁移；
   旧模块只剩转发壳）；页面与投影不解释 `test_plan` / `run_mapping`。
4. 设备绑定是仪器连接的唯一来源；电源引用只认 `supply_id`（过渡期同写 `name`）。
5. 用户可修正的问题走结构化文案 / 返回值；文件、硬件、程序错误走异常。
6. 任何失败都不产生“静默的半份”状态：整批拒绝绑定、投影失败整体回滚；运行切换的
   中间态（例如页面已回填、`prepared_run` 未提交）必须由提示文案明确说明，不能让人
   以为已经整体成功或整体回滚。
7. 读取失败不留旧配置；保存失败不标干净；创建/加载失败不提交新的 `prepared_run`、
   运行状态或旧端口所有权（失败点之前已完成的写入/冻结按 4.6、4.7 的分阶段记录保留）。
